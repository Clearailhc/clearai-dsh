# 循环哲学：让机制守住事实边界

这份文档回答一个问题：**ClearAI 为什么长成这样**。它描述当前 DSH 原生实现背后的取舍与理由。每条哲学都应在本仓库的机制或测试中找到落点；找不到落点的，只是偏好，不是系统保证。

---

## 0. 总纲

> **让模型负责智能判断，让系统负责事实边界。**

这句话不是分工口号，是**接口定义**。它规定了什么可以被交给概率，什么必须被交给确定性：

- **可以交给模型的**：理解材料、提出假设、选择路线、判断哪条证据更可信、决定下一步做什么。
- **不可以交给模型的**：什么算完成、状态是什么、一个事实能不能被写进知识库、一次写入能不能撤回、谁的裁决有效。

第二类问题共同的特征是：**它们都有正确答案，而正确答案不依赖于谁来回答**。凡是具备这个特征的东西，系统都自己算——因为让模型去“说”一个本可以被算出来的事实，就是把确定性降级成概率。

一个结论可信，当且仅当它经受住了一个本可以让它失败的检验。系统的职责不是提供检验，而是**保证这个循环的形状**：每个结论之前都有一个能失败的检验，检验先登记后执行，结果被如实记账。

## 1. 五条落进机制的哲学

### P1 · 机制优于劝告

**行为约束优先落机制，不堆 prompt。**

提示词是概率性的：写十遍“不要执行危险命令”，它依然会在某次长上下文的第 40 步被绕过。而机制是确定性的。所以这套系统里，一条重要的约束几乎总能找到一个**代码里的落点**：

| 约束 | 落点 |
|---|---|
| 危险命令不可执行 | DSH 工具治理在执行前拒绝不允许的命令；ClearAI 的策略贡献参与其中 |
| 写入不可并发交错 | 工作区写入由运行时治理与账本保持边界 |
| 工具不可越出工作区 | DSH 工作区边界与沙箱规则负责路径约束 |
| 一条结论不能自证 | 内核按等级分离执行者与评估者（`SELF_JUDGE_MAX_INDEX`） |
| 步骤不能自称完成 | `AdvancePlan` 是唯一完成动词，且必须交付证据 |

**判据**：如果一个行为约束只存在于提示词里而没有任何机制承载，那它迟早会失效。这时要么补机制，要么承认它只是一个偏好。[灵魂映射](soul-map.zh-CN.md)按这条判据逐条标注哪些是机制、哪些仍是偏好。

### P2 · 不可表示优于不可违反

比“加了防御所以不会出错”更强的，是“这种错根本无法表达”。

两个实例：

- 计划步骤的秩（`open/blocked=0 < advanced/void=1`）让**降级不可表示**——不存在“驳回重做”这条路，与其补一条防御边，不如不给这条路。
- 折法在应用变更时把 done / void / verified / adopted 压回，使“事实倒退”在写入侧**不可表示**。

### P3 · 事实与判断分离：意图工具不能断言事实

模型可以**请求**，不能**宣称**。

- 计划步骤的 `status` 与 `loops` **不接受调用方声明**——模型不能把一步标成 done，只能交付证据让系统去推进。
- 目标的阶段（drafting/planning/executing/auditing/stalled…）与完成度**全部派生**，不存第二本账；`goal_id` 与 `phase_id` 只写在 plan 侧。
- 假设的状态由证据**算**出来，不打分：通过到第几级、有几条推翻、有几次无法判定。

这条哲学的直接收益是：**系统的状态永远可以被重新计算**，因此永远不会与事实不一致。凡是被存储的状态，都是潜在的谎言。

### P4 · 做的人不判自己

- 判定标准**在结果出现之前**写下。`done_criteria` 在入口强制，并做自指检测（判据不能引用它自己）。
- L0–L2 允许做的人自判，但**依据必须可复查**；L3 以上直接拒绝自判（`verdict_not_accepted`）。
- 独立评估者以 fresh context 只读产物，产出结构化评估卡；卡由系统落盘，**不经被评估者之手**。

### P5 · 什么都不删

被推翻的假设、被拒绝的观测、被撤回的事实、落选的世界线——全部保留并可查。

- 账本历史**只前进**：restore 是一次新 commit，不是回滚。
- 世界线落选只标 `pruned` 留痕；**只删工作副本，保留 branch ref**——因为事后改判依赖它永久可读。
- 目标修订留版本与原因（`SetGoal` 必带 reason，旧段标 superseded 不删），结案后目标文档**不清空**。

一条被推翻的假设是有价值的资产：它记录了一次“此路不通”，而这正是探索的真实产出。

## 2. 七阶段与运行时四拍

认识论循环对外展开为**七个阶段**：界定 → 提出假设 → 规划 → 观测 → 验证 → 评估 → 记录并行动（见[认识论循环](epistemic-loop.zh-CN.md)）。

运行时，这七个阶段压缩成**四拍**：计划 → 执行 → 观察 → 反思。四拍不是另一套本体，而是模型与系统协作时的执行节奏。**一个循环推进，不做多 Agent 编排**；子角色（Scout / Executor / Evaluator）由 Harness 按触发派生，不是自由委派。

| 拍 | 对应阶段 | 模型做什么 | 系统保证什么 |
|---|---|---|---|
| **计划** | 界定 + 提出假设 + 规划 | 拆步骤、写判据 | 细粒度 + 可执行 + 可证据验收；`done_criteria` 强制；≤25 步；声明产物 |
| **执行** | 观测 | 探索、写脚本、计算 | 只读并行 / 写入串行；沙箱；每次写入自动进账本 |
| **观察** | 验证 | 拿到结果 | **观测准入只看收不收，不做裁决** |
| **反思** | 评估 + 记录并行动 | 交付、收敛、修正 | `AdvancePlan` 唯一完成动词；评估按等级分离；结论带边界落盘 |

**“观测准入不做裁决”是这套设计里我最有信心的一处**：准入只检查三件事——声明的产物**存在**、**非空**、**结构合法**。它回答的是“这份观测收不收”，而不是“这份观测说明了什么”。因为不裁决，所以不存在“准入污染结论”的问题；裁决被完整地留给下一步的评估者。

四拍之间有一个**唯一动词**原则：`AdvancePlan` 是唯一的完成动词，其余三个（`AmendPlan` 补一步、`RefinePlan` 改判据不动进度、`VoidPlanStep` 带因作废）都不改变进度。**只有一个动词能推进循环**，这让“谁推进了这一步”永远可回答。

## 3. 事实边界的三道防线

系统的安全不依赖任何单一机制，而是三段接力：

```
事前：工具治理的确定性闸门  →  事中：沙箱 + 账本  →  事后：账本可恢复 + turn 变更条
```

一个刻意反直觉的取舍：**默认免审批直执**，理由是“事后可回滚取代事前审批”——如果每次写入都能精确恢复，那么拦住每一次写入的收益就小于它带来的摩擦。安全垫因此变成三件事：事前拦**真危险**（而不是拦一切）、账本保证**可恢复**、turn 变更条保证**可见**。

这个取舍成立的前提是账本足够可靠。所以账本的要求写得比别处更硬：身份固定、HEAD 固定、排除规则显式、单笔失败不阻塞主流程但绝不静默吞掉。

## 4. 失败的处理哲学

### 判据只有一条：这份数据是谁写的

边界归一不是“吞掉故障”，而是**让每一层消化自己层位的错**：

- **provider / 模型参数 / 外部回包** → 在入场边界**静默归一 + 留下计数**。不回显给模型（回显只会在上下文里播下行为漂移），不 panic（那会把一次外部抖动升格成整个 run 的死亡）。
- **我们自己序列化的状态、审批记录、计划数据、快照** → 坏了就是账本坏了，**绝不静默**。

推论：**不可信输入不许升格为 run 死亡。**

### 三条路严格分开

| 层 | 表现 | 走向 |
|---|---|---|
| 普通工具错误 | 同回合 `ok=false` + `failure_class` | 可继续，模型自纠 |
| 供应商失败 | 归一化为**类型化事实** | 有界退避；终不可用则 run `paused`，一句「继续」原地续跑 |
| 引擎级未分类异常 | 升格为引擎故障，**标记效果可能已提交** | 降权**只读**恢复回合 |

### 效果不确定时，先观察

有副作用的工具是 **at-most-once**；越过派发边界后结局未知一律按“效果未知”处理。语义只有一条：**先观察当前事实，再谈重试**。重试的安全前提是“知道上次到底做没做”，而这个前提在效果未知时恰恰不成立。

## 5. 上下文是受控资源，不是缓存

三条纪律，每一条都有代码落点：

1. **prefix 稳定是硬约束，不是优化。** 工具投影序冻结；环境段**刻意不含时间**（时间每次调用都不同，会让后面的提示词与整段历史失去前缀缓存）；同一工具结果的渲染只有**一处定义**，让实时、重放、历史重建三条路径产出**同一串字节**。
2. **凡是发给过模型的字节，都要在 transcript 里有据。** 事件的“记录态”与“观察态”严格分流：关于**通道**的事实只广播、永不落 transcript，因为它们是关于通道的事实，不是关于**工作**的事实。
3. **注入必须有界且有硬上限。** 运行态卡每回合重建；压缩阈值可配；观测内容分页。

第 2 条有一个漂亮的推论：SSE 断线重连后**不欠账**。因为不落账的东西本来就不参与恢复游标，重连补拉的一定是完整的事实序列。

## 6. 引擎与内容解耦

**ClearAI 不改 DSH 引擎。** 三条支撑：

- 认识论层以**贡献**的形式加在 DSH 的组合面上：一个宿主包、一个 agent 预设、一个客户端模块。
- 行为经**冻结的预设与内核契约**进入运行时；声明与实现不一致时装配期就失败，不把坏数据静默解释成另一套权限。
- 本体声明（`preset/plugins/ontology.js`）在**装配期**校验形状，并由测试与折法交叉核对。

**新行为 = 注册一个贡献（Tool / 策略 / 提示词模块）+ 声明一行，永不加引擎分支。**

为什么值得为这条纪律付出复杂度？三个具体回报：

1. **可裁剪**：不同发行 = 不同清单（少装/换装插件），不是代码分支。
2. **可验证**：装配期就能跑完全部不变量，而不是等到运行时某个分支才暴露。
3. **可替换**：换掉全部提示词与角色配置，引擎代码零改动。

## 7. 这套哲学的内部张力

哲学文档如果只写优点，就是宣传。以下是这套设计**真实存在**的张力：

1. **机制完备 ≠ 实现完备。** 最典型的是验证闭环：文档描述了「验证」8 状态机与「L4 必须有人放行」，而后者并非覆盖每一次评估的通用闸门（详见 [验证本体](verification-loop.zh-CN.md) 文首的实现状态）。设计的完备性容易让人误以为运行的完备性。
2. **证据门靠判据而非等级，所以「判据缺失」会改变门的形状（2026-09 已部分收紧）。** 独立评估者的派遣由 `needs_audit`（产物齐备**且** `done_criteria` 非空）触发——判据是这条门的**结构前提**。曾经的写法是「一个 L3 以上的步骤若没有 `done_criteria`，会走确定性放行出口而完全不经过独立评估」；**当前正常入口已经堵上**：`CreatePlan` 会调 `validateSteps`，每一步的 `done_criteria` 必须是字符串且去空白后长度 ≥ 4，否则整次调用被拒（`preset/plugins/clearai-kernel.js:2405-2426`，调用点 `:2745`）。所以这条软肋现在只在**旧日志、内部构造的计划对象、以及将来新增的其他入口**上成立——它是"入口一致性"的问题，不再是"用户可以不写判据"的问题。哲学层面的残余风险是：它仍然假设**每一条进入系统的路径**都校验了判据，而这份假设靠测试而不是靠类型系统维持。
3. **文档与实现之间没有机械等价检查。** 这套仓库里出现过多次「机制改了、文档/注释/prompt 没跟上」（例如计划授权的自动确认分支已删、续跑额度已从 6/512 改成 128、`set_autonomy` 已摘除，而注释与提示词仍在讲旧语义）。修法是把它变成可执行检查：[机制真值表](optimization/truth-table.zh-CN.md)（`node tools/verify-truth-table.mjs`）、状态机文档（`node test/state-machine.test.mjs`）与文档禁用词扫描。**在那些检查覆盖不到的地方，漂移仍然可能。**
3. **复杂度与测试密度不匹配。** 机制越完备，越需要测试来证明机制真的在生效——否则“落进机制的约束”和“以为落进机制的约束”在代码里长得一模一样。当前测试覆盖见 `test/`，已知未覆盖项记在[已知缺口](known-gaps.zh-CN.md)。
4. **不可表示是要花成本的。** 每一条“做成不可表示”都意味着把复杂度从运行时前移到装配期/类型层。这个成本在小型系统里可能不划算——这套设计愿意付，是因为它把正确性押在了“确定性”上。

---

## 8. 一句话收束

**把不确定性留给模型，把确定性收进机制；凡是能被算出来的，就不要被说出来；凡是能被恢复的，就不必事先拦住。**

这就是这个循环的全部意图。
