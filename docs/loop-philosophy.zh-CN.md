# 循环哲学：让机制守住事实边界

> **改造中。** 本文按[「少即是多」方案](less-is-more-plan.zh-CN.md)描述目标设计。

这份文档回答：**ClearAI 为什么长成这样**。每条哲学都应在机制或测试里找到落点；找不到的，只是偏好。

---

## 0. 总纲

> **让模型负责智能判断，让系统负责事实边界。**

这句话是接口定义：

- **交给模型的**：理解材料、提出判断、选择路线、判断哪条证据更可信、决定下一步。
- **不交给模型的**：什么算完成、现在是什么状态、一个事实能不能写进知识、谁的裁决有效。

第二类问题都有正确答案，而且答案不依赖于谁来回答。凡是这样的东西，系统自己算——让模型去「说」一个本可以算出来的事实，就是把确定性降级成概率。

**起源。** 用 AI 做研究，最大的风险不是答不出来，而是答得太顺：已知、推测和编造用同一种口气说出来，人分不清哪句能信，下一次又从零开始。认识论回答「这句话凭什么能信」；本体论回答「这些结论加起来是什么」。

**脚手架原则。** 模型会越来越强。ClearAI 只提供它自己做不到、也不该自己做的那部分；其余交给模型，或交给宿主。所以这一版的主要动作是减法：宿主已经有的，不再做第二份；提示词只留骨架。

## 1. 六条落进机制的哲学

### P1 · 机制优于劝告

提示词是概率性的；写十遍「不要自己宣布完成」，长上下文的第 40 步依然会绕过。机制是确定性的。

| 约束 | 落点 |
|---|---|
| 目标不能自己宣布完成 | 守卫拒绝模型直接完成原生 goal；只有 `Conclude` 在独立评估通过后能完成它 |
| 步骤不能自称完成 | `AdvancePlan` 是唯一完成动作，且必须交付产物 |
| 结论不能自证 | L3 以上分离做的人与判的人 |
| 人的决定不能被转述 | 内核直接问人，答案不经模型 |
| 危险命令、越出工作区 | 宿主的工具治理、沙箱与权限预设 |

**判据**：一条约束只活在提示词里，迟早失效。要么补机制，要么承认它只是偏好。

### P2 · 不可表示优于不可违反

比「加了防御所以不会错」更强的是「这种错根本写不出来」：步骤的秩让降级不可表示；工具没有可写的状态字段；L3 以上的路径根本不收调用方的裁决。

### P3 · 事实与判断分离

模型可以**请求**，不能**宣称**。步骤状态、判断状态、进度都从日志折出来，不存第二份。**凡是被存储的状态，都是潜在的谎言**；能重算的状态永远不会与事实不一致。

### P4 · 做的人不判自己

判据在结果出现之前写下；L0–L2 允许自判但依据要能复查；L3 以上派独立评估者，全新上下文、只读产物，评估卡由系统落盘，不经被评估者之手。目标的完成同样要过独立评估。

### P5 · 什么都不删

被推翻的判断、被拒的产物、被撤回的事实都留着。一条被推翻的判断是资产：它记录了一次「此路不通」，这正是探索的真实产出。

### P6 · 本体生长是循环的原生行为

一个机制如果不在任务的完成函数里，它就只是「随时可以被调用」。所以知识任务的判据做成**结构的**：目标开着、登记了判断，系统就进入知识模式——运行态卡给出相关已知与缺口（只给模型，三种），结案前有一道门（断言提到的实体必须落图）。普通问答从不进入，零成本。

真跑给过一个反直觉的结论：改变行为的主要是**缺口看得见**，不是门。看得见负责「让它想做」，门负责「不让它绕过」。

## 2. 一条循环

> 问题 → 判断（写明怎样算错）→ 一次可能失败的检验 → 证据 → 带范围的结论 → 长进本体

这一版所有取舍只用这一把尺子：能直接服务这条循环的留下，不能的删掉或交给宿主。它取代了过去的「七阶段」与「运行时四拍」——两套说法讲的是同一件事，留一套。

**准入不做裁决**是这套设计里最有把握的一处：准入只看产物存在、非空、结构合法。它回答「收不收」，不回答「说明了什么」，所以不存在准入污染结论；裁决完整留给评估者。

**唯一完成动作**：`AdvancePlan` 是唯一能推进步骤的动作，`RevisePlan`（补步、改判据、作废）都不改进度。只有一个动作能推进，「谁推进了这一步」永远答得出来。

## 3. 安全交给宿主

过去这里写的是「事后可回滚代替事前审批」，靠的是我们自己的 git 账本。这一版把文件历史交还宿主：宿主能显示每轮改了什么，但**不能恢复**。所以安全的前提跟着变——它由宿主的**权限预设与审批**在事前承担，不再由我们的账本在事后承担。这是一项明确接受的代价，写在[方案](less-is-more-plan.zh-CN.md)第六节。

## 4. 失败的处理

**判据只有一条：这份数据是谁写的。**

- 提供方、模型参数、外部回包坏了 → 在入场边界归一并计数，不回显给模型，也不让一次外部抖动升格成整个运行的死亡。
- 我们自己写的状态坏了 → 那就是账坏了，绝不静默。

| 层 | 表现 | 走向 |
|---|---|---|
| 普通工具错误 | 同回合返回错误 | 模型自纠 |
| 提供方失败 | 类型化事实 | 有界退避；终不可用则暂停，一句「继续」续跑 |
| 引擎级异常 | 标记效果可能已提交 | 先观察，再谈重试 |

有副作用的工具至多执行一次；越过派发边界后结局未知，一律先观察当前事实。

## 5. 上下文是受控资源

1. **前缀稳定是硬约束。** 工具顺序冻结；环境段不含时间；同一工具结果只有一处渲染定义。
2. **注入有界。** 运行态卡只在状态变化时注入一次；提示词三段、约三四千字；工具怎么用写在工具说明里，用到时才出现。
3. **发给过模型的字节，在日志里都有据。** 关于通道的事实只广播、不落日志。

## 6. 引擎与内容解耦

**ClearAI 不改 DSH 引擎。** 认识论层以贡献的形式加在 DSH 的组合面上：一个宿主包、一个预设、一个客户端模块。新行为 = 注册一个贡献 + 声明一行，永不加引擎分支。回报是可裁剪、可在装配期验证、可替换。这一版更进一步：**宿主已经提供的能力，连贡献都不做。**

## 7. 内部张力

哲学文档如果只写优点，就是宣传。以下是这套设计**真实存在**的张力：

1. **机制完备 ≠ 实现完备。** 文档写的是目标设计；哪一段落地了，以[已知缺口](known-gaps.zh-CN.md)为准。
2. **交给宿主，就承担宿主的边界。** 失去恢复；宿主的 goal、问答、交付卡片的行为变化会直接影响我们。原型验证证明了今天的接口可用，不保证明天不变；所以每一处依赖都要有测试钉住。
3. **文档与实现之间没有机械等价检查。** 真值表、状态机文档测试与禁用词扫描能覆盖一部分；覆盖不到的地方，漂移仍然可能。
4. **本体层是约定，事实层是经验。** 一个术语一旦被当成事实引用，反对那条结论看起来就像反对整个词汇。缓解它的是：词条带依据接纳、废止黏性、语义变化换 id、冲突只暴露不裁决。

## 8. 一句话收束

**把不确定性留给模型，把确定性收进机制，把宿主能做的交还宿主；凡是能被算出来的，就不要被说出来。**
