# 验证闭环：对象、等级、流转与术语

> **改造中。** 本文按[「少即是多」方案](less-is-more-plan.zh-CN.md)描述目标设计。代码分阶段跟进，哪些已经落地，以[已知缺口](known-gaps.zh-CN.md)为准。

一个判断怎样一步步变成可以放心引用的事实。本文定义系统里的对象、等级、流转与术语；其他文档、提示词与代码注释提到这些概念时，以这里为准。

## 1. 一句话原则

一个结论可信，当且仅当它经受住了一次本可以让它失败的检验，并写清在什么情况下不成立。

系统不提供检验本身——那是领域知识，来自做研究的人与模型。系统保证循环的形状：判据先写后做，做的人不判自己，结果如实记账。

## 2. 对象

| 对象 | 是什么 | 必带的东西 | 谁能改 |
|---|---|---|---|
| 目标 Goal | 要回答的问题 | 判据（怎样算回答了） | 文字与续跑归宿主的原生 goal；判据由 `Frame` 挂上，改判据要一份独立裁决 |
| 假设 Hypothesis | 一个要检验的判断（界面里叫「判断」） | 一句话主张；什么结果会推翻它 | 模型经 `Frame` 提出与修订；状态由系统算 |
| 验证 Verification | 检验某条假设的一个步骤 | 验哪条假设；等级；判据 | 模型登记；步骤状态由系统改 |
| 观测 Observation | 步骤交上来的产物与执行记录 | 内容；来源 | 只追加 |
| 评估 Evaluation | 拿登记的判据对照观测，得出裁决 | 用的哪份判据；看的哪些观测；谁在判 | 按等级：做的人自判，或独立评估者 |
| 证据 Evidence | 评估的结果 | 支持 / 推翻 / 说不清；等级；引用 | 写下就不改；重评产生新证据 |
| 事实 Fact | 证据够了之后升格的假设 | 范围；等级；证据；可选的断言 | 系统升格；人可以撤回 |

- **步骤**是执行单位。一个步骤最多检验一条假设；不检验假设的步骤是普通工作，不产生证据。
- **结论**是对目标的回答，由若干事实拼成，写在给人的汇报里；它引用事实，自己不跟踪状态。
- **假设属于项目**，已确立的事实跨会话留在工作区，下一轮按概念取用。

## 3. 等级

等级只决定两件事：**谁来判**，以及 **L4 要人放行**。它由三个性质决定：证据是已有的还是新产生的；能不能重跑得到同样结果；能不能由机器判。

| 等级 | 定义 | 谁来判 | 认可的观测 |
|---|---|---|---|
| L0 | 只靠推理的快速合理性检查 | 做的人，依据要能复查 | 推导、计算过程 |
| L1 | 已有知识：文献、数据库 | 做的人，依据要能复查 | 出处 |
| L2 | 已有数据或小规模计算 | 做的人，依据要能复查 | 数据、脚本与输出 |
| L3 | 新产生的、可重复的证据 | 独立评估者，或机器 | 做的人的产出，必须能重跑 |
| L4 | 新产生的、不可重复或来自外部的证据 | 独立评估者，先经人放行 | 做的人自己写的文件不算 |

机器评估者（证明检查器、测试、统计脚本）在任何等级都算独立评估者。各领域的五级具体是什么，写在项目技能里；引擎只认这五个抽象等级。

| 等级 | 数学 | 物理 | 生命科学 |
|---|---|---|---|
| L0 | 小情形代入、数量级、边界情况 | 量纲、极限情形、守恒律 | 剂量范围、通路是否说得通 |
| L1 | 文献里是否已证或已有反例 | 文献、手册数据 | 文献、公共数据库 |
| L2 | 数值验算、符号计算 | 已有实验数据重分析 | 已有组学数据重分析 |
| L3 | 系统搜索反例、形式证明经机器检查 | 数值仿真 | 计算模拟、公开数据的新分析 |
| L4 | 同行评审 | 实验、装置机时 | 湿实验、临床 |

## 4. 流转：从问题到事实

```
人        模型                       系统                        独立评估者
 │ 问题 ─▶ │ 原生 goal + Frame：判据、假设（各带推翻条件）
 │         │ CreatePlan：步骤 = 做什么 + 产物 + 判据 [+ 检验哪条假设、等级]
 │  ┌ 每步 ┤ 做事
 │  │      │ AdvancePlan ──────────▶ │ 准入：存在、非空、结构合法
 │◀─┼──────┼── L4：当场问人放行 ─────┤
 │  │      │                         │ L0–L2：记自判证据
 │  │      │                         │ L3+：派评估者 ─────────▶ │ 只读产物与记录
 │  │      │                         │ ◀────────── 评估卡 ──────┤
 │  │      │ ◀── 收下 / 拦下（缺什么）┤ 记证据，算假设状态
 │◀─┴──────┼── 连续被拦：当场问人 ───┤
 │         │ Conclude ─────────────▶ │ 派评估者核对目标判据 ──▶ │
 │         │                         │ ◀────────── 评估卡 ──────┤
 │         │                         │ 通过：完成原生 goal，升格事实，结案时声明交付物
 │◀────────┼── 推翻证据碰到已升格的事实：当场问人撤回或维持
```

人只在三处出现：给出问题；需要人的门（L4 放行、连续被拦、事实遇到反例）由那次调用直接问；以及人随时可以用 `/goal` 或原生界面暂停、结束目标——人结束目标不算任何判断已确立。

## 5. 状态

所有状态由系统从会话日志折出，模型没有可写的状态字段。

**目标**：阶段归原生 goal（进行中 / 暂停 / 阻塞 / 完成）。ClearAI 只补一条派生：判据还没写，或结案评估正在进行。

**假设**：

| 状态 | 怎么进 | 怎么出 |
|---|---|---|
| proposed（提出） | 写清主张与推翻条件 | 有了第一条证据 → alive |
| alive（检验中） | 从 proposed 进入 | 达到升格门槛 → confirmed；出现推翻证据 → refuted；被改写 → superseded |
| confirmed（已确立，成为事实） | 结案时达到门槛且无推翻 | 人决定撤回 → retracted |
| refuted（被推翻，留着） | 任一等级的推翻证据 | 终态 |
| superseded（被新版替代） | 修订假设时旧版进入 | 终态 |
| retracted（已撤回，留着） | 人复核后决定 | 终态 |

**步骤**：`open → advanced` 或 `open → void`（作废必带原因）。降级不可表示：没有「驳回重做」这条路。

**验证**——派生，不存储。这九个名字曾是一台「存储式状态机」的设计；它们都不存：要么是账上的事实，要么由 `derive()` 现算，要么刻意不可表示。

| 状态 | 含义 | 今天住在哪 |
|---|---|---|
| planned | 判据草稿 | 刻意不可表示：`CreatePlan` 拒绝没有判据的步骤，所以它根本不会被存下 |
| registered | 判据已登记 | 步骤自己——`tests: {hypothesis, level}` 加判据；`plan/created` 就是登记那一刻 |
| authorized | 人已放行（只有 L4） | 不是状态：一条放行事实（`human/released`），由 `AdvancePlan` 问人后落下 |
| submitted | 在执行 | 派生：步骤是 open；`inFlight` 标出正在进行的那次交付 |
| awaiting | 等结果 | 子任务自己的事实：`audit/dispatched` |
| observed | 拿到结果 | `observation/recorded`，交付时登记 |
| evaluated | 已评估，证据写好 | `audit/settled` + `evidence/recorded`；`derive()` 按假设现算支持 / 推翻 / 说不清 |
| expired | 到期没等到 | 不是状态：`audit/settled` 的裁决为 `unknown`，与准入被拦共用一个连拦计数（`block/counted`） |
| aborted | 没拿到结果就中止 | 是事实，不是状态：带原因的作废（`VoidPlanStep`，经 `RevisePlan` 触发），或子任务记下的结束原因 |

**事实**：新的推翻证据只**标记**它待复核，并当场问人；撤回与维持都落同一条复核记录。从外部拿回来的数据也可能有问题，所以不自动撤回。

## 6. 规则与落点

| 规则 | 落点 |
|---|---|
| 判据先写后做 | `CreatePlan` 拒绝判据缺失或过短的步骤；`RevisePlan` 改判据保留旧版本；改目标判据要一份独立裁决 |
| 并行路线的产出不互相覆盖 | 同一计划里两个步骤声明同一个产物路径，`CreatePlan` / `RevisePlan` 即拒 |
| 步骤不能自称完成 | `AdvancePlan` 是唯一完成动作；工具里没有可写的状态字段 |
| 准入只判收不收 | 产物存在、非空、结构合法；不判它说明了什么 |
| 做的人不判自己 | L3 以上拒绝调用方自带裁决，派独立评估者（只读、全新上下文、结构化输出） |
| L4 要人放行 | `AdvancePlan` 交付 L4 步骤时当场问人；做的人自己写的文件不算 L4 观测 |
| 连续被拦就停下等人 | 同一步连续被拦到阈值，`AdvancePlan` 当场问人；改判据或换做法后自然放行 |
| 目标完成要过独立评估 | 只有 `Conclude` 能完成原生 goal；模型直接调原生「完成目标」被守卫拒绝 |
| 什么都不删 | 被推翻的假设、被拒的产物、被撤回的事实都保留；会话日志只追加 |
| 人的决定不经模型转述 | 门由内核工具直接问人，答案在进程内交回内核 |
| 没人能答时不替人决定 | 门保持开着，原生 goal 置为阻塞并写明原因 |

## 7. 术语

全仓库统一用左列叫法。界面与汇报一律用人话（第三列），内部名不改。

| 统一叫法 | 代码标识 | 界面里的说法 | 弃用的旧叫法 |
|---|---|---|---|
| 目标 | 原生 goal；`Frame` / `Conclude` | 问题 | — |
| 假设 | `hypotheses[]` | 判断 | 猜想、命题（作对象名时） |
| 判据 | `done_criteria` | 怎样算完成 / 怎样算错 | 完成标准、验收判据 |
| 观测 | 产物文件 + 执行记录 | 交上来的东西 | 物证 |
| 准入 | `admission()` | 收下 / 拦下 | 证据门 |
| 评估者 | `agent_role=evaluator` | 独立复核 | 审计员、裁判 |
| 评估卡 | `clear/evidence/audits/` | 复核记录 | 审计卡 |
| 证据 | `evidence[]` | 凭什么 | — |
| 事实 | `fact/promoted` | 能信的结论 | 已确认结论 |
| 等级 | `L0`–`L4`（大写） | 检验强度 | — |
| 升格门槛 | `promote_at_level` | — | 验收门槛 |

## 8. 与领域本体的关系

本文是**过程**：认识的规则，随插件版本变，不可在运行时编辑。[领域本体](domain-ontology.zh-CN.md)是**语言**：项目的词汇与它长出来的图，随项目长，由具名动词治理。两者只在四处握手：登记假设时校验断言形态、升格时定型、重放时派生冲突、废止后新断言拒引。
