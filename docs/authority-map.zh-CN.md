# 权威归属

这份文档回答一个问题：**每一件事实由谁产生、存在哪、谁消费。**

> 同一件事实只有**一个权威来源**；同一类故障只在**一个地方**解释；没有证据时系统能**安静地说不知道**。

它来自一次自我诊断：连续几轮修缺陷之后，我们发现自己在按症状打补丁——根因是**同一件事被两处各自推断了一遍**：宿主已经在回答，我们又在内存表里推一遍。所以这一轮的主线是减法：宿主已经是权威的，一律交还宿主。

## 一、归属表

| 事实 | 权威 | ClearAI 怎么做 |
|---|---|---|
| 目标的文字、续跑轮数、暂停 / 阻塞 / 完成 | **宿主**：原生 goal | 消费。只经 `Conclude` 完成它，门开着时置为阻塞 |
| 计划审阅（人批不批这份计划） | **宿主**：plan mode | 不另做审阅卡 |
| 子任务在不在跑、怎么结束 | **宿主**：subagent 服务与 `subagent/end` | 只记业务绑定：这个子任务是哪一步的评估 |
| 人对某个问题的回答 | **宿主**：user-questions | 内核亲自问、在进程内拿到答案，落一条复核或放行记录 |
| 哪些文件被交给了人 | **宿主**：会话日志里的 `deliverables/presented` | 结案时由内核写一次；模型另交的用原生 `present` |
| 文件每轮改了什么 | **宿主**：workspace-changes | 不维护账本与快照，不提供恢复 |
| 技能、项目说明 | **宿主**：skill 目录、`PROJECT.md` | 不自带技能模板与记忆 |
| 要检验哪条判断；事先承诺的判据；哪份观测用于哪次评估；评估支持 / 推翻 / 说不清；一条事实为什么获得或失去可引用资格 | **ClearAI**：会话日志里的内核事件 | 这是不可替代的部分。任务完成 ≠ 判断成立；评估失败 ≠ 判断被推翻 |
| 领域词汇、实例、断言 | **ClearAI**：`ontology/*`、`entity/*`、`fact/promoted.assertions` | 只经具名动词落账 |
| 冲突、本体图、实体图、进度、缺口 | **投影（派生）** | 每次现算，不存 |
| `clear/` 下的货架与本体格 | **渲染** | 不是权威；系统幂等重写，界面只读 |

## 二、几条推论

- **父回合结束，只证明父回合结束。** 子任务可能还在跑，也可能已结束、结论还没收集；只有宿主报告结束，才谈对应判断。宿主查不到，状态就是**未知**，不等于死亡。
- **评估者结束但结论没送到，先从它自己的会话日志取回**；取不回才如实落「未知」，并把「结束未收集」与「失联」分开写。
- **已经发生的失败必须允许记录。** 评估者崩溃、评估卡落盘失败，都是事实；拒收一条已经发生的失败，本身就是一次不实陈述。
- **两份读数不能证明同一口径，就只展示原始读数**，不宣称有效排名。

## 三、该拦还是该诊断

| 类别 | 处理 | 例子 |
|---|---|---|
| 非法业务操作 | 工具入口拒绝 | 模型直接完成目标、没有判据就交付、L3 以上自带裁决 |
| 已经发生的运行失败 | 必须允许记录 | 评估者崩溃、子任务被打断 |
| 历史记录自相矛盾 | 报告诊断，保留原件 | 引用不存在的步骤 |
| 无法证明的业务判断 | 标为未知，交给评估者 | 两条读数是否可比 |

## 四、领域词汇的边界

- **词汇事件不推进任何过程对象**，过程事件也不改词汇；两个状态机不互相嵌套。
- **断言只在升格那一刻随事实落地**；实例与观测断言在被观测到时带出处落账。
- **所有箭头指向读面**，读面不指回账本。
