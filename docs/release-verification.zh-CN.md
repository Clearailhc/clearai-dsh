# 发布前 recheck（逐组件）

面向「把这个插件发给别人用」的那一刻。**顺序即优先级**;每一格都写清
**判据 / 怎么验 / 通过线**,能机械化的就机械化(`tools/recheck.mjs`),剩下的人工项在文末。

## 怎么跑

```bash
# 机械面(单测 + 装机自检 + 打包 + 逐面字数预算)
node tools/recheck.mjs --log ~/.dsh/sessions/<桶>/<会话>/session.v3.jsonl.zstd

# 人工面(真浏览器):见文末「人工闸」
```

`--log` 给一场**有内容的真会话**(有目标/计划/步骤/证据/事实那种;模拟宿主的 `events.jsonl` 也行)。没有就跳过字数预算那一节,
它会如实说"没量"。

## 人工闸(机器验不了的,发布前必须点一遍)

在**隔离家**里(别碰自己那份):

```bash
cp -a ~/.dsh /tmp/smoke-release && \
DSH_HOME=/tmp/smoke-release bash install.sh && \
cd /tmp && DSH_HOME=/tmp/smoke-release npx --no-install @deepseek-ai/dsh web --port 3092 --no-open
```

用浏览器逐条点(`node tools/recheck.mjs` 末尾打印的是同一份):

1. **新建对话** → 发一句话 → 模型回话(证明插件没把 app 拖垮);
2. 中栏有 **探索** 与 **本体** 两格;右栏没有 ClearAI 的页签;
3. 打开一场**有证据的**会话:探索页眉有课题与标签,问题下列出候选假设,下一步带各候选的预测;屏上没有 `h-…` 这类编号;
4. 本体格:结论卡四部分齐全;本体图 / 实体图能切换;已确立的事实点开是进度 → 可信度变化 → 补充说明,「查看核验」开得出评估卡或评估者会话;
5. 结论卡点「**查看探索记录**」⇒ 切到探索;
6. 展开过程记录,在计划详情点「**查看此步骤的证据**」⇒ 对应判断展开;
7. 多份计划的会话:过程记录里的下拉能切到旧计划,并标「已收尾 · 存档可看」;
8. 有要人处理的事时,探索格与输入框旁都是「待处理 N」,只陈述、没有按钮;决定由原生提问卡问;
9. 新发现的问题点「**立为问题**」⇒ 对话里出现替您发出的那句话。

任何一条不过 ⇒ 不发布,回到对应组件的用例先补一条回归。

## 已知的未验项(如实挂着,别假装)

- **双向跳转的"点在真浏览器里"那一下**:机制与数据都验过(单测 + 真投影渲染),
  但完整点通需要一场带计划与证据的真会话,目前只在 node 渲染层验过;
- **客户端半也在宿主进程里缓存**:装完必须**重启 `dsh web`**,只刷新浏览器不够。
