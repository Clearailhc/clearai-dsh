# 少即是多:人与模型各自该感知到什么

这份文档是「少即是多」这一轮升级的**锚**:它回答在机制都对的前提下,**人应该看见什么、模型应该被喂什么**。机制的骨架(账本、准入、独立裁决、只增不删、人门)一行不动;这一轮做的全是减法。

它和另外两份锚的分工:

- 内部叫法(代码、账本、提示词、给模型的契约)的权威仍是[验证闭环](verification-loop.zh-CN.md)第 7 节;那里新增了「对人的叫法」一列,权威在那一列。
- 「知识」那一格的排布,权威是[领域本体](domain-ontology.zh-CN.md)第 9 节。
- 这份文档给出**为什么**、做了哪些**决定**、拿什么**判定**做到了。

---

## 一、起源:它到底要解决什么

用 AI 做研究,最大的风险不是答不出来,而是**答得太顺**:已知、推测和编造用同一种口气说出来。人分不清哪句能信;下一次再问,又从零开始。

认识论和本体论各管一半:

- **认识论**回答「这句话凭什么能信」。一个结论可信,当且仅当它经受住了一次本可以让它失败的检验,并写清在什么情况下不成立。
- **本体论**回答「这些结论加起来是什么」。成立的结论沉淀成结构——概念、关系、找到的具体东西——下一轮从已知出发,而不是从零出发。

## 二、对人只有四个问题

| 问题 | 谁来回答 | 在哪里 |
|---|---|---|
| 1. **现在能信什么?**(凭什么、在什么情况下不成立) | 认识论 | 「知识」格的结论清单;汇报里的「结论 / 凭什么 / 范围」 |
| 2. **什么被推翻了、什么还说不清?** | 认识论 | 结论清单的后两组;汇报里的「被推翻的 / 还没定的」 |
| 3. **这些加起来长成了什么?** | 本体论 | 「知识」格的页眉图(概念图 / 实例图) |
| 4. **需要我做什么?** | 人门 | 输入框旁的「需要你 N」、过程视图里的门、提问卡 |

其余一切——计划、步骤、等级、准入、裁决派发、世界线、账本、词条登记、缺口、续跑——都是**让这四个答案可信的手段**。手段必须查得到,但不该被呈现。

## 三、感知预算

### 给人的三层

| 层 | 什么时候出现 | 放什么 |
|---|---|---|
| **结果**(常驻) | 一直在 | 问题 1–3 的答案:结论清单 + 页眉图 + 你拿到的文件 |
| **需要你**(打断) | 只在真的需要时 | 问题 4:批准计划、在两条方案里选、处理互相矛盾的结论、复核被推翻的事实。没有就不出现 |
| **过程**(按需) | 点开才有 | 逐条依据、计划与步骤、方案对比、词汇维护、文件历史、技能目录 |

**判据**:一条信息若回答不了四个问题之一,就不进结果层;若不需要人行动,就不打断人。

### 给模型的纪律

模型也有感知预算,而它读到什么,就会转述什么。

1. **同一份事实只注入一次。** 运行态卡在状态变化时由 pre-step 注入;工具结果只说「这一下做成了什么」,不再附整张卡。
2. **卡上的读数不自相矛盾。** 一个数字只有一种意思;两种意思就拆成两个数。
3. **不重复说教。** 规则落在机制里,不在每一次回执里重讲一遍。
4. **对人说人的话。** 机制词是模型和系统之间的语言,汇报给人时要翻译(见第六节 D7)。

## 四、诊断:现在哪里在污染(以真实界面与真实会话为据)

1. **整张卡跟着每一条工具结果。** 两场真模型长测里,162 次 ClearAI 工具调用有 148 次在结果里附了一整张运行态卡,合计三十多万字;登记一个概念也要把判据与全部假设重读一遍。而同一张卡每一步之前本来就会注入。
2. **机制词外泄。** 面板上同时出现命题、假设、事实、升格、门槛、L0–L4、自判、世界线、人门、本体货架、读面……用户要先学二十多个词,才读得懂自己的研究。
3. **欠账排在知识前面。** 「缺口」(模型的待办,写的是「用 `RegisterInstance` 补」这类给模型的动作)排在已知之前。
4. **结构性的空。** 事实只在结案时升格,大半个会话里「已确认事实 · 0」,所有判断挤在「命题 · 验证中 · L0 · 自判」里。
5. **内部标识外泄。** 计划 id(`P-MTYCH5N1N02M · ACTIVE`)、证据 id(`e-1`)、阶段码(`stage_boundary`)、值形态(`statement`、`reference` 被画成和领域概念并列的节点)。
6. **自相矛盾的读数。** 卡上「阶段边界:步都落定了 · 完成度 0%」——派生的完成度在有活动计划时是「交付了几步」,没有时是「确立了几条判断」,同一个百分号两种意思。
7. **过程画成了结果。** 展开一条判断,先看到一张画满「没走过的转移」的状态机图。
8. **说教。** 「它是读面,不是权威」「你不能声明它们」「不许退化成随便挑一条」在卡片与回执里反复出现。

## 五、两层语言

内部名字不改(代码、账本、给模型的契约照旧);**界面与对人的汇报**只用「对人的叫法」。完整对照表在[验证闭环](verification-loop.zh-CN.md)第 7 节,这里只列最常用的:

| 内部 | 对人 |
|---|---|
| 假设 / 命题 | 判断 |
| 事实(已升格) | 已确立 |
| 验证中且有支持证据 / 没有证据 / 有证据但判不出 | 有依据,待复核 / 还没验 / 说不清 |
| 已推翻 | 被推翻 |
| L0 / L1 / L2 / L3 / L4 | 推理 / 查过资料 / 复算 / 独立复核 / 人工确认 |
| 自判 | 自己判的 |
| 冲突 | 说法不一致 |
| 本体货架 / 「本体」页签 | 知识 |
| 缺口 | (不对人显示) |

## 六、决定

每条写清**不选的那条路**为什么不选。

**D1 结论是一张清单,按能信的程度分组。** 已确立 / 有依据,待复核 / 还没验 / 说不清 / 被推翻;每行一句话,下面一句「凭什么」(依据的类别 + 是不是做的人自己判的)。已替代 / 已撤回只留一个归档数。
*不选「事实货架 + 命题货架」两张*:事实到结案才升格,前一张大半个会话是空的,人要找的东西全挤在另一张的机制词里。对人只有一个问题——能信什么——所以只排一张。

**D2 图是结果的另一半,常驻在页眉。** 有词条时,页眉画一张紧凑的图(本体图 / 实体图一键切换);点节点打开它的详情,「按此筛选」把下面的清单收窄到这个概念。图上**只画领域里的东西**:值形态(`statement` / `quantity` / `reference` …)是语言的语法,不画成节点。
*不选「图默认收起」*:这一轮的第一版这么做过,是错的——它把本体论的答案(问题 3)当成了过程。图既是门面也是索引,这与领域本体第 9 节原有的判断一致。

**D3 缺口只给模型。** 缺口是「这份知识还缺什么形态」的账,动作全是模型的动词;人既不能也不需要去补。它留在运行态卡上,不上「知识」格。若缺口挡住了结案,由模型用人话说明为什么还不能收口。

**D4 过程按需。** 点开一行只看:在什么情况下不成立、逐条依据(说人话、不带证据 id)、它说了什么(断言)、打开原文、看过程。删掉展开区里的状态机图。产物格先列「你拿到的」文件;计划收起成一行「做到第几步」,点开才看简述与步骤;不显示计划 id、授权记号、逐步判据全文与账面计数。

**D5 卡只注入一次。** 工具结果的 `message` 只说这一下做成了什么;卡留在结构化字段 `card` 里(`CheckPlan` 照旧把卡当正文——那是它的本职)。卡里删掉:运行档(部署预设,不是可据以行动的事实)、结尾说教、重复的阶段 / 完成度、重复的目标全文、未改过时的判据留痕行;判据只在「怎样算完成」出现一次。

**D6 一个数一种意思。** 「完成度 N%」换成两个具体的数:「计划 a/b 步 · 判断已确立 x/y」。派生量 `progress` 本身不改(其他读者仍在用),改的是卡上怎么说。

**D7 汇报口径。** 提示词要求对人说话用人的词,机制词与内部 id 不转述;结论按「结论 / 凭什么 / 范围 / 被推翻的 / 还没定的」写,没有的那项不写;过程只在人问起或需要人决定时再说。

**D8 不动什么。** 机制、账本、门、事件形状、工具契约、派生量的定义一律不动。代码里的内部名字不改。

## 七、怎么判定做到了

每条决定都要有一条会红的检查,不靠肉眼:

| 决定 | 检查 |
|---|---|
| D1 | `test/client.test.mjs`:分组与顺序;「知识」格里不出现 L0–L4、门槛、升格、自判、命题、本体货架 |
| D2 | `test/client.test.mjs`:有词条时页眉图常驻;值形态不成节点;没有词条时图不存在 |
| D3 | `test/client.test.mjs`:「知识」格不渲染缺口;运行态卡照旧带缺口(`test/readability.test.mjs`) |
| D4 | `test/client.test.mjs`:展开区没有状态机;证据行不露 id;产物格不露计划 id 与账面计数 |
| D5 | `test/kernel.test.mjs`:工具结果的 `message` 里没有运行态卡;卡里没有运行档与说教 |
| D6 | `test/kernel.test.mjs`:卡上不出现「完成度」百分比 |
| D7 | `test/prompt-sections.test.mjs`:交付段里有对人叫法的规则 |
