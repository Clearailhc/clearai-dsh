# 少即是多:用户该感知到什么

这份文档回答一个问题:**在机制都对的前提下,用户应该看见什么、听到什么**。机制的骨架(账本、准入、独立裁决、只增不删)不动;这里做的全是减法。

---

## 一、起源:它到底要解决什么

用 AI 做研究,最大的风险不是答不出来,而是**答得太顺**:已知、推测和编造用同一种口气说出来。人分不清哪句能信;下一次再问,又从零开始。

认识论和本体论各管一半:

- **认识论**回答「这句话凭什么能信」。一个结论可信,当且仅当它经受住了一次本可以让它失败的检验,并且写清在什么范围内成立。
- **本体论**回答「这些结论加起来是什么」。成立的结论沉淀成可复用的结构(概念、关系、具体的东西),下一轮从已知出发,而不是从零出发。

两者对用户的全部价值,可以压成三个问题:

1. **现在能信什么?** 结论 + 凭什么 + 在什么范围内成立。
2. **什么被推翻了、什么还说不清?** 负知识与开放问题同样是成果。
3. **需要我做什么?** 只有人能做的决定。

其余的一切——计划、步骤、等级、准入、裁决派发、世界线、账本、词条登记、缺口、续跑——都是**让这三个答案可信的手段**。手段必须可查,但不该被呈现。

## 二、感知预算:三层

| 层 | 什么时候出现 | 放什么 |
|---|---|---|
| **结果**(常驻) | 一直在 | 结论清单:已确立 / 有依据待复核 / 还没验 / 说不清 / 被推翻。每条一句话 + 一行人话的「凭什么」+ 范围 |
| **需要你**(打断) | 只在真的需要时 | 只有人能做的决定:批准计划、在两条方案里选、处理互相矛盾的结论。没有就不出现 |
| **过程**(按需) | 点开才有 | 证据链、计划步骤、方案对比、概念图、词汇维护、文件历史 |

**判据**:一条信息若回答不了上面三个问题之一,就不进常驻层;若不需要人行动,就不打断人。

## 三、现在哪里在污染(以真实界面与真实会话为例)

1. **机制词汇外泄。** 面板上同时出现命题、假设、事实、升格、门槛、L0–L4、自判、世界线、世界树、人门、本体货架、读面、权威……用户要先学二十多个词才读得懂自己的研究。
2. **欠账排在知识前面。** 「缺口」清单(模型的待办)排在「已知」之前,而且写的是「用 `RegisterInstance` 补」这类给模型的动作。
3. **结构性的空。** 事实只在结案时升格,大半个会话里「本体货架 · 0」,所有判断都挤在「命题 · 验证中 · L0 · 自判」。用户看不到自己已经知道了什么。
4. **内部标识外泄。** 计划 id(`P-MTYCH5N1N02M · ACTIVE`)、假设 id(`h-kakmke`)、阶段码(`stage_boundary`)、值形态节点(`statement`、`reference` 被画成和领域概念并列的节点)。
5. **自相矛盾的读数。** 运行态卡上「阶段边界:步都落定了 · 完成度 0%」同时出现。
6. **说教。** 工具回执和运行态卡里反复出现「它是读面,不是权威」「你不能声明它们」。模型每回合读到,就会转述给人。
7. **过程画成了结果。** 展开一条判断,先看到的是一张画满「没走过的转移」的状态机图。

## 四、说人话:对用户的词

内部名字不变(代码、账本、给模型的契约照旧);**界面与汇报**只用右边这一列。

| 内部 | 对用户 |
|---|---|
| 命题 / 假设(hypothesis) | 判断 |
| 事实(已升格) | 已确立 |
| 验证中且有支持证据 | 有依据,待复核 |
| 已提出 / 验证中但没有证据 | 还没验 |
| 有证据但判不出 | 说不清 |
| 已推翻 | 被推翻 |
| 已替代 / 已撤回 | 归档(默认收起) |
| L0 / L1 / L2 / L3 / L4 | 推理 / 查过资料 / 复算 / 独立复核 / 人工确认 |
| 自判 | 自己判的 |
| 冲突 | 说法不一致 |
| 本体货架 | 知识 |
| 本体图 / 实体图 | 概念图 / 实例图 |
| 缺口 | (不对用户显示,只给模型) |

## 五、这一轮做的减法

1. **「本体」格 → 「知识」格**:一张结论清单按上面五组排;缺口移出;图带默认收起成一行;概念图不画值形态节点;展开一条只看「凭什么」(证据一行一条),不再画状态机。
2. **产物格**:先列「你拿到的文件」;不显示计划 id;计划简述默认收起。
3. **运行态卡**(给模型):删掉运行档说明、结尾说教与重复读数;阶段与完成度不再互相打架。
4. **工具回执**:删掉每次重复的说教句。
5. **汇报口径**(提示词):对用户说话时按「结论 / 凭什么 / 范围 / 被推翻的 / 还没定的」,不用机制词。

不做:机制、账本、门、事件形状、给模型的工具契约一律不动。
