# ClearAI 核心主张红队评估

日期：2026-11-06。对象：仓库 0.5.7、当前源码；宿主兼容修复由主代理单独验证。本报告没有运行付费模型、不把历史 0.5.1 结果当作 0.5.7 实测结果。方法为文档交叉审查、执行路径审查及独立工具守卫探针。严重性：P1 表示核心信任边界或产品主张需优先处理；P2 表示证据不足或文档误导。

## 结论

ClearAI 有可核查的工程价值：把结案、审计派发、来源坐标、事实升格与回收做成可追踪状态；对于“模型自由宣告完成”的问题，它提供了真实约束。但这些约束不能推出“知识为真”“每条本体边经过独立验证”或“比裸模型更有效率”。当前最强证据支持的是流程可追踪性和部分边界执行，而非通用科学有效性。

## C1 / P1：『每条边都有独立验证』把本体定义与已验证事实混在一起

- 宣称：`README.zh-CN.md:19`、`:21`、`:61` 分别说每条边经过证据与独立评估、本体每个关系都有来源和验证记录。
- 代码事实：`preset/plugins/clearai-kernel.js:252` 明确模型可直接写本体的 concepts/relations/entities；`:3027` 接收 Frame 的本体列表；`:3210`–`:3217` 在 Frame 中写盘并同步。这条路径执行格式/引用检查，不派发独立评估。`:5062` 和 `:5242` 也明确本体三支是模型可写区。
- 影响：用户可能把词汇定义、候选结构或实例关系理解为经过验证的事实。形式自洽与经验真实性是不同性质，不能用同一个“每条边验证过”承诺覆盖。
- 判定：静态实现证据已确认；没有声称构造过真实模型伪造事实攻击。
- 建议：把核心表述限定为“升格为已确立事实的断言经过准入与评估”；UI 视觉区分模型定义的结构、待检关系与已验证断言。

## C2 / P1：评估者的『只读』不是文件系统级隔离

- 代码：`preset/evaluator.cordis.yml:42`、`:46`、`:67`、`:68` 给评估者 bash/pwsh；`preset/plugins/clearai-evaluator-face.js:58` 的 guard 只按工具名字判断，允许 shell 后不检查命令能力或目标路径。
- 实测：独立导入 apply，用最小 tools stub 捕获 guard；`guard({name:'write'})` 被拒；`guard({name:'bash',args:{command:'echo tamper > /tmp/redteam-example'}})` 返回 undefined（放行）。没有执行该写命令。
- 核验补偿：`clearai-kernel.js:4594`–`:4601` 会在 auditRerun 模式下比较 gate.confirmed 的产物摘要，能发现这些文件的最终变化；这不是只读沙箱，也不覆盖未申报文件、临时改后复原、外部副作用。`:1063` 的提示词本身承认复跑可能写入全局用户数据目录。
- 影响：若评估者误用命令或被产物中的指令影响，可能污染原始证据或其他文件。新子会话提供了角色分离，但不等于数据不可变性或统计独立性。
- 建议：优先使用真正不可写的原始证据快照、限定写入的复跑目录；在没有该机制前，把“只读”改成“禁用直接写工具、要求在副本复跑，并对声明产物做事后摘要检查”。

可复现探针（从仓库目录执行）：

```js
import { apply } from './preset/plugins/clearai-evaluator-face.js'
let guard
apply({ tools: {
  view: () => ({ restrictableNames: ['write', 'bash'] }),
  restrict: () => {}, guard: g => { guard = g },
}}, { allow: ['read', 'bash'] })
console.log(guard({ name: 'write' }))
console.log(guard({ name: 'bash', args: { command: 'echo tamper > /tmp/redteam-example' } }))
```

## C3 / P1：主要效果展示遗漏已完成、较不利的后续对照

- `README.zh-CN.md:186` 仍写“0.5.1 的对照尚未跑完”；`:196` 展示旧实验约 2.2 倍 token。
- 仓库已有 `docs/optimization/sim-runs/2026-10-08-0.5.1-dev/README.md:10`，结论是止损线未通过；`:28`–`:35` 记录预测有本体来源仅 47%、多个机制指标不达标、含评估总 token 为裸模型 4.8–7.2 倍。
- `docs/known-gaps.zh-CN.md:21` 已承认该结果，所以不是没有披露，而是首页证据选择与后续记录不同步。
- 影响：仅看主页面的读者会系统性高估当前证据。历史结果不证明 0.5.7 仍失败，也不能被单元测试通过或 0.5.3 机制 probe 的 passed 替代。
- 建议：主页面并列报告后续不利结果、测试版本、成本口径和未完成的当前版本独立留出集验证。不要使用“已证实更高效/更正确”作当前结论。

## C4 / P2：可复核审计证据链没有被完整强制

- `clearai-kernel.js:906`/`:930` 要求 basis 是一句话，论证放 refs；但 `:1022` 明确 refs 非必填，`:1030` required 只有 holds、basis。
- `:1181`–`:1187` 对 refs 仅归一化路径和行号，未在这里证明评估者真的读过这些行。评估请求提供的是作者生成的文件与判据，`observations` 在 `:4488` 一律登记 source:self。
- 影响：格式合法的正面裁决可以没有逐条可复核坐标；摘要证明内容被绑定，不证明内容来自可信来源，也不证明论证正确。若模型和评估者共享知识盲点，两个角色仍可能一起相信伪数据。
- 判定：代码边界确认；未跑真实模型的伪来源成功率实验，不宣称已有可利用的端到端伪造样本。
- 建议：对高等级支持裁决要求至少一项可验证引用和逐项 criterion 结论；显示“来源是作者提交/独立取得/复跑生成”的区别；留出集加入伪数据、循环引用、诱导文档和共同偏差题。

## C5 / P2：停止检查只能保证登记项完整，不能证明科学探索完备

- `README.zh-CN.md:60`/`:75` 给人的理解是会改变答案的候选与反常已处理。
- `clearai-kernel.js:3373` 附近注释已经明确“只查有没有写，不判断写得对不对”；`:3395`–`:3412` 遍历的是已登记 candidates/anomalies/questions，并接受把 ID 写进 open.about。它不能发现从未进入账本的备择机制、错误问题框架或共同遗漏。
- 好的一面：当前实现会考虑评估者发现的异常，不能把旧版“评估者异常没登记”的历史缺陷直接归到当前版本。
- 建议：产品称“已登记事项的结案完整性检查”；把发现新候选、盲评提出替代解释、未解释项抽样审计作为独立质量指标。

## C6 / P2：『每问题至少两个候选、动手前分别预测』不是当前硬契约

- 宣称：`README.zh-CN.md:73`。
- 当前配置：`clearai-kernel.js:364` 的 minHypotheses 默认为 0，主预设不再配置下限；`test/preset-composition.test.mjs:58` 明确断言“不再设假设数量下限”；`:5546` 的 predictions 文案为 Optional。预测动作本身检查非空，不能推出每一步已预注册全部候选预测。
- 影响：文档让用户误以为强制对立假设、预注册已全面实现；实际上这是一部分提示与可选结构。取消凑数假设可能是正确设计选择，问题在于旧承诺没有同步。
- 建议：改成“允许按候选记录预测，提示不能区分候选的检验”；若确需硬契约，先明确例外场景并在真实任务验证其收益与成本。

## 应保持的优点与验证边界

- 知识文件由系统所有、模型不能通过同一普通写工具直接替代事实升格；高等级交付拒收工作者自带 results，评估回包由内核接收。这比只写提示词更强。
- 将 unknown、pending、失败与通过分开，保留被推翻判断，审计材料绑定摘要，均为可测试的工程能力。
- 独立评估是“不同会话与工具角色”的独立性；没有不同模型/盲化/来源隔离约束时，不能解释为相互独立的统计证据。
- 0.5.3 native-probe 明确写了“Engineering mechanism probe ... not evidence of comparative quality or token savings”，应保留这个诚实限制。

## 下一轮验证建议

先冻结当前版本与基线 DSH、工具和预算，在外部人员编写的留出任务上预注册。每项记录：最终答案质量/错误确信率、关键异常漏检率、真实引用可复核率、全子代理 token 与墙钟时间、失败/挂起率。对照至少包括裸模型、仅结构记录、加独立评估、完整 ClearAI；盲评而且保留未完成任务为失败。当前报告没有把未执行的新一轮实验填成成功或失败。
