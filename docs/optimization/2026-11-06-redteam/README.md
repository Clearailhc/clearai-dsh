# ClearAI 0.5.7：DSH 兼容性修复与红队评估

日期：2026-11-06。基线提交 `47f8cda175ed3bf73162fa3dc47a4c0d3874a542`。运行环境：Node 24.22.1、pnpm 11.25.0、DSH 0.2.2-rc.1。本轮保持 ClearAI 版本号 0.5.7；按用户要求不做旧宿主兼容，不发布。

## 总判断

**最新版 DSH 的预设启动问题已修复；核心价值有工程支持，但正确性和净效率的强主张尚不成立。** 事件投影、裁决记录、拒绝自报完成和独立评估提供可追踪的约束；它们不能直接推出结论真实、探索完备或整体节省成本。当前应优先修复文件保护和审计缓存边界，再完善 UI，最后以当前版本的配对盲测决定效果主张。

## 兼容性修复与验证

DSH 0.2.2-rc.1 已将 `list_agents` 合并到 `@deepseek-ai/dsh-tool-subagent-control` 主入口，并取消 `/list-agents` 子路径。旧配置仍加载子路径，导致 ClearAI 主预设 `broken: never started`。

最终改动仅删除 `preset/agent.cordis.yml` 中过时的独立挂载，重新生成 `pack/presets/clearai.patch.yml`。主控制插件保留，版本号与依赖声明未改。中途研究的旧版兼容层不在最终实现中。

| 检查 | 结果 | 证据 |
| --- | --- | --- |
| 真实最新版 DSH 干净安装、注册和启动 | 修复前21通过/1失败，修复后22通过/0失败 | [安装日志](clearai-compat-fixed.log) |
| 全量项目测试，含已安装宿主和客户端 | 通过；native 37/37，宿主38/38、客户端180/180，其余套件见日志 | [测试日志](clearai-fixed-tests.log) |
| 发行包可重建与实际打包 | 45通过/0失败 | [包校验日志](clearai-fixed-package.log) |
| 真实 Chromium 图谱装载、绘制、拖动 | 9项通过；不能代表完整产品UX通过 | [浏览器日志](ui-browser-probe.log) |
| 真实模型会话与当前版本配对效果实验 | 未执行，环境未配置模型凭据 | 不作通过或失败判断 |

现有干净安装测试已捕获原始缺陷，并验证修复后的两个预设均没有 broken。本轮没有通过修改测试断言来消除失败。

## 红队发现与处理顺序

P1 表示优先影响信任边界或关键任务可用性，P2 表示重要的效率、体验或表述问题；这些是本次评估的优先级，不是已成功利用的通用安全评级。

| 优先级 | 发现 | 证据强度及影响边界 |
| --- | --- | --- |
| P1 | 受保护文件写入可绕过 | 用真实内核 guard 和一次性目录实测：Python、Node、变量拼接命令被放行且成功写 `clear/evidence`；未证明会话日志的权威变更可伪造 |
| P1 | 绝对路径产物修改后错误复用旧裁决 | 完整测试宿主路径复现：WRONG改VALID后仍返回旧拒绝、评估调用仍1次；未复现错误接受 |
| P1 | 评估者“只读”缺少执行层隔离 | 直接write被拒而bash写命令通过guard；未执行真实模型攻击或此评估者写命令 |
| P1 | “每条本体边都独立验证”超出实现 | Frame可直接写模型定义的本体结构，未逐边派审计；不能与已确立事实混为一谈 |
| P1 | 当前净效率没有充分证据，首页结果陈旧 | 未找到0.5.7配对验收；历史0.5.1结果为4.8–7.2倍总处理token，不能当成当前版本实测 |
| P1 | 键盘用户无法操作多个核心图谱入口 | 真浏览器DOM确认点击span不进入Tab顺序；结论展开的同类问题由源码确认 |
| P1 | 375px全屏详情挤掉图谱 | 实测canvas宽2px，抽屉右边界412px超出375px视口 |
| P2 | 图谱默认适配牺牲文字可读性 | 50个长标签构造样本中，12.5px节点字实际显示约5.8px |
| P2 | 裁决字符上限不是生成成本上限 | native schema删除maxLength；消费后截断不能追回已生成token费用 |
| P2 | 每次审计快照复制过多材料 | 同步复制包含.venv与嵌套node_modules；本地微基准约156.7ms/65.5MB，不外推生产延迟 |
| P2 | 引用、候选、停止条件和双语辅助提示存在缺口 | refs非必填、停止门只涵盖已登记项、两个候选不再强制，中文图有英文读屏说明 |

## 复现

从仓库根运行；需要允许子进程、本地监听与系统Chromium。脚本中的文件写入限于一次性测试目录。

```bash
node docs/optimization/2026-11-06-redteam/repro-authority.mjs
node docs/optimization/2026-11-06-redteam/repro-cache.mjs
node docs/optimization/2026-11-06-redteam/repro-digest.mjs
node docs/optimization/2026-11-06-redteam/efficiency-probe.mjs
node docs/optimization/2026-11-06-redteam/ui-browser-probe.mjs
```

前三个探针归档后已再次执行，结果与报告一致。UI探针使用真实React/React Flow和生产客户端模块，但主题、数据、API由夹具提供；它不等于完整DSH用户旅程。本轮未做真实读屏器、完整英文界面、触屏、跨浏览器、生产长会话或WCAG全量审计。

## 建议下一步

1. 先修权威文件隔离和绝对路径摘要/缓存一致性；让评估者对原材料真正只读。
2. 修复键盘入口、窄屏详情及图谱默认可读性，同时纠正文档中超出证据的表述。
3. 冻结修复后版本，执行预注册的配对实验：裸模型、仅结构记录、加评估、完整ClearAI；独立留出题、盲评、相同模型/预算，失败和取消不剔除。分别报告质量、错误确信率、实验次数、所有代理token、实际费用及墙钟时间。

除DSH兼容性问题外，本报告列出的产品缺陷本轮仅评估与复现，尚未修复；避免将报告归档误解为这些风险已解决。
