# ClearAI 0.5.2 设计:能实际改变行动的知识闭环

2026-10-09 定稿(第十一节为已确认的决定)。方向已与您确认:重心是「沉淀与取用通过适用范围对接」,计算是其中一步;正向与负向信息都尽可能回灌本体与实体图。

## 一、闭环与判据

**遇到问题 → 取用本体知识并检查适用性 → 提出假设 → 计算或实验 → 根据证据调整 → 循环直到问题解决、证实或证伪 → 保存可复用成果(丰富本体与实体)。**

判据:一项机制只有在它提供的信息或约束**改变了某次判断、实验或方案选择**,并且以可接受的成本带来更好的结果时,才算有价值。只增加记录的机制,收益限于可审查性。

### 0.5.1 断在哪里

闭环的两端都没有接上:

- **取用端**:模型自行翻阅 `clear/knowledge/` 与 `clear/ontology/`,系统不做适用性检查。旧知识要么不被使用,要么被用在范围外(良率题中九月数据撤回了八月范围内成立的事实)。
- **沉淀端**:事实的 `scope` 存的是推翻条件(`clearai-kernel.js:3270`),没有可检查的适用范围;经验是自由文本,不挂在实体上;被推翻的假设、未解释的反常、测量缺陷都不跨会话保存。下一次无从判断哪些已知适用、哪些已排除。

已有的正面证据也指向这一点:同一现场 3 题序列中,经验在第 3 题被点名使用 3/3,漂移纠正 5/6 对裸模型 1/6(仓库内 `docs/optimization/sim-runs/2026-10-08-site-series/README.md`)。带过去的是做法,带不过去的是「哪里已经排除、哪里不适用」。

## 二、可复用成果的单位:挂在实体上的知识条目

沉淀的格式等于取用的格式。每条知识是实体图上的一条记录:

| 字段 | 含义 |
|---|---|
| `about` | 涉及的实体或概念(如「反应釜 R-2」「热电偶 TC-1」「良率(按月)」) |
| `kind` | 见下表 |
| `statement` | 一句话陈述 |
| `scope` | 适用范围:条件(产线、月份、批次、工况)、变量取值范围、所用口径的定义指纹 |
| `status` | 成立 / 已排除 / 范围外 / 待核验 / 未解 |
| `evidence`、`level` | 证据与检验程度(沿用现有等级) |
| `use` | 可选:可重跑的核算或预测模型(`clear/models/<id>/`) |
| `history` | 来源会话、复检、范围扩展或收缩 |

### 正向与负向条目

| `kind` | 方向 | 例子 | 来源(多数由系统从账本生成) |
|---|---|---|---|
| 事实 | 正 | 「R-2 上 T 与 cat 沿斜脊耦合(T 150–175 °C,cat 0.8–1.6)」 | 评估者支持的判断 |
| 模型 | 正 | 收率二次响应面,含 T×cat 项,留一误差 0.6 | 结案时登记的计算依据 |
| 口径与校准 | 正 | 「TC-1:实际温度 = 设定 − 8 °C(第 25 次后)」 | 解释掉的测量类反常 |
| 已排除 | 负 | 「在 L2、2026-08 范围内,操作工不是良率下滑原因」 | 被证据推翻的判断 |
| 范围外 | 负 | 「八月的 B0723 归因在九月数据上不成立」 | 复检时新数据落在原范围外 |
| 缺陷 | 负 | 「TC-1 会漂移」「快测外推寿命偏高」 | 测量或方法类反常 |
| 未解 | 负 | 「同设定收率 91.07 → 86.99,未解释」 | 结案时仍开着的未解释项 |
| 做法 | 正/负 | 「此装置存在耦合,单因素优化无效」 | 评估者核过的经验(现有 lessons,补 `about` 与 `scope`) |

负向条目在避免重复踩坑上往往比正向条目更有用:已排除的不再花预算重验,范围外的不再误用,缺陷先核,未解的优先追。

### 存储

在现有知识目录旁加一个负向目录,其余在现有文件上补字段:

- 事实(`clear/knowledge/facts/`)新增 `about`、结构化 `scope`(`scope_spec`);范围外的反证记在事实自己的 `boundaries` 上,事实保持成立。
- 经验(`clear/knowledge/lessons/`)新增 `about` 与 `scope`。
- 已排除、未解、缺陷写进 `clear/knowledge/negatives/<id>.json`,一条一个文件,由系统从账本生成。实施时改为单独目录、不写进实体文件的 `history`:实体文件归模型所有,系统改写它会与模型的写入冲突;条目带 `about`(实体 id),按实体 id 查找一次即可同时取到事实、经验与负向条目。
- 模型放 `clear/models/<id>/`,由事实或做法条目的 `use` 引用。

## 三、闭环各步的机制

| 环节 | 系统(确定性,不耗模型 token) | 模型 | 改变了什么行动 |
|---|---|---|---|
| 遇到问题 | `Frame` 新增 `about`(涉及的实体、量)与 `conditions`(本次的产线、时段、工况),供适用性判定使用 | 说清要做的决策 | — |
| 取用并检查适用性 | 不另设检索机制。条目都是文件,模型用原生文件查找取用。模型在判断或步骤的 `uses` 中引用某条时,系统当场判定:口径指纹变了 → 口径已变;条件与本次 `conditions` 冲突 → 范围外;取值超出 → 外推;本身待核验 → 待核验;否则适用。有 `use` 核算且有新数据的,先重跑再判定。判定结果随工具返回 | 自行查找相关条目;判断语义上是否同一回事 | 适用的直接用,不从零摸索;已排除的不再重验;范围外与外推的先检验再用 |
| 提出假设 | 不在卡上列条目 | 结合数据与反常提出假设,`uses` 注明来源;不强制数量 | 从已知出发,避开已知的坑 |
| 计算或实验 | 有模型时,在计划的操作点上运行模型给出数值预测;新数据到来时比对预测,偏差超出噪声即自动登记未解释项 | 写计算、设计实验 | 反常不依赖模型自己留意 |
| 根据证据调整 | 判断被推翻、反常被解释或转交,都在账上;取用的条目若在本次被反驳,按范围区分「范围外」与「反证」 | 解释反常、修改假设 | — |
| 循环直到解决 | 停止检查(审计之后,见第四节) | 决定下一步或结案 | 会改变结论的未决项不能静默结案 |
| 保存成果 | 结案时从账本生成全部正负条目,挂到 `about` 实体上;范围由判断的 `scope` 与所用数据的实际范围合并 | 补写提炼性的做法;确认 `about` | 下一次取用可以判定是否适用 |

### 取用:文件查找,而不是检索机制

本体、实体图与知识条目都是工作区里的 JSON 文件,模型用原生的文件查找(按实体 id、量名、关键词)就能取用,不需要另设类似 RAG 的检索与卡上列表。系统只做两件让查找可靠的事:

- **文件可查**:条目一条一个文件,`about` 使用实体与概念的稳定 id。按实体 id 在 `clear/knowledge/` 下查找一次即可取到正负两类条目。
- **引用时判定**:适用性在模型通过 `uses` 引用某条时当场判定并随工具返回,不需要预先检索。

风险是模型不去查。提示词中只保留一句「立题后先查找 `about` 涉及实体的已有条目」;是否奏效由 M2 检验,不奏效再考虑系统提示,不预先加机制。这也省去了卡上的取用列表,降低成本。

### 回灌的写入规则

- **随发生随写,不只在结案时写。** 负向条目在发生的那一刻落盘:判断被证据推翻、反常被解释为测量缺陷、取用的条目在本次被判范围外。正向事实仍在结案时经独立评估后升格。这样会话因预算或 token 限制中断、以 `partial` 或 `abandoned` 结束时,负向信息不会丢失。
- **系统写,模型补。** 已排除、范围外、未解、缺陷、模型、口径条目由系统从账本生成,模型不需要额外写文件;模型只补做法类条目,并可修改 `about` 的指认。
- **范围默认继承。** 条目的 `scope` 依次取:判断自己的 `scope`、`Frame` 的 `conditions`、所用数据的实际取值范围。三者都没有时标为「范围未声明」。
- **负向条目标明强度。** 已排除条目带推翻它的检验程度与次数(如「1 次自行检验」),界面与工具返回都显示为「初步排除」或「已排除」。初步排除不阻止后续重新检验,只提示「曾经排除过,依据较弱」。这是为了防止一次带噪声的检验错误地排除了真实结构(例如耦合),使后续会话再也不去检验它。
- **独立评估只核正向事实与做法**(现状不变);已排除条目不做独立评估。
- **撤回只在范围内。** 取用的条目被新证据反驳时,若新证据落在其范围外,记为「范围外」并收窄或注明范围,原条目保持成立;范围内的反证才走撤回,仍由人确认(现状)。

## 四、修复(0.5.1 已核实的三处漏洞)

1. **停止检查移到审计之后**(`clearai-kernel.js:3071`)。顺序改为:评估者审计 → 评估者提出、未在状态中的问题登记为未解释项 → 停止检查。审计超过 `auditTimeoutMs` 时如实记为「未知」并释放目标,避免一次审计拖住整组运行。
2. **适用范围与推翻条件分开**(`:3270`)。判断新增结构化 `scope`;事实的 `scope` 不再取 `refute_when`。没有范围信息的事实标为「范围未声明」。
3. **测量门改为取用时的口径检查**(`:2124`、`:2742`)。删除按 `kind` 检查的立题门;改为:同一物理量在本体中有多个口径(设定、回读、探头)时,取用或绑定数据时必须指明口径,口径指纹不同的条目判为「口径已变」。测量关系的 `check` 可指向一份可重跑的核算(如「探头与设定之差」),由系统在新数据到来时重跑。

## 六、成本

0.5.1 的成本主要来自模型自身(裸模型的 4–6 倍),评估者只占 13%–24%。

1. **先测量**:模拟宿主记录每次请求的输入构成(系统提示与工具说明、运行态卡、工具结果、对话历史),长测记录按构成报告。
2. **提示词**:循环一节按本设计重写,删去第五节对应内容;目标是系统提示加 ClearAI 工具说明的 token 数降低 40% 以上。
3. **运行态卡只发变化**,并设长度上限;卡上不列知识条目,由模型按需查找文件。
4. **回灌由系统生成**,不增加模型回合。
5. 另一线程正在排查 0.5.2 长测因 token 限制终止的问题,结论若涉及上下文增长,并入本节。

## 七、验证方案

所有长测的模型、独立评估者与对照组均为 Sonnet 5.5,思考强度中等;评分者盲评,只看该题的最后答复与产物。

### 1. 主体:同一现场的问题序列

闭环的价值体现在第 N 个问题上,单题对照测不出「沉淀 → 取用」。因此主体是序列测试,两组对照(您 2026-10-09 确定:先只对比裸模型):

| 组 | 内容 | 回答的问题 |
|---|---|---|
| A 裸模型 | 每题独立,同一工作区,无额外机制 | 基线 |
| C ClearAI 0.5.2 | 完整闭环 | — |

「裸模型 + 笔记」对照暂不做;若本轮通过,在正式验证时再考虑加入,以区分本体的作用与「有地方记」的作用。

### 2. 序列题设计(新编,开跑前封存答案)

在现有现场模拟器(`tools/sim/long-horizon/site/`)基础上编一组 4 题序列,每题专门检验闭环的一个环节:

| 题 | 内容 | 检验 |
|---|---|---|
| t1 | A 线优化(有漂移、有耦合) | 产生正负条目 |
| t2 | A 线换催化剂批次再优化 | 正向复用:模型与口径校准适用,应以更少实验达到目标 |
| t3 | B 线优化,B 线热电偶无漂移、无耦合 | 适用性:A 线的条目范围外,误用会导致过度纠正 |
| t4 | A 线收率突降的问题定位 | 负向复用:已排除项不重验,缺陷与未解项优先查 |

另保留良率归因三连(`lh-factory-1/2/3`),检验跨月份的范围处理。

### 3. 次要:单题不劣与成本

反应器、电解液、固态电池调研各 A/C 3 + 3,只检验得分不低于裸模型与成本。0.5.1 已说明单题上的收益有限,这一部分不作为有效性依据。

### 4. 机制指标(从账本机算)

- **M1 回灌完整**:每次结案,账上的被推翻判断、开着的未解释项、测量类反常,落成条目的比例(目标 ≥ 95%)。
- **M2 取用被使用**:t2–t4 中,至少一条取用条目出现在判断或步骤的 `uses` 中的比例。
- **M3 适用性判对**:t3 中 A 线条目被判为范围外的比例;任何一题中,范围外条目未经检验即进入结论的次数。
- **M4 负向复用**:t4 中重验已排除项所花的实验次数(C 对 A)。
- **M5 范围误撤回**:范围内成立的事实被范围外数据撤回的次数(目标 0)。
- **M6 静默结案**:评估者提出、未处理而结案的问题数(目标 0)。

### 5. 止损线(预注册,任一不满足即停止并重新设计)

| 编号 | 条件 | 不满足的含义 |
|---|---|---|
| S1 | M1 ≥ 95%,M2 ≥ 80%,M5 = 0,M6 = 0 | 闭环机制本身没有接上 |
| S2 | t3 中误用 A 线条目导致结论出错:C 组 0 次 | 适用性检查无效,存下的知识会伤人 |
| S3 | t2–t4 均分(按各题满分归一后)C ≥ A + 0.5,且 t2–t4 相对 t1 的提升 C 大于 A | 沉淀与取用没有带来更好的结果 |
| S4 | t2、t4 达到相同得分所用实验次数 C ≤ A 的 80% | 复用没有节省预算 |
| S5 | 「错而自信」C 组不多于 A 组 | 可信性退化 |
| S6 | C 组含评估者的总 token ≤ A 组 2.5 倍 | 投入产出不达标,先裁剪 |

规模:序列 2 组 × 3 个序列 × 4 题 = 24 次,另加良率三连与单题检查约 22 次。开发集只对照止损线,不作为有效性证据;通过后按 0.5.1 计划第五节第 2 条做正式验证(新题由不看代码的代理出、每组 6 次、双盲评、bootstrap 置信区间),再做消融(去掉适用性检查、去掉负向条目、去掉系统生成回灌)。

## 八、界面

原则不变:「探索」货架放过程,「本体」货架放结果;人与模型读同一份记录;界面上的操作只替人向模型发一句话,不直接写状态。新增的内容都围绕「沉淀了什么、这次用了什么」。

### 1. 本体货架:实体图成为知识的主视图

- **实体节点显示知识计数。** 每个实体节点旁标出挂在它上面的条目数,按状态分色:成立、已排除、超出范围、待核验、未解。负向条目在图上用虚线边表示。
- **实体卡。** 点击实体,打开实体卡,分六栏:
  - 已知成立(陈述、适用范围、检验程度、来源会话)
  - 已排除(陈述、排除依据与强度,初步排除单独标注)
  - 适用边界(在哪些条件下不成立)
  - 测量与口径(口径、校准关系、已知缺陷,如「TC-1 第 25 次后偏低 8 °C」)
  - 未解问题(仍开着的反常)
  - 做法(经验)
  每条可展开查看证据与历史(提出、复检、范围收窄)。
- **本体图显示口径。** 一个物理量的多个口径(设定、回读、探头)显示为同一量下的分支,校准关系标在连线上。
- **人对条目的操作。** 条目上提供「请复检」「请撤回」「请修改适用范围」三个按钮,点击后向模型发送一句说明,由模型落账。
- **结论卡底部加一行沉淀摘要。** 例如「本次沉淀:成立 2 条、已排除 3 条、未解 1 条」,点击跳到对应的实体卡。

### 2. 探索货架:这次用了什么、将留下什么

- **「取用的知识」一节。** 列出本次通过 `uses` 引用的条目及系统判定:适用、超出范围、口径已变、超出取值范围、条件未声明。判定不是「适用」的条目排在前面,并说明后续如何处理(先检验、按新口径换算、待您确认)。
- **「将沉淀的内容」一节。** 实时列出本次已写入的负向条目,以及结案时待独立评估的正向条目。人在结案前就能看到将留下什么,并通过对话纠正。
- **待您处理。** 新增两类:范围内的反证要求撤回某条已有知识;取用的条目口径已变,需要确认换算方式。

### 3. 用语

新增词条按 [ui-wording](../0.5.1-plan/ui-wording.zh-CN.md) 的原则拟定,定稿前请您确认:适用 / 超出范围 / 口径已变 / 超出取值范围 / 条件未声明;成立 / 已排除 / 初步排除 / 待核验 / 未解;适用范围、测量与口径、已知缺陷、本次沉淀。

## 九、整条通路推演:盲点与断点

以「同一现场 4 题序列」为例,从第一题开始逐步推演,每一处可能断开的地方及处理如下。

| # | 环节 | 断点或盲点 | 后果 | 处理 |
|---|---|---|---|---|
| 1 | 遇到问题 | **新会话不知道有旧知识。** 文件查找的前提是知道去找 | 旧知识完全不被使用 | `Frame` 返回时附一句计数:「工作区中与 `about` 涉及实体相关的已有条目 N 条(成立 a、已排除 b、未解 c),位于 …」。只给计数与位置,不给内容,不构成检索机制 |
| 2 | 遇到问题 | **实体身份不一致。** 本次叫「反应器」,上次叫「R-2」 | 查找落空,或同一实体建出两份 | 实体文件新增 `aliases`;`about` 引用新实体时,系统按名称与别名的相似度提示「可能与已有实体 R-2 相同」,由模型确认合并或另建 |
| 3 | 遇到问题 | **实体图稀疏。** 现状是「只在结论要指认时才建实体」 | 回灌无处挂载 | `Frame` 的 `about` 即建立或引用实体;回灌默认挂在 `about` 上 |
| 4 | 适用性 | **本次条件未声明。** 模型没写 `conditions`,所有条目都会被判为适用 | 范围外的知识被当成适用,正是良率题的反向错误 | 条目范围中有某一维度、而本次条件未声明该维度时,判定为「条件未声明」,不判为适用,并要求说明 |
| 5 | 适用性 | **用了却没引用。** 模型读了旧知识直接用,没写 `uses` | 适用性检查被绕过;机制指标也测不到 | 结案审计时,评估者核对结论所依赖的旧知识是否都已引用;未引用的列为缺口。M2 同时度量引用率 |
| 6 | 提出假设 | **初步排除被当成定论。** 一次带噪声的检验排除了真实结构 | 后续会话不再检验真实结构,知识越积越错 | 负向条目标明强度;初步排除不阻止重验(见第三节写入规则) |
| 7 | 计算或实验 | **计算与条目脱节。** 模型写了脚本,但脚本不挂在任何条目上 | 下次无法复用,也无法重跑 | 结案时把产生正向事实的脚本登记为该事实的 `use`;不强制,缺失时在沉淀摘要中如实显示「无可重跑的计算」 |
| 8 | 根据证据调整 | **反驳没有回到条目。** 本次数据与某条旧知识矛盾,但模型没有显式复检 | 旧条目一直显示成立 | 未解释项的 `touches` 可以指向条目;引用过的条目所支撑的判断被推翻时,系统按范围比对把该条目标为「待核验」或「超出范围」 |
| 9 | 根据证据调整 | **评估者发现的问题不入账**(0.5.1 漏洞) | 静默结案 | 第四节第 1 条修复;这些问题同时作为「未解」条目回灌 |
| 10 | 保存成果 | **只在成功结案时回灌。** 中断、`partial`、`abandoned` 时什么都不留 | 失败中最有价值的负向信息丢失;token 限制中断的长测正是这种情况 | 负向条目随发生随写(见第三节写入规则) |
| 11 | 保存成果 | **范围缺失。** 判断没写 `scope` | 事实无法判断是否适用 | 范围默认继承 `conditions` 与数据实际范围;都没有时标为「范围未声明」 |
| 12 | 保存成果 | **负向条目成为噪声。** 为凑数提出的弱假设被推翻后大量回灌 | 实体卡被无关的已排除项淹没 | 已删去「至少两个候选」的要求,弱假设本身会减少;界面按强度与时间排序,初步排除默认折叠 |
| 13 | 下一次取用 | **口径变更无法传导。** 0.5.1 的「定义已变」从未触发,原因是事实不链接本体 | 改了良率口径,旧结论仍被当作适用 | 条目的 `about` 与 `scope` 中的口径 id 都参与定义指纹;口径变化后引用即判「口径已变」 |
| 14 | 下一次取用 | **知识陈旧。** 条目很久以前成立,装置已变化 | 过时知识被当作现状 | 判定结果附「最近一次检验于第几题或何时」;超过人设定的期限显示为「待核验」(默认不设期限,由您决定) |
| 15 | 人的介入 | **人无法纠正知识。** 现在只能手改 JSON | 错误知识长期留存 | 实体卡上的「请复检 / 请撤回 / 请修改适用范围」(见第八节) |
| 16 | 范围之外 | **知识只在一个工作区内。** 换文件夹即无法复用 | 跨项目的现场知识不能共享 | 0.5.2 不处理,明确列为已知缺口 |
| 17 | 验证 | **序列题由了解机制的人编写。** 可能针对机制出题 | 开发集结果偏乐观 | 开发集只对照止损线;正式验证的题目由不看代码的代理出,开跑前封存 |
| 18 | 验证 | **裸模型在序列中可以自行留文件。** 同一工作区里裸模型也能自己写笔记 | 比较的是「ClearAI 闭环」对「模型自发的记录」,这是有意的口径 | 记录中写明裸模型是否自发留了文件、后续是否读取 |

推演后的结论:按原设计,第 1、4、5、10 四处会直接让闭环断开(不知道有旧知识、范围外误判为适用、用了不受检查、中断时什么都不留);第 6、8、13 三处会让知识越积越错。以上处理均已并入第三节与第八节。

## 十、实施顺序(确认后)

| 步 | 内容 | 完成标准 |
|---|---|---|
| 1 | 第四节三处修复 | 单元测试;良率会话二回放不再撤回八月事实 |
| 2 | 条目字段(`about`、`scope`、负向状态与强度)、实体 `aliases`;负向条目随发生随写、正向条目结案时写 | 一次中断的会话也留下负向条目;一次结案后账上的推翻、未解、缺陷全部落成条目 |
| 3 | `Frame` 的 `about`、`conditions` 与已有条目计数;`uses` 引用时的适用性判定(含「条件未声明」);反驳回到条目 | 端到端剧本跑通「适用 / 超出范围 / 口径已变 / 条件未声明」四种判定 |
| 4 | 删减与成本(第五、六节),模拟宿主记录输入构成 | 提示词与工具说明 token 降 ≥ 40%,附前后对比 |
| 5 | 界面(第八节) | 宿主测试通过;截图逐块对照;用语经您确认 |
| 6 | 模型与核算(`clear/models/`)、新数据时的预测比对与核算重跑 | 先验证宿主能否执行模型声明的命令;不可行则退回为模型执行、系统校验产物 |
| 7 | 新序列题与答案键封存,开发集长测与记录 | 按第七节执行 |

## 十一、已确认的决定(2026-10-09)

1. 对照组只用裸模型,暂不加「裸模型 + 笔记」。
2. 已排除条目不做独立评估,以强度标注(初步排除 / 已排除)替代。
3. 新编 4 题现场序列作为主体验证,单题只做不劣检查。
4. 模型与核算的自动重跑放在最后,前几步不依赖宿主执行脚本。
5. `Frame` 返回已有条目的计数与位置,不返回内容。
6. 知识陈旧默认不设期限。
