# PR #23 之后的 v0.5.2 候选

基线固定为 `4a866bc5c22f80face7b5c0a78a83e6fe832f7da`。本候选保留按需建本体、开放假设来源和实体挂知识的实现，不合入旧 RC.4。日常工作区、安装和既有实验记录保留。合并、发布不属于这轮交付。

## 审计与持久复核

评估卡的两层路径组件都是完整 SHA-256，卡内仍保存原始步骤与评估者 id。读取优先使用账本 `card_path`；历史路径不迁移。正常结束与子会话恢复共用落盘函数，落盘失败始终为未知。

`v4:` 审计指纹绑定规范化完整答案、经验、判据、引用条目、定义语义、输入、方法脚本和交付文件内容。显示名称、别名、审计派发时间和审计产生的证据不使相同材料重复付费。补证据、改变答案、处理异常或实质改动方法都必须重新审查。旧指纹仅供查阅，不用于本规则结案。

派发前把意图写入原生会话并 flush，再保存子会话关联。没有持久写入监听器、flush 失败或无法保存子关联时停止派发。恢复通过原生 `sessionQuery.observeSession` 查询非驻留子会话；只有成功的权威 `structured_output` 可恢复新裁决。DSH rc.2 不支持 `maxLength`，因此派发 schema 把长度限制写到说明中，读取方仍限制输出长度；缺少结构化能力不能退化成正文裁决。

事实可保存系统字段 `calculation={model,reference,inputs,method,at}` 与 `rechecks[]`。`reference` 固定为接受事实时的结果，后续执行只增加观测。内容摘要改变才重跑；相同输入不能清除待核验。失败、缺输出或无基准均持久记为复检未完成。重跑使用原生 bash/pwsh 工具、权限及取消机制，符合 rc.2 的 `description` / `timeoutMs` 参数契约。

复核按原因逐条解除。独立评估者的 `rechecks:[{fact,id,basis}]` 只解除本次明确确认、范围匹配的原因；有核算原因时还要核对当前方法、输入和原基准。人工入口的明确维持裁决可以解除已见原因，之后新发现的原因保留。范围外观测记录边界，不撤回原范围事实。

## 取用与图

`Conclude.answers[].uses?:string[]` 表示答案直接使用的条目 id；不会继承 Frame 中的拟用引用。独立评估者逐条返回 `reuse:[{id,verdict,basis}]`，最终答案保存 `uses_review` 的确认、指纹和评估卡。读文件、相关性匹配和立题引用均不能算成功实际复用。

事实、经验、已排除项、缺陷和未解项仍挂在 `about` 指向的概念、关系和实体上。新的事实文件另保存 `evidence_records`，使新会话能打开原始依据；旧事实不补造历史证据。实体卡展示复核原因、恢复方式和证据入口。定义语义改变触发复核；仅改显示名称或别名不触发。

缺范围、文字边界、部分重叠、缺单位及不可比较口径保持未知。支持和反驳分别保留原范围、证据，不生成普遍逆命题。
