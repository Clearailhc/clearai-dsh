# 端到端长测:剧本、结果与发现

> 这份文档回答一个问题:**把认识论循环真跑起来之后,机制之间还对不对得上?**
> 单测覆盖的是每个函数;这里覆盖的是它们的**先后与配对**——推进前有没有准入、
> 分叉有没有留孤儿、评估者有没有悬空、被推翻的假设会不会被升格。

## 为什么要单独做长测

阶段 8 的两场 headless e2e(建计划即停、两步收尾)与一场真浏览器 e2e,
验的是「装得上、跑得通、面板画得出」。它们的共同点是**短**:两步、十几拍,
最深的那几条链(世界线分叉与算术裁决、证伪、长链多步、侦察先于计划、目标链)
一次都没跑过。而这几条链恰恰是最容易在**长度**上出问题的地方:

- 短跑里每个机制各出现一次,«A 在 B 之前»这种**顺序**断言等于没验;
- 分叉、评估者这类**异步**对象,只有跑到收敛与回填才看得出配对关系;
- 证伪这类**负结果**路径,正常跑动里不会自然触发。

所以长测的断言分两层:每个剧本验自己那条链,另有一组**跨机制不变量**对所有剧本生效。

## 怎么跑

```bash
npm run e2e:long                                   # 全部剧本,并发 3
node tools/e2e-parallel.mjs --scenarios long-plan,scout-first
node tools/e2e-parallel.mjs --concurrency 1 --timeout-min 45
node tools/e2e-run.mjs --scenario falsification --keep   # 单场,留着现场看
```

产物:

- `docs/optimization/e2e-logs/<剧本>.log` —— 每场完整输出(含每条断言的通过/失败与变更直方图)
- `docs/optimization/e2e-logs/summary.json` —— 结构化汇总(用时、变更数、失败项、现场路径)
- `--keep` 会把临时工作区与会话日志路径打出来,便于事后翻证据

**并发上限默认 3**:每场自己还会派世界线执行者与独立评估者,一场最坏拉起三四条模型流,
并发开太大打的是 API 的限流,不是本机的 CPU。这一点如实记进 `summary.json`。

## 剧本目录

| 剧本 | 验什么 | 为什么单测不够 |
|---|---|---|
| `worldline-arbitration` | 分叉两条世界线、各自交付读数、`ConvergeFork` 按事先登记的尺子算术裁决、采纳赢家 | 分叉/世界线/读数/裁决是机制里最深的一条链;单测只到内核函数的边界,`worldline/prepared → executed → converged → merged` 的**配对**没人验过 |
| `falsification` | 两条互斥假设,一条 support、一条 **refute**;只把成立的那条升格为事实 | 「推翻是有价值的结果」是这套循环的口头禅,但真跑里从没出现过负结果路径 |
| `long-plan` | 五步长链:数据 → 计算 → 独立核对 → 报告 → 写记忆,全物证落地并收尾 | 步数一多,«跳步推进»、«物证造假»、«收尾不干净»才有机会出现 |
| `scout-first` | 先 `SpawnScout` 只读侦察,拿到结论再立目标建计划 | 侦察是**同步只读**那条路,它与主线的衔接(收结论 → 据此立约)没在真跑里验过 |
| `goal-chain` | 一个对话里连做两个目标,第二个复用第一个的产物 | 「一个对话多个目标」是面板与投影的一等公民,第二个目标会不会把状态机搞乱没人验过 |

任务书里**点名**要用哪个工具(见 `test/e2e-scenarios.test.mjs` 的断言):
这里测的是**装配**,不是模型的创造力——任务书不说,模型可能绕开那条链,那场就白跑了。

## 跨机制不变量(所有剧本都跑)

| 不变量 | 它防的是什么 |
|---|---|
| 没有跳过准入的推进 | 每个 `step/advanced` 之前必须有一条该步的 `admission/checked`。少了它,「先交付再补证据」这种顺序错误会静默通过 |
| 评估者没有悬空 | `audit/dispatched` 的条数不得超过 `audit/settled`。派出去没人收,面板上那条裁决会永远停在「在跑」 |
| 分叉不留孤儿 | 每个 `fork/created` 都要以 `converged`/`abandoned`/`undecidable` 收口 |
| 证据都挂在存在的步骤上 | `evidence/recorded.step` 必须属于本计划的步骤 |
| 声明的物证真的在盘上 | 已推进步骤声明的 `artifacts` 必须真的存在(与内核准入同一判据:得是文件) |

**不变量本身也有人管**:`test/e2e-scenarios.test.mjs` 给每条不变量配了**反例**——
造一份坏日志,断言必须红;造一份好日志,断言必须绿。
理由是直接的:如果断言写漏了,长测会以「全绿」的姿势骗人,那比没有长测更糟。

## 发现

### 1. 侦察结论回灌断了(真缺陷,**只修了一半**)

**现象**:`SpawnScout` 派出的侦察**正常跑完**(子会话 `turn/end{completed}`,6 步 30 次工具调用),
但父会话里 `scout/settled` **一条都没有**,资料面也没有 `source:'scout'` 的观测。
两次 scout-first 场(两批)完全一致。

**根因**(读代码 + 对日志):
`AwaitWorldlines` 的等待循环靠 `sweepWorldlineExecutors()` 产出的「仍在跑」行数决定要不要继续等
(`clearai-kernel.js` 的 `pending()`),而**只有世界线执行者会产那行**(:1470);
`sweepScouts()` 从来不报「还在跑」。于是**只有侦察在跑时**,`running` 恒为 0,
循环第一拍就退出——模型被告知「要在这个回合里等它,用 `AwaitWorldlines`」
(SpawnScout 自己的返回原话),而那条路**根本不会等**。

一次性形态还叠了第二层:没有下一回合,侦察若在最后一次工具调用之后才落定,
就再也遇不到下一个回收点。

**后果链(第二场的完整证据)**:模型的判据里写了「内容与**侦察结论**一致」,
而侦察结论不存在 ⇒ 独立评估者裁决 **inconclusive** 并拒收结案,原话:

> 该句以「侦察结论」为对照物,而 scout s-… 的结论未落在任何可读位置……
> **故该半句无可核验对照物**

于是模型又立了第二份计划、再次 `CloseGoal`、仍被拒,最后开人门问人。

**这一条同时是好消息**:循环**没有**把「判据依赖一个不存在的产物」放过去——
审计机制抓住了装配层的缺陷,报的是 inconclusive 而不是 achieved。没有假绿。

**修法(已落地)**:
1. `sweepScouts()` 把「内存表里 `settled === null` 的条目数」作为 `pending` 返回;
2. `collectExecutors()` 把它透出来;
3. `AwaitWorldlines.pending()` 把 `scoutsPending` 计进 `running`。
侦察在场时循环就会真的等,落定那一拍 `publish`(`landedIn` 在下一拍看到账已落)。

顺带修掉同一处的**另一句假话**:回报里的「回灌 N 条」数的是**变更条数**,
而一条侦察会落两条变更(`scout/settled` + 观测)——模型读这句话是判断「它回来了没有」,
数变更会把一条报成两条。现在数的是**结论条数**,措辞也写全了(「回灌 1 条结论」)。

**修后验证**(同一剧本真跑一场,内置 deepseek-flash)——**注意:这一场是弱判据下的假绿**:

| | 修前(两批) | 修后 |
|---|---|---|
| 侦察结论 | `scout/settled` **0 条**(子会话却已 `completed`) | `scout/settled` **1 条**,4000 字结论进资料面(`source:'scout'`) |
| 结局 | 目标开不开,评估者裁 `inconclusive` 拒收,模型改计划后开人门 | 目标 **`achieved`**、计划剩 0 步、**36 通过 0 失败** |
| 不变量 | 「侦察没有悬空」红 | 七条不变量全绿 |

顺带一个正面观察:侦察的工具面**没有 bash**(只读角色,设计如此),侦察在结论开头
如实写明了「用 `glob`+`read` 替代目录感知,目录是否存在是推断」——外脑的诚实纪律也成立。

**但这一场的 36 通过 0 失败只证明了「账落了」,没证明「模型读得到」**——
判据查的是 `scout/settled` 存不存在、资料面里有没有 `scout:` 引用,
而这两件事与「结论正文进没进模型上下文」是两回事。见发现 6。

### 2. 一次性形态没有「下一回合」(形态限制,已知)

侦察/执行者的结论回收点挂在工具成功返回上,而「跨回合补发」是设计里的第二条保险。
headless 一次性形态只跑一个回合,这份保险没有机会生效;常驻形态(有续跑窗口)才有下一回合。
这条与发现 1 相互放大:修了发现 1,单回合内的等待就能拿到结论;不修,单回合必等不到。

### 3. 模型会回避「写下推翻」(行为发现,1/2)

证伪剧本要求「不成立的那条必须给 refute」,任务书里写死了。
第一批做到了(h-ok support / h-no refute,假设状态算出 `refuted`);
第二批两次记录**全是 support**,那条被观测证伪的假设一直停在 `proposed`。
机制侧没问题(`verdict` 枚举里有 `refute`,第一批走通过),这是**模型的判断倾向**。
不过更准的读法是:批二里 `h-no` **根本没被任何证据触及**(而不是「写了 support」)——
模型只测了会成立的那条。机制对此是**诚实**的(状态停在 `proposed`,卡片上看得见),
但结案门不要求「假设都判过」,所以它照样结了案。**这是设计问题,不是缺陷**:
要么在结案门加一句提示/一道要求,要么明确接受「`proposed` 就是诚实的未知」。

顺带的教学:一条断言如果考的是「模型肯不肯做某件事」,它就会随模型波动。
所以剧本里这类断言现在都标了「这条考的是模型的判断,不是机制」,
而真正的机制性质(比如「被推翻的绝不许升格」)由**安全性质**断言与等级自洽不变量管。

### 4. 判据本身被抓过三次(方法学)

长测的价值建立在判据正确之上。这一轮里,**我写的判据错了五次**,每一次都是真日志抓出来的:

| 错法 | 真相 |
|---|---|
| 数 `worldline/prepared` 的**变更条数** | 一条变更携带**全部**世界线,要数 `branches` |
| 用 `plan/created` 的步骤集判证据归属 | 计划会被 `plan/amended`(单个 `step` 对象,不是数组)修订 |
| 同上,把「记过证据之后被作废」的步当孤儿 | 那是历史,不追溯;要**按时间顺序就地判** |
| 不认合成锚点 | 目标级审计落在 `goal:<目标id>`,世界线级落在 `<forkId>:<branchId>` |
| 目标还开着就要求「到级必须升格」 | 升格只发生在 `CloseGoal` 那一刻 |

教训直接写进工具:`test/e2e-scenarios.test.mjs` 给**每条不变量都配反例**
(坏日志必须红、好日志必须绿),并且把判据抽成**唯一一份实现**供
`e2e-run` 与 `e2e-replay` 共用——否则「跑一场」和「重判一场」会各说各话。

### 6. 侦察结论对**模型**不可见(真缺陷,未修;上一轮的验证是弱判据下的假绿)

修完回灌之后复查「模型到底读到了什么」,发现结论正文**只出现在变更记录里**:

```
结论正文("侦察结论(只读)")出现的位置:.data.meta.mutations[0].conclusion / [1].note
模型可见文本(tool/result 的 message.content、user/assistant 消息)里出现次数:0
```

而模型每一步读到的 `clearai` 注入段就是 `renderCard()`(kernel :5562 `sections:[{name:'clearai', text: card}]`),
**`renderCard()` 里没有「资料面」这一节**——`state.materials` 只进了 `view()`(面板),
从没进过卡片。可是工具消息两次承诺它在那里:

- `SpawnScout` 返回:「结论会作为观测回灌到资料面(来源标 scout),**下一步卡片的「资料面」里能看到**」
- `AwaitWorldlines` 返回:「回灌 1 条结论」+ 一张没有资料面的卡片

**后果**:侦察(外脑那条链)对**模型**几乎无用——它只知道「有一条结论回来了」,
读不到结论说了什么;而判据里一旦写「与侦察结论一致」,模型与独立评估者**都**无处可读
(结论既不在模型上下文里,也不在工作区文件里),只能裁 inconclusive 拒收。
发现 1 与这一条是**两件事**:前者是「结论没落账」,后者是「落了账也读不到」。

**为什么上一轮没发现**:判据查的是账(`scout/settled` 存在、资料面有 `scout:` 引用),
没查**模型的上下文**。这是本轮第六次判据失效,也是后果最重的一次——它给出的是**假绿**。
修法里必须同时补一条断言:**结论正文必须出现在某条 tool/result 的 message.content 里**。

### 5. 还没看到的(诚实边界)

- 世界线**并列/不可判**那条路(`fork/undecidable`、横评仲裁)没被自然触发过;
- `MapScouts`(一次多条侦察)没用上——第一批只用了单条 `SpawnScout`;
- 长链场只到五步;25 步上限那条路没压过;
- 两批都跑在 headless 一次性形态,**常驻形态**(窗口叫醒、跨回合补发)没有并跑对照。

## 复算(怎么复核这些结论)

判据只有一份实现(`tools/e2e-scenarios.mjs` 的 `evaluateLog()`),`e2e-run` 与
`e2e-replay` 共用它,所以任何一份日志都能离线重判、不花 token:

```bash
node tools/e2e-replay.mjs --scenario scout-first \
  --log ~/.dsh/sessions/<slug>/session-xxxx/session.v3.jsonl.zstd \
  --workspace /var/folders/.../clearai-e2e-ws-XXXX
```

原始的每场日志与会话日志路径都在 `e2e-logs/summary*.json` 里(`--keep` 保下的现场路径也在)。
