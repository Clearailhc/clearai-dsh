# ClearAI 0.5 阶段三设计:探索深度

2026-10-08 草稿,待定。上接 [meta-design.zh-CN.md](meta-design.zh-CN.md) 与 [upgrade-plan.zh-CN.md](upgrade-plan.zh-CN.md)。

## 结论

**探索浅是认识论问题,不是搜索算法问题。** 三套现场序列里,模型都看到了耦合的信号,却把它记成「说不清」就停了;评估者又用一个碰不到斜脊的检验判「最优在内部」成立。缺的不是更多实验手段,而是三条纪律:

1. **结论只说检验够得着的范围。** 「单因素邻域里最优」和「最优」是两句话,证据不一样。
2. **可能推翻主结论的「说不清」是开着的问题,不是终点。** 它要么花预算拆开,要么让主结论收窄。
3. **经验要记在能迁移的那一层。** 「酯化的 T 与 t 耦合」到了胺化就被判不适用;「温度常和另一个因素沿斜脊耦合」才带得过去。

三条都落在已有的对象上(判断、未解释项、经验),不加新工具、不加新门。建议放进 0.5 作为阶段三,原来的阶段三(正式验证)顺延为阶段四。

## 证据:浅在哪里

数据来自 [2026-10-08 现场序列](../sim-runs/2026-10-08-site-series/README.md),第 3 题(C 线,温度与 cat 沿斜脊耦合,真最优 94.1%)。

| 现象 | 例子 | 说明 |
| --- | --- | --- |
| 信号有,被归档成「说不清」 | sc1 半因子里 T×cat 与 P×t 别名,交互 −29;报告结论 10 写「说不清:交互的归属,没有专门拆分」 | 交互比任何主效应都大,却没占一次预算 |
| 检验碰不到推翻条件 | 「规格内最高收率在内部」的推翻条件是「最优点在边界且邻点单调」;检验只做了单因素邻点 | 在斜脊上,单因素邻点都更低,最优却在对角方向。评估者判支持 |
| 预算花在确认上 | sc2 推荐点重复 5 次、备选再 4 次,共 9 次 | 确认到 2–3 次后,多出来的次数几乎不改结论 |
| 经验带过去了,但层级太低 | sc1 的 l-7m96i2「酯化这类连串反应收率对温度和时间强耦合」;sc3 的 l-l0onyj「酯化类体系最优往往在较低 T 配较长 t」 | 都写成酯化专属,到 C 线不适用。sc1 第 1、2 题耦合都得了分,第 3 题反而 0 |
| 有害经验通过了核验 | sc1 的 l-rjw23e「中心点已在高收率平台时,直接在中心点做单因素邻域」 | 这正是会停在斜脊错误点上的做法,评估者判支持 |

裸模型同样浅(第 3 题耦合三组都是 0),所以这不是 ClearAI 引入的问题。但 ClearAI 有现成的位置去管它:判断的推翻条件、未解释项、经验的核验。

## 第一性原理

一个「最优」主张,隐含着一个全称命题:**在没去过的地方,没有更好的点。** 只有两种办法让它可信:去过足够多的地方(覆盖),或者有一个模型说明没去过的地方不会更好(机理)。单因素邻域两样都没有,它只证明了「沿坐标轴走一步不会更好」。

所以探索深度的问题可以还原成认识论问题:**主张的范围比检验的范围大。** 认识论循环本来就要求每个判断带推翻条件;缺的是检查「这批数据有没有可能碰到推翻条件」。碰不到的检验,结果只能是「区分不了」,不是「支持」。

推论:不需要教模型响应面方法。只要它不能把「单因素邻域最优」说成「最优」,它就要么去拆交互,要么老实收窄结论。两种都比现在好:前者找到斜脊,后者让人知道还有没探过的方向。

## 改动

### ① 检验够不够得着(评估者)

- `evaluatorPrompt` 加一问:**这条推翻条件,这批数据碰得到吗?** 碰不到就给 `inconclusive`,在 basis 里写明缺什么样的观测才碰得到。
- 「最优」「最好」「内部峰」这类主张,评估者要核它的推翻条件有没有覆盖两个以上因素同时变的方向;只做了单因素的,判 `inconclusive`,不判 `support`。
- 提示词与 Frame 说明加一句:主张写成检验够得着的范围(例如「在单因素邻域内,推荐点最好」)。
- 改哪里:`clearai-kernel.js` 的 `evaluatorPrompt`、Frame 说明;`prompts.js`。

### ② 能推翻主结论的「说不清」是开着的问题(未解释项)

- `Anomaly` 加可选字段 `stakes`:这条如果成立,会动哪条判断或结论(引判断 id 或写「主结论」)。评估者的 `anomalies` 已有 `matters`(会不会动摇结论),两边对齐成同一个意思。
- 卡片上,带 `stakes` 的开着的未解释项排在最前,写明「这条可能推翻 h-xxx;下一步要么拆开它,要么把 h-xxx 收窄」。
- 结案时评估者多核一件事:有没有带 `stakes` 的项还开着,而对应的结论没收窄。有的话记一条 `shortfall`(判据「结论范围」),`holds` 不能是 yes。这在已有的独立评估门里,不新增门。
- 「说不清」本身不改:真的拆不开(预算用完、需要另一套装置)时仍可交给人,但结论要按已检验的范围写。
- 改哪里:`Anomaly` schema、`fold.js` 的 `anomaly/opened` 带 `stakes`(状态版本 +1)、`knowledge-view.js` 排序与一行提示、`evaluatorPrompt`。

### ③ 经验记在能迁移的那一层(经验核验)

- Conclude 的经验说明加一句:写成下一条**不同**的线也用得上的形式。具体对象和数值放进 `evidence`,`text` 写做法和它对哪类体系成立。
- 评估者核经验时多两条判据:
  - **太窄**:只是这次结论的复述,或只对这一条线成立,判 `inconclusive`(不落盘)。
  - **会误导**:照它做会跳过它自己的凭据里显示还没解决的问题(例如「直接做单因素邻域」而凭据里交互还没拆),判 `refute`。
- 本体里已有 `affects` 关系的 `shape: coupled`。经验里出现「A 与 B 耦合」时,提示词建议同时在本体里写一条 `coupled` 关系,挂在类别上(「液相反应」),不挂在某条线上。这样下一题写预期时,它会作为「用到的关系」出现在卡片上。
- 改哪里:Conclude 说明、`lessonBrief` 的判据段;`prompts.js`;不改 schema。

## 不做什么

| 不做 | 理由 |
| --- | --- |
| 内置实验设计(响应面、贝叶斯优化) | 违背「靠模型自己的能力」;题目换一类就失效 |
| 强制每个因素对都做交互实验 | 预算不允许,也会让简单题变重(违背「不添乱」) |
| 预算门(剩多少次时拦住确认) | 门只留给独立评估和人;用卡片排序和评估者核结论范围就够 |
| 新的「开放问题」对象 | 未解释项已经是它,加一个字段就行 |

## 怎么验

1. **预注册。** 复用现场三题,ClearAI 与裸模型各 3 个序列,同模型(Sonnet 5.5,思考中)、同预算、盲评。
2. **主指标。** 第 3 题的耦合项(0–1)与配方真值离真最优的差。门:ClearAI 第 3 题耦合项至少 2/3 组得分,且配方真值的平均差距小于裸模型。
3. **机制指标。** 带 `stakes` 的未解释项第 3 题至少出现在 2/3 组,且其中至少一组为它花了预算(做了两个因素同时变的实验);落盘的经验里至少一条写成跨线形式并在第 3 题被引用。
4. **不添乱。** 一道没有交互的简单题,ClearAI 次数与耗时不超过裸模型 2 倍,结论不劣。
5. **止损。** 机制指标不成立,先修机制;机制成立而主指标不成立,记下来,不改题重跑,在正式验证里当作阴性结果报告。
