# 0.6 候选版：固定题复核与优化方向

本次目标是判断当前版本哪里真正退步，并以最小改动减少重复核验，同时保留独立验证和可复用本体。当前候选版验收未通过，不建议发布。工程回归通过不能替代真实任务完成。

新版历史交接与阶段事实能力保留，先修确定性遗漏；不据此整版回退。按下面的顺序逐项做小幅改动，再以同条件复用与条件变化任务检验可信本体的实际收益。

数据核对通过：输入哈希、模型、安装包、使用量、角色归属、隔离探针和隐藏真值配方评分一致；评估者运行期间没有父代理模型轮询。证据见 [release-baseline-comparison.json](release-baseline-comparison.json)。本次新增旧版对照估算 $0.53830；累计记账约 $5.47367 / $30，包含此前已接受的 $0.80 未知用量预留，无新增未知用量、无待结请求。

## 能从记录确定的问题

1. **评估通过不等于流程能收束。** 候选版两题共 5 次独立评估都为 `holds=yes`，两题仍未完成。当前瓶颈不能统称为“首次评估失败”。加性题 3 次步骤评估重复支持同一最优区，交互题两次评估同一组 3 条主张。
2. **局部问题会压住无关事实。** `AdvancePlan` 整理评估结果时丢失 `independent_of_open_issues`，随后又因任一未决重要问题阻止所有阶段事实保存。此次已修复为与原生主张核验相同的逐主张边界检查。影响范围未知、主张受影响或缺少评估者独立确认时，仍不保存事实。该修复不能消除真实记录里未明确影响范围的异常，不能声称重放后必然多出事实。
3. **中间核验与最终交付混在一起。** 加性题在尚未进入提交步骤时多次被登记“submission.json 不存在”，且 `matters=unclear`。这是最终义务未完成，不自动构成当前证据错误；同时也不能从此忽略最终交付检查。
4. **历史交接没有保证增量核验。** 交互题修改 5 个普通文件后，第二次仍对同一组主张做大量重算。当前以整个工作区变化判定失效是保守的，但历史裁决加文件差异仅作为提示，并未建立可执行的依赖边界。不能因文件看起来只是报告就自动认定无影响。
5. **本体录入的工具往返多。** 两题分别出现多次 Frame 修订及前置拒绝，包括未登记的 about、缺失 assertions、主体类型错配、遗漏修订判据。单字符 x/y 被 ID 校验拒绝，错误文案却只说明最长 40 字符，没有说明至少 2 字符。保留约束，改清楚 schema、例子和一次返回的诊断，比反复补救便宜。
6. **事实自身的范围表达不够细。** 交互题裁决正文限定“峰区”“只有一个复测点，无法排除更慢漂移”，事实仍沿用较宽的原主张和目标级范围。证据链接保留了限制，但检索、图谱和后续复用不应要求每次重新读裁决才能发现限制。需要把评估后的限制直接绑定到事实及断言。
7. **已反驳的信息传递不及时。** 加性题 quick 可比性的反例在中间评估异常里已出现，但未属于当步被检主张，直到最后一步才正式得到 refute。不要把异常文本自动升级成裁决；应让主代理知道哪条主张需要定向补核，避免继续把旧支持当作现状。

## 优化次序与通过条件

### 1. 先修确定性丢失，不增加新的代理层

此次修复步骤核验的逐事实沉淀。接着统一工具契约与诊断：说明 ID 的真实长度、修订必填项，返回合法主张 ID，集中列出本次提交的结构问题。保持原子提交，不为减少错误绕过本体校验。通过条件：同样的错误输入一次得到完整可执行的诊断，无额外模型调用，非法断言仍不能写入。

### 2. 区分本次核验义务、未来义务和相关风险

沿用现有评估请求，明确本次评什么、哪些最终交付尚未到期。未来义务继续留在目标中，不写成无范围的当前科学异常；如果它确实影响当前证据，则必须说明依赖并阻断受影响部分。对正式 refute 使用现有主张结果通道；只发现反例线索则给主代理定向补核建议。通过条件：缺最终报告不阻止独立测量事实，缺影响测量的校准仍阻止该事实，最终报告缺失仍不允许结案。

### 3. 把增量复核建立在已核实的依赖上

不增加第二套任务调度器。扩展现有裁决凭据，记录每条主张实际核验的来源、方法、判据、范围、本体定义和信任配置，以及依赖是否完整。主代理与探索代理提供证据定位、已排除解释和反例线索；评估者核实这些信息，作者不能自行给证明材料盖章。依赖已知且未变的裁决才可限定范围复用；变更触达的主张及下游需要重核；任何未知依赖保守扩大检查。

通过条件：无关文件修改不会重派相同核验；修改计算脚本、引用来源、适用范围、单位、判据或信任配置必然触发相关复核；删除文件、漏记依赖、取消和迟到结果均不能沿用旧结论。测量实际模型调用、token 和 wall time，不用缓存命中率代替收益。

### 4. 让最终核验聚焦覆盖缺口与答案一致性

默认工作流也应做单独对照：候选版加性题仍选择五步计划，交互题选择按需 ReviewClaims。新旧两条路径并存时，不能假定模型会自然选择更经济的路径。先在现有官方工具接入能力内明确新会话的默认入口与旧会话兼容入口，保留旧计划恢复，不修改宿主，不凭这一组结果直接移除兼容能力。

正常探索与自查由主代理完成，独立核验应发生在结论将影响重要决策、准备持久化知识或最终交付时。已有有效独立凭据的主张不重复从头证明；最终评估检查答案依赖是否覆盖、引用与当前材料是否一致、未决风险是否如实披露。没有有效凭据时必须补核，不能用“只看摘要”代替。

通过条件：相同有效材料不会因“阶段/结案”换一个名称就再做整轮实验；主代理隐藏关键依赖、答案扩大支持范围、材料已过期时仍能检出。

### 5. 把可信本体作为有质量的输出衡量

把裁决限定的适用域、测量分辨率和未解决问题写到被支持的事实/断言上，必要时窄化命题并保留修订来源。不要把一个宽命题拆成多个条目来美化数量。测量、仪表、响应模型、约束与适用条件尽量使用已有类型化关系连接，避免全部塞进 has_property 的一段文字；原始观测作为可追溯证据保存，不自动成为普遍规律。衡量任务重要知识的覆盖、范围准确性和后续复用成功率，而非单独追求节点数。后续任务真正复用时，再衡量减少的实验/核验开销与正确性。

通过条件：峰区结论不能直接用于全域；一处复测不能成为“仪表永不漂移”；改变环境、仪表、材料或测量条件时能正确拒用或要求复核。至少完成一次同条件复用和一次条件变化任务后，才宣称本体复用有收益。
