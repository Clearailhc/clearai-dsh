# 主张通路修复

2026-11-07。根据[真实验收](evidence-candidate-results.md)中出现的局部问题扩大、文字事实绕过本体准入和历史版本误判，收窄修复现有内核路径。不新增工具、调度器或第二套研究状态。

## 统一的路径

`Frame 登记主张 → 现有本体准入 → 独立评估 → 证据落账 → 合格事实沉淀`。

`ReviewClaims` 与 `Conclude` 均检查本次选中主张的概念、关系、实体和断言关联。普通探索与未选中的假设不因此被强制核验。旧 steps-v1 目标保留原合同。

目标审计整体未通过，不再丢掉其中的逐主张裁决。支持、反驳和证据不足分别保留；只有完整覆盖、结构有效且评估者明确确认独立于缺口的主张，才能沿原有 promoteFacts 路径保存。影响未知、命题受影响、缺少独立性确认、范围覆盖不足、材料在审计中变化或评估不可用时，不晋升。目标继续开放。

修复交付后仍使用 Conclude；已保存的事实不重复生成，剩余主张与交付要求继续独立核验。新流程失败回执不再附带“还没建计划”的旧卡片，避免诱导主代理进入额外计划与派评流程。显式创建的旧计划仍须正常完成。

## 版本交接

立题时把有界文件摘要保存在原有 goal/set 事件中，修订不重置也不重复存储基线；投影版本升为 27，日志重放可恢复。交接只传基线摘要、边界说明和差异，不反复传输整份基线。

这是**立题时的文件状态**，不是会话开始快照，也不是内容正确性的证明。评估者看到的本目标变化与历史审计引用版本分开；不能单凭更早的审计摘要推断本目标篡改了上一份最终交付。旧日志或无法完整观察的基线保持未知。审计后的改动仍需按其影响核验，不自动继承原裁决。

## 验证范围

内核回归覆盖整体拒绝下的局部沉淀、未知影响、受影响主张、缺少独立性确认、覆盖不足、审计中改动、直接修复再结案、无重复事实、本体准入不能绕过、真实目标修订不重置基线以及冷重放。复用了既有异常、取消、信任、范围、L4 和旧流程回归。

完整安装件套件已通过：内核 796 项、宿主 38 项、客户端 195 项，及其余工程套件均无失败；发行包检查 45 项、官方 DSH schema/会话/重放契约均通过。测试没有调用付费模型；上一轮两笔未知费用仍保留，未接受预留替代计量，也未重置预算。

## 明确的边界

这次修复保证主张准入与保存路径的一致性，不把任意导出图谱自动导入平台，不按文件存在认证语义，也未建立自动的细粒度依赖证明。完整图谱覆盖、定义忠实度与真实运行成本仍需新的任务验收。立题基线不能恢复更早审计版本的原文，未提供操作系统级只读沙箱或审计后文件自动再认证。

工程回归中的“两次目标评估即可保存局部主张并最终完成”证明该路径可达，不代表真实模型一定采用它，也不等于已测得 token 或时间下降。0.6 仍为候选，未发布。
