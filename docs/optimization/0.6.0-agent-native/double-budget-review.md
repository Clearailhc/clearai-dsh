这里 output 是 API 用量口径，不等于可见回复字数；请求耗时不是精确 CPU 归因。评估轮数与请求数减少，输出和总耗时仍可增加。当前两题评估费用分别约 80.2% / 76.7% 来自输出 token。因此，仅压缩缓存上下文、仅降低触发频率或简单追加预算，都不足以解决问题。等待评估期间父任务的模型轮询次数核对为零，没有等待轮询可供消除。

拒绝并非都无价值。旧候选交互题首轮遗漏了自己登记的 quick/full 差异判据；当前候选首轮把一个配对点推广为全域“无系统偏差”，评估正确要求限制范围或补证。当前加性题两轮都为 holds=yes，但核验仍揭示了报告参数与产物不一致、抄写错误、样本内残差冒充独立验证、残差 sd 与预测 sd 混用、网格与噪声参数作用混淆、清单自哈希失效等问题。不能把检出这些问题的成本全部称为浪费。

与此同时，当前交互题首轮已经支持模型比较与内部最优两项；后续步骤核验再次独立重算同一组 full 数据的 LOO、最优点和杂质统计，最终又检查交付。材料变化可以要求重核，但当前记录尚不能证明每次都需要整组重算。已有历史交接没有替代经过验证的依赖范围。

## 下一步：小改动，保留核验标准

1. **先减少可确定发现的作者错误。** 让报告数值引用固定产物与参数版本，现有提交预检检查引用、参数一致性、清单自引用等；不要把机械一致性检查再交给昂贵的整轮独立探索。科学结论仍由独立评估核验。
2. **补齐修复后的沉淀闭环。** 保存“已支持但因未决影响暂不晋升”的状态；问题修复后对受影响的主张申请明确确认。影响未知继续阻断，目标通过不自动等于主张支持。
3. **把依赖与范围做成现有裁决凭据的一部分。** 评估者核实来源、方法、判据、范围、本体定义与信任配置；未变化且依赖完整的凭据允许复用，变化触及部分及下游必须重核，依赖未知保守扩大。最终核验聚焦覆盖缺口与交付一致性，不另建代理层，不以摘要代替证明。
4. **将评估限制写入事实及断言。** 结构化表达实测域、模型假设、噪声和未定性问题；再用同条件复用与条件变化任务验证价值，避免靠增加条目数美化成果。
