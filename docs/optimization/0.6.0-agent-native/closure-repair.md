# 从实测现象修复核验与知识沉淀闭环

2026-11-07，基于[预算翻倍对照](double-budget-review.md)。本轮是小范围工程修复，不发布 0.6，不改宿主，不引入新代理或调度器。

## 原则

核验的基本单位是“有证据、适用范围与断言约束的主张”，不是一整份报告或计划步骤。交付是否完成、某条主张是否有充分支持、知识能否长期保存，是三个不同判断。局部问题只有在独立确认其影响边界后才允许局部保存；未知依赖不能靠作者声明消除。

由此，本轮不调低评估标准、不压低模型预算、不用节点数量当成可信度，也不直接把旧 support 变成新事实。先修确定性的信息丢失和遗漏，再测运行成本。

## 对应实测的改动

1. **整包未通过，不丢局部独立成果。** `ReviewClaims` 对已落定的 no / unclear 结果分别记录主张裁决；满足原有等级、独立影响边界、实体与本体检查的支持项可以保存。证据不足或反驳另行保留。无效、未知、被取消或材料变更的审计仍不认证；复用同一拒绝不会再派评或重复落证据。
2. **修复后不漏掉待沉淀知识。** 从现有账本派生“当前目标、有效主张、最近独立结果为支持、尚无事实”的集合，加入已有最终评估的主张清单。只增加本轮明确的核验义务，不另派子代理，不强制核完无关探索。作者解释异常本身不触发晋升，必须拿到当前逐主张支持。
3. **新裁决与真实覆盖优先。** 评估结果要求 `coverage=full|narrower|unknown`，覆盖对象包括原命题、合并目标条件后的范围及本体断言。support 但覆盖不足或缺失时按 inconclusive 保存；主代理可通过既有 Frame 修订窄命题后再核验，系统不从正文猜出新事实。最终晋升不能用旧支持等级覆盖当前 inconclusive，也不能越过未决影响边界。
4. **请求与回执一致。** 官方结构化输出 schema 固定主张 ID，数量由冻结请求在内核严格校验；结算直接使用派发时冻结的请求。宿主投影延迟不再造成漏检，也不会把带请求的裁决卡错误写成旧版无覆盖信息的卡。旧卡恢复保留当时策略，不重新标成新版本。
5. **接通已有凭据，减少明显重复。** 最终交接接受仍通过原有材料、引用与信任检查的步骤评估凭据，不只接受 ReviewClaims 凭据。变更后的凭据仍只作为历史线索。历史交接不重复长篇裁决正文，保留 ID、结果、来源路径、变化和先前条件；同一次交接只构造一次来源快照。若已经准备交付且不影响中间决策，流程说明明确直接交给 Conclude，不要求紧接着做 ReviewClaims。

评估策略更新为 `clearai.review.v3`，旧缓存不会绕过新增要求。类型、工具 schema、中英文使用说明及 CHANGELOG 同步更新。新字段仍在既有审计记录内，不创建第二套权威状态，也不新增展示模型调用。

## 回归证据

针对性用例覆盖整包 no / unclear 下独立事实保存、反例及不确定性保留、幂等与重放、narrower / unknown / 缺失范围确认拒绝认证、未知影响保持暂缓、作者修复不自动晋升、结案补核待沉淀项但不扩到无关主张、新 inconclusive 不被旧支持盖过、漏判阻止结案，以及步骤凭据在材料变更前后的可信级别。原有取消、迟到结果、冷恢复、完整性与本体回归继续运行。

完整安装件回归通过：87 项 Node 测试、773 项内核检查、38 项宿主检查、193 项客户端检查，以及领域语言、本体、生命周期/状态机、文档、长测和其他既有套件全部通过；发行包检查 45 项通过。第一轮完整回归发现旧测试回执缺少新增 coverage 字段及尚未写入的文档链接，修正测试协议样本、补齐文档并增加缺失 coverage 反例后，全套复跑通过，没有跳过失败项。

新构建使用官方 DSH `0.2.2-rc.1` 安装到独立临时 profile，安装包 SHA-256 为 `a64e472069ea437e75b469cd45cf2e13c4b42fce39b2500aaab0554f19f98211`。原付费对照的冻结安装与结果保持不变。本轮未启动付费模型测试，没有新增 API 支出。

## 实际边界

这不是完整的按依赖增量缓存。普通文件变化仍会保守失效，只有经过独立核验且依赖完整的凭据，未来才应允许自动缩小重验范围。新 coverage 字段能够阻止结构化的“范围不足但仍支持”晋升，不能机械证明评估者的科学判断一定正确。

不把工程测试通过解释成 token、耗时或费用下降。下一轮真实验收应检查：直接结案是否减少一次核验；局部失败能否即时保存不受影响的事实；修复后是否在同一次最终评估完成沉淀；事实范围是否准确；同条件复用与条件变化是否分别复用、拒用。付费预算仍沿用已授权账本，不重置历史支出。


后续真实追溯任务发现 DSH 输出 schema 不支持 minItems/maxItems，第一次 ClearAI 首轮评估无法派发。该失败保留，不能以当时工程全绿代替真实验收。适配层现将数量约束转为说明，逐主张完整性仍由内核执行；测试的所有评估派发另用已安装官方 DSH 校验器检查，原生契约测试包含此反例。修复后的效果由新运行单独报告。
