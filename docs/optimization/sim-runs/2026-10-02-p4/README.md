## 发现

1. **结案的摩擦没了。** 第三阶段证伪那一场 Conclude 被拦四次(跳级理由 → 断言形态两次 → 实体落图),这次四场的 Conclude 全部一次过。
   拦人的那几样已经不在门上:跳级机制整个删了，断言形态降成缺口(`prose_only_claims`),实体门只管带断言、将要升格的判断。
2. **为什么加跑一场证伪。** 第一场证伪的扮演模型把观测步按 L2 申报、自己给了结果，没有判断走到升格门槛，实体门根本没被考到,
   这个读数不能和第三阶段直接比。第二场照第三阶段的走法把观测步定为 L3:带 `results` 交付被拒一次(「L3 的裁决只能由评估者写」,
   这是第三阶段就有的规则),去掉后由评估者判 h-ok 支持、h-no 推翻,结案时 h-ok 升格成事实。这正是第三阶段被拦四次的那条路,
   这次 Conclude 一次过、全场 7 次调用(第三阶段 17 次)。
3. **实体门在这四场里没有触发。** 升格的两条判断(证伪第二场的 h-ok、长链的 h-8lu0kp)都是纯文字判断，没有断言，所以实体门不管。
   这是设计内的:断言是可选的，写了主体才要落图。门本身的拦与放由 `test/kernel.test.mjs` 的实体门那组用例覆盖
   (拦在派评估之前、`RegisterInstance` 一次就放行、不必再 `Assert`)。这次的模型都没有主动写断言，也没有调用 `Define` / `RegisterInstance` / `Assert`。
4. **合并后的计划工具用上了。** 长链那一场环境里没有 numpy / pandas,模型用两次 `RevisePlan`(`action: "refine"`)改了前两步的判据,
   一次过，旧判据和原因留在账上。
5. **长链这次结案了。** 任务书与第三阶段相同，第三阶段的模型照「到 ClosePlan 为止」没有结案，这次的模型结了案(评估者判两条判据都满足),
   调用多出的 3 次就是两次 `RevisePlan` 和 `Conclude`。这是扮演模型的取舍不同，不是机制的变化。
6. **一处措辞值得留意。** 长链升格的事实沿用了假设原话里的「pandas 路径」,而实际走的是标准库 `csv`。模型在答复里提醒了人,
   事实文件归系统所有、模型改不了;撤回或保留由人在面板上决定。升格照抄假设原文是既有行为，这次没有改动。
