## 对照设计

1. **本体写成文件:成立。** 两场都没有调已删的本体工具,153 次写文件全部一次过写时校验——`SCHEMA.json` 里的字段与例子足够模型照着写。
2. **读时只标不拦:成立,而且确实需要。** 模型先写实体、后补概念时,跨文件引用会暂时指空,卡上依次标出 1 → 9 处问题,
   写完都归零。如果写时就查跨文件,这些写入都会被拒。
3. **目录嵌套表达上下位:概念用上了,实体几乎没用。** 两场概念都长到两层;实体的「组成」只用了一次(V-JEPA 2-AC 放在 V-JEPA 2 下)。
4. **事实写成文件:成立。** 升格的 6 条都落成了 `f-*.json` 并渲染进 `INDEX.md`。
5. **事实没有挂到本体上。** 两场登记的 18 条判断一条都没带结构化断言,所以事实文件的 `assertions` 与 `definitions` 都是空的:
   「定义已变」的检测在真跑里无从触发,本体与事实是两张互不引用的表。设计没有强制,模型也就不做。
6. **写技能的提醒:没有被采纳。** 两场结案回执都提醒了写 `.agents/skills/`,两位模型都没写。
7. **跨会话:这两场没有测到**(各自一个新工作区)。由 `test/kernel.test.mjs` 的跨会话用例覆盖。
