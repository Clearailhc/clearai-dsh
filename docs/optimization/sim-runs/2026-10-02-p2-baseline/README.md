# 第二阶段基线 · 模拟宿主 + Claude(2026-10-02)

**代码**:第二阶段之后(20 件工具、21 段提示词;PR #9 的头)。
**怎么跑**:`tools/sim/`——真内核装进模拟宿主;模型由一个 Claude 子代理扮演,只拿到 ClearAI 的提示词段、工具目录与剧本任务书;
独立评估者由另一个只读的 Claude 子代理扮演;计划审阅按缺省答案批准;判分用长测同一个判官(`evaluateLog`)。
**每场的东西**:`events.jsonl`(会话日志,可用 `node tools/sim/judge.mjs` 重判)、`result.json`、`final-reply.md`(模型最后的答复)、
`evaluator-*.md`(评估者拿到的任务)、`lab/`(模型留在工作区的产物)。路径里的临时目录换成了 `<sim>`。

## 发现

1. **推翻的那一步收不了尾(机制缺陷,两场独立撞上)。** `AdvancePlan` 只有在 verdict 是 `support` 时才推进这一步
   (`preset/plugins/clearai-kernel.js` 的 ⑦);交付 `refute` 会记下证据,但这一步一直停在 open。
   竞争路线与证伪两场里,输的那条路线本来就该被推翻——这一步的工作做完了,判据也满足了,可它只能带因作废。
   账面上它显示为「作废」而不是「完成」;证伪那一场里,模型还先试了 RefinePlan 改判据,没用。
   这与已确认的方案 A(竞争路线 = 竞争假设,各由一个步骤检验)直接冲突:**「这一步做完了没有」和「它检验的假设成不成立」被混成了一件事。**
2. **跳级门在结案时拦了两次。** 竞争路线与证伪两场的第一次 CloseGoal 都因为「跳过 L0/L1 没写理由」被拦下,补 ExplainLevelSkip 后才通过。
   两场都是直接实测的小任务,补的理由都是「这个数只能实测」。方案第四阶段本来就要删掉跳级理由这一整套,这是支持那条决定的证据。
3. **小任务上,知识模式的压力偏大。** 长链那一场,运行态卡一直挂着 4 条缺口(假设只有散文、没有概念与断言);模型判断这么小的任务不值得立词,
   没有结案,把决定留给人,并倾向按 abandoned 结。第四阶段把缺口从 7 种收到 3 种、关口从 3 道收到 1 道,方向一致;是否还要放宽,第四阶段再看真跑。
4. **没有升格。** 三场的步都是 L2,默认升格门槛是 L3,所以都没有新增事实。这是设计行为,不是缺陷。
5. **并行没测到。** 模拟环境没有原生子任务,竞争路线那一场的两条路线是在同一个 Bash 命令里一起跑的。产物路径互斥那条规则照常生效(没有撞路径)。

## 测试台本身

- 评估者三次都给出了结构化裁决,并用 settle 交回;其中一位用 `cat` 读文件(只读,不碰工作区,但不是读文件工具)。
- 模型的子代理也带着 Claude Code 自己的系统提示词,ClearAI 的提示词是作为任务书交给它的,不是真正的系统提示词。
