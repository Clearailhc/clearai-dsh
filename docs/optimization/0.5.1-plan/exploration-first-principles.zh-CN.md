# 探索的第一性原理:本体与认识论到底该帮什么

2026-10-08 定稿,随 0.5.1 实现。接 [exploration-depth.zh-CN.md](../0.5-plan/exploration-depth.zh-CN.md) 的暂缓草稿,往下再挖一层。

## 一句话

**科学探索、工艺优化、问题定位是同一件事:在有限的实验预算里,把「关于这个系统,哪些解释还在考察」缩小到不会再改变决策为止。** 本体的用处是把「可能的解释」列全(生成假设空间),认识论的用处是保证每一次排除都真的发生过(检验够得着、数据可信)。算力该花在这两件人做起来又贵又容易漏的事上,而不是写更多的说明文字。

## 三类任务其实是一个结构

| | 科学探索 | 工艺优化 | 问题定位 |
|---|---|---|---|
| 要做的决策 | 信哪个机理、下一篇写什么 | 定哪个配方 | 修哪个部件 |
| 系统里藏着的 | 机理 | 响应面的形状(单调、峰、耦合)+ 装置是否可信 | 哪个部件坏了 + 哪个读数在骗人 |
| 一次实验的价值 | 能区分两个机理 | 能区分「可加」和「耦合」、「真变化」和「漂移」 | 能把候选原因劈成两半 |
| 什么时候停 | 剩下的机理不影响结论 | 剩下的结构不会让配方变 | 剩下的候选指向同一个修法 |

共同点:**价值 = 决策质量 / 花的预算;可信 = 说得清还有哪些可能没排除。**

## 专家到底比新手多了什么(这次说得更准)

上一版计划里写的是「预期、分类、经验」。现场序列跑完后看得更清楚:我们补上了「预期落空不能解释过去」,它管住了**坏数据**;但专家还有两样我们没给:

1. **一张「可能是什么」的清单。** 老工程师看到收率不随温度单调,脑子里同时冒出三个解释:有峰、和另一个量耦合、温度计不准。新手(和 LLM)只拿一个最顺的解释往下走。这张清单不是灵感,是从他对「这类系统通常有哪些结构」的认识里**枚举**出来的,这正是本体该装的东西。
2. **挑能把它们分开的那次实验。** 专家不会再在中心点做第五次重复,而是去做「两个量一起动」那一次,因为只有这一次,不同的解释给出不同的预测。

现场序列里的证据:耦合的信号(交互 −29)其实出现了,模型把它记成「说不清」;它手上**只有一个解释**,于是没有理由去做那次区分实验,预算花在了确认上(一个序列 9 次重复)。

## 由此推出的探索方式

五步,前四步每一轮都转:

1. **先说决策。** 这次要决定什么(配方、修哪里、信哪个结论),什么样的差别会让决策变。没有决策,就无从判断哪个不确定性值得花预算。
2. **从本体枚举考察中的解释。** 不靠模型凭空想对手(上一版的对手判断 8 组用了 0 次,就是因为要凭空想)。本体里每个涉及的量都带着「这类东西常见的结构」:影响关系的形状(单调 / 有峰 / 阈值 / 耦合),测量关系的已知毛病(会漂、有滞后)。把这些槽位对着这次的因素展开,就是一张清单:哪几对因素的耦合还没测过,哪几个读数还没核过。
3. **每个解释各写一个预期。** 「若可加,对角点收率约 A;若耦合,约 B」。两边预期一样的实验,不管做多少次都不区分任何东西,这一眼就能看出来,不需要额外的提示。
4. **做最能分开它们的那次实验,然后排除。** 被数据推翻的解释划掉,原因写清;算力用在这里:模型可以写个小脚本,把几种结构分别拟合到已有数据上,算出下一个点在哪里分歧最大。这是 LLM 比人便宜得多的地方。
5. **停在决策不再变的地方,结论只说排除过的范围。** 「在 {可加, T×cat 耦合, 漂移} 里,前两个已排除、漂移已纠正;P×t 没测」。独立评估者核两件事:每次排除的数据够不够得着;清单外有没有一个明显该在清单里的解释(来自本体或未解释项)。

结案后写回:被检验过的关系,检验程度升级;经验写的是「这类系统里哪些解释常常是真的」,也就是下一次清单的排序。这就是越做越快的来源:**清单越来越准,区分实验越来越少。**

## 算力换人力,换的是哪一部分

| 人做起来贵、容易漏的 | 交给算力 |
|---|---|
| 同时记住五六个解释并逐一推预测 | 从本体枚举,每个解释写预期 |
| 算哪个实验最能区分 | 拟合几种结构、算分歧最大的点 |
| 回头怀疑数据本身 | 独立评估者在副本里复跑、查未解释项 |
| 跨项目记住踩过的坑 | 经验库,在决策点推到眼前 |

留给人的:定决策和代价(什么算「够好」),放行不可逆的动作,拍板撤回旧知识,以及提供本体里还没有的新机理。

判断「换到了没有」的指标不是得分本身,而是:**同样可信的结论,要花多少次实验、多少次人工返工。**

## 和现在的 ClearAI 差在哪,改动多大

| 已有 | 要改 |
|---|---|
| 判断带推翻条件 | 判断可以成组:同一个问题的几个解释放在一起,对着同一个决策 |
| 步骤带一个预期 | 预期可以按解释分开写;各解释预期相同的步骤,卡上标出「这一步区分不了」 |
| 本体关系的 shape、测量的 check | 卡上把「这次涉及的因素里还没检验过的结构」列出来,作为待排除的解释 |
| 结案的独立评估 | 多核:排除是否够得着;清单外是否漏了明显的解释 |
| 经验 | 多写一类:这类系统里哪些结构常是真的(用来排序清单) |

没有新工具,也没有新门,**也不强制写对手**(10-03 你担心的「为了竞争而竞争」):清单是系统从本体里展开、摆到卡上的,模型可以写一句理由把某一项排除,不用为它编一个假设。最大的风险是:模型仍然不展开清单。所以这一版要先用最小的代价验证一件事:**清单摆到卡上以后,模型会不会去做区分实验。**

## 要你先定的

1. **这个框架对吗?** 三类任务都是「在预算里排除解释直到决策不变」,本体负责列出解释,认识论负责保证排除是真的。
2. **第一步验证放在哪?** 我的建议是先做最小的那一刀:只加「卡上列出未检验的结构 + 按解释分开的预期」,在现场序列上看区分实验有没有出现。区分实验出现了,再做完整的五步。
3. **验证题要不要换一批?** 现在的现场题都藏了耦合,只在它上面调,容易调成「针对这道题的规则」。建议同时加一道问题定位题(候选原因 + 一个会骗人的读数),看同一套方式能不能迁移。

## 让人看得见:界面、卡片与提示词(2026-10-08 追加)

你定了框架,并要求这个「分叉 → 排除 → 收敛」的过程在界面、卡片、提示词上都凸显出来:人随时知道现在在哪、下一步 agent 要做什么,结案时只看到干净的结论,而不是一堆中间判断。

### 原则

1. **一个主轴:问题与它的解释。** 现在界面的主轴是「判断列表 + 计划步骤」,人要自己拼出「我们在回答什么、还剩什么没排除」。改成以**问题**为轴:每个问题下挂着几个解释,每个解释只有三种状态:考察中、已排除(被哪次实验)、采纳。判断、证据、步骤都退到这条轴的下面。
2. **人和模型看同一张图。** 卡片(模型每一步读的)与面板(人看的)用同一套结构和同一套词。人看到的「下一步」就是模型卡上的「下一步」,不另写一份。
3. **结论只说决策需要的。** 结案只给四块:答案、为什么可信(排除了什么)、还没排除的、要你定的。中间判断全部收进「过程」,默认折叠。

下面的样稿用现场序列 C 线做例子,数字是示意,不是实测。

### 进行中:人看到的(对话页顶部一条带,和「本体」页签的第一屏)

```
问题 1/2 · 定配方(杂质 < 0.2%,预算 18 / 30)
  解释                         状态
  ● 收率只随温度单调          已排除 · 第 9 次(140 °C 收率反降)
  ● 温度与 cat 沿斜脊耦合      考察中 · 交互 −29,没拆
  ● 有内部峰,可加            考察中
  ● 温度计漂移                已采纳 · T_ref 偏低 8 °C,配方按实际温度写
下一步 · 对角点 T−8 / cat+0.3
  若耦合 → 收率约 93;若可加 → 约 88。这一次能把剩下两个分开。
⚠ 1 条可能推翻结论的未解释项
```

- 「问题 1/2」告诉人在哪;解释表是分叉;「下一步」带着各解释的预期,所以人看得懂 agent 为什么选这一步,也能在它动手前插话。
- 解释不是模型凭空写的:本体里涉及的量带着的结构(耦合、峰、测量会漂)由系统展开成候选,模型采纳成解释,或写一句理由划掉。划掉的也留在表里,灰显。
- 底部工具行那颗计划 chip(现在是 `8/8`)改成 `问题 1/2 · 剩 2 个解释`,点开就是这张表。

### 模型卡(每一步都读)

和上面同构,多两行只给模型的:

```
问题 q1 定配方 · 预算 18/30
考察中:h-coupled(T×cat 耦合)、h-peak(内部峰)
已排除:h-mono(第 9 次)    已采纳:h-drift
本体里还没成为解释的结构:P×t 耦合(没测、没划掉)
下一步 s5 的预期:按 h-coupled 93,按 h-peak 88 → 能区分
(若下一步各解释预期相同:这一步区分不了,先说明为什么还要做)
```

### 结案:人看到的结论(对话里的最后答复 = 面板「结论」页的第一屏)

```
答案
  配方 T 142 °C(实际)/ P 6 / cat 1.75 / t 90,收率 92.5 ± 0.6,杂质 ≤ 0.13
为什么可信
  · 温度计漂移已纠正:5 个 T_ref 读数一致偏低 8 °C,配方按实际温度写
  · 「T 与 cat 耦合」已检验:对角点收率 93.1,优于单因素最优 → 采纳
  · 独立评估者复跑了收率与杂质,数字对得上
还没排除的(会改变答案的才列)
  · P×t 耦合没测;若存在,收率可能再高 1–2 个点
要你定的
  · 装置修好后,先在 142 °C 复测一次再放大
过程(14 条判断、30 次实验)▸
```

- 「为什么可信」每一行对应一个被排除或被采纳的解释,不列中间判断。
- 「还没排除的」只列会改变答案的;不会改变答案的不写(这就是不堆砌的标准)。
- 提示词要求最后答复照这四块写;面板的「结论」页同一结构,由状态算出来,不依赖模型怎么写。
- 现在的结论列表(待核验 4、不确定 1、已推翻 2……)整体搬进「过程」。

### 要动的地方

| 层 | 改动 |
|---|---|
| 状态 | 新增「问题」与「解释」两级:Frame 的判断可以挂在一个问题下(问题带决策和预算);解释的三种状态由证据算出 |
| 本体 | 关系的 `shape`、测量的 `check` 用来展开候选结构;不新增字段 |
| 模型卡 | 按上面的格式重排;旧的判断列表缩成一行计数 |
| 面板 | 对话顶部一条带;计划 chip 改说问题与剩几个解释;「本体」页第一屏换成问题表与结论四块,图与判断列表下移 |
| 提示词 | 最后答复固定四块;「下一步」必须说它区分哪两个解释 |

### 要你再定的

1. **问题要不要显式立?** 建议要:Frame 时写 1–3 个问题(每个对着一个决策),比让系统从判断里猜更清楚。
2. **结论四块的名字**(答案 / 为什么可信 / 还没排除的 / 要你定的)合不合你的口味?
3. 要不要我先做一个**可点的界面样稿**(进行中与结案两屏),你看着改,再动代码?
