# 真宿主第一对(DeepSeek)复盘与开发计划调整

2026-10-08。材料:用户上传的 `clearai-vs-bare-pair1-2026-10-08.zip`(ClearAI 0.5.0 对裸模型,同宿主 DSH 0.2.0-rc.2,模型 deepseek-flash,反应器题,40 次预算)。本文只写复核后的判断与对开发计划的修改建议。

## 一、结论

用户的判断基本成立,需要分开说:

- **本体:确实没有用上。** 全场 0 个本体条目,3 条升格事实均无断言。这不是模型偶然疏忽,而是我们的设计让它很容易被跳过(原因见第二节)。
- **认识论:用上了一半。** 未解释项这一层工作得很好:漂移被独立探头量化(151.9 / 152.1 / 161.9),甚至对一条已升格的事实登记了读法警告(`u-uixxap`:「T_controller 只是设定值回读,不是釜内温度」)。但这些读数**没有进入结论**:推荐配方、重复实测、中试条件都仍按设定温度 170 °C 表述,而系统允许它以 `achieved` 结案。
- **代价:** 独立裁决 9 次,约 60 万 token,占全场 64%,没有改变任何一个交付数字。

## 二、复核到的具体原因(均可在会话日志中查到)

1. **提示词自相矛盾。** `preset/plugins/prompts.js:24` 写「`clear/` 归系统,你不直接写」,而第 57 行要求在 `clear/ontology/` 下写本体文件。能力较弱的模型会服从前一条更硬的禁令。
2. **本体被放在循环末尾。** 循环写作「……→ 带范围的结论 → 长进本体」。模型照此把本体写入安排在最后一步(计划 s8:「同时把本体的度量与关系补进 clear/ontology/」),最终没有执行。本体因此从未成为预测和候选假设的来源,所有 `expect` 都来自直觉。
3. **提醒无效。** 「先在 clear/ontology/ 下写概念……」在卡片上出现 52 次,模型均未响应。重复提醒不能替代结构。
4. **测量关系缺失直接导致了错误事实。** Frame 中的假设「温控读数一致:T_controller 等于设定温度」被支持并升格,但 T_controller 是回读字段,不测釜温。如果本体里有一条「测量」关系(哪个仪表测哪个量、如何核对),这条事实就不会被当作釜温成立。这正是本体本该发挥作用的地方。
5. **未解释项没有出口。** 内核在 Conclude 时不检查开着的未解释项是否涉及答案中的变量(`preset/plugins/clearai-kernel.js:2694` 起的 Conclude 实现中没有针对未解释项的检查)。三条与温度相关的未解释项「随结案交出」,答案本身没有改写。
6. **针对已升格事实的未解释项不影响该事实。** `u-uixxap` 登记后,那条事实的状态没有变化。

## 三、对开发计划的修改建议

探索货架的方向不变(候选假设由本体列出,探索直到决策稳健)。上述问题正是探索货架要解决的问题,但必须先补内核这一层,否则界面只是把空本体展示得更清楚。建议把以下五项作为探索货架实现的第一步:

| # | 修改 | 是否增加强制门槛 |
|---|---|---|
| 1 | 删除提示词矛盾;循环改写为「问题 → 本体(相关的量如何测量、如何相互影响)→ 候选假设与预测 → 检验 → 结论」 | 否 |
| 2 | Frame 直接接收本体条目(度量及其测量方式、影响关系及其形状),由内核写入文件;不再要求模型另行写文件 | 否,只是把写本体变成立题的一部分,成本降到一次工具调用 |
| 3 | 未解释项登记时注明涉及的变量或候选假设;Conclude 做一项入账检查:涉及答案变量的开着的未解释项,必须在结论的「尚未确定的事项」中写明它对答案的影响,或答案已按它改写。只检查是否写了,不判断写得对不对 | 是,属于入账检查,与现有「产物存在且格式正确」同类 |
| 4 | 指向某条已升格事实的未解释项,使该事实回到「待核验」 | 否,状态由系统按证据计算 |
| 5 | 独立裁决只用于升格与结案,并只核对答案所依赖的判断;逐步裁决改为可选 | 否,目标是把裁决 token 降到当前的一半以下 |

第 2 项涉及一个需要用户决定的问题:立题时是否**要求**列出答案所涉及各量的测量方式(没有就不能立题),还是只允许、不要求。建议要求,理由是本场唯一的错误事实恰好来自缺失的测量关系,而 52 次提醒已证明「允许」不够。这与「不为竞争而竞争」不冲突:它要求的是说清楚测量,不是凭空编造对手假设。

## 四、对测试方法的修改

同意报告中的四条下一步,另补两条:

- (已撤回:用户决定测试只用 Sonnet 5.5,不设第二个测试模型。)
- **无人值守时给人工审批设一个应答脚本**(固定按「批准」或「拒绝」应答,两臂一致),使中试一项可比较。产品中的人工审批门槛保持不变。

评分口径按报告建议改为:纠正 = 1;发现但未纠正 = 0.5;未发现且结论不受影响 = 0.5;被误导 = 0。温度按实际温度还是设定温度计算,写入答案键,两臂一致。
