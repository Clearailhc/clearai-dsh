# ClearAI 0.5.1 升级与测试计划

2026-10-08 定稿,随 0.5.1 实现。综合三份材料:[探索的第一性原理](exploration-first-principles.zh-CN.md)、[探索货架设计](explore-shelf-design.zh-CN.md)(界面已定稿,用语见 [ui-wording.md](ui-wording.zh-CN.md))、[真宿主第一对复盘](pair1-review.zh-CN.md)(仅作参考,用于补全逻辑)。

## 一、目标

让本体与认识论**在每一次决策中实际起作用**,并且让用户随时看清:当前在回答什么问题、还有哪些可能未被排除、下一步做什么、最终结论凭什么成立。

0.5 已证明的只有一项:对反常的纪律(漂移纠正 3/4 对 1/4)。尚未证明的有三项,也是本次升级要解决的:

1. **本体没有成为推理的来源。** 本体条目常常为零或只在结尾补写,预测大多来自直觉。
2. **反常没有出口。** 未解释项登记得很准,但不影响结论,开着也能以 `achieved` 结案。
3. **探索浅。** 配方普遍停在单因素水平,因为没有机制要求「把会改变决策的可能都排除掉才停」。

外加一项成本问题:独立裁决逐步进行,token 占比过高,却很少改变交付数字。

## 二、核心逻辑(一句话)

**立题时先写清相关的量如何测量、如何相互影响(本体);本体给出每个问题的候选假设与各自的预测;每一步选能区分候选的检验;反常要么被解释、要么排除、要么写进结论的影响;所有会改变答案的候选都已处理,才可以结案。**

这条逻辑同时覆盖两种工作方式:

- **定向求解**(问题定位、工艺优化、识别关键问题、估计优化空间):课题 → 问题 → 候选假设 → 步骤。
- **广度调研**(行业调研、入门学习、发展脉络):课题 → 调研板块 → 新发现的问题(可立为问题,转入定向求解)。

## 三、升级内容

所有新增字段均为可选或有默认值,旧会话照常读取(旧会话没有问题,就把整个目标当作一个问题显示)。状态版本 `STATE_VERSION` 18 → 19。

### A. 提示词与循环

- 删除「`clear/` 归系统,你不直接写」与本体写入要求之间的矛盾(`preset/plugins/prompts.js:24`)。本体改由工具写入后,这句改为「`clear/` 由系统通过工具维护」。
- 循环改写为:问题 → 本体(量如何测量、如何相互影响)→ 候选假设与预测 → 区分性检验 → 证据 → 结论 → 经验。本体从末尾移到开头。
- 立题时说明工作方式(广度调研 / 定向求解 / 先调研后求解);最后答复按结论四部分写。
- 删去卡片上重复出现、但从未起作用的本体提醒(「先在 clear/ontology/ 下写概念……」),由下面的结构替代。

### B. 立题与本体(Frame)

- **Frame 直接接收本体条目**:`ontology.concepts`(类别 / 度量 / 现象,度量带口径与单位)与 `ontology.relations`(「影响」带形状,「测量」带仪表与核对方式)。由内核按现有 SCHEMA 校验并写入 `clear/ontology/`。模型仍可直接编辑这些文件,但不再必须。
- **答案涉及的每个量,必须写明由什么测量、如何核对**(一条「测量」关系)。缺失时 Frame 拒绝并列出缺哪些量。这是本次唯一新增的立题要求,依据是:复盘中唯一的错误事实,正是把设定值回读当成了釜温。如您决定改为「允许但不要求」,这里退化为卡片提示。
- 新增可选字段:`mode`(调研 / 求解)、`areas`(调研板块)、`questions`(问题,每个带一句「怎样算回答了」)。不写 `questions` 时,整个目标就是唯一的问题。

### C. 候选假设与预测

- 判断(hypotheses)新增 `question`(属于哪个问题)与 `from`(由本体中哪条关系提出;没有就写「直觉」)。界面上判断即「候选假设」。
- 卡片在当前问题下列出:考察中的候选、本体中**已有但尚未成为候选**的结构(例如有一条「耦合」关系,却没有任何候选覆盖它)。只列出,不强制。
- 计划步骤新增 `serves`(服务哪个问题或板块)。`expect` 改为**按候选分别写预测**;若某一步对所有考察中的候选预测相同,卡片提示「这一步无法区分候选」。
- 候选状态由证据算出:考察中 / 已排除 / 已采纳;「暂不考察」需写理由。

### D. 反常的出口

- 未解释项新增 `touches`:涉及哪些量、候选或事实。
- **指向某条已升格事实的未解释项,使该事实回到「待核验」**,直到该项被解释或排除。
- 未解释项若涉及答案中的量,视为一个**会改变答案的候选**,与 E 的停止条件一并处理。

### E. 停止条件:决策稳健

Conclude 时内核做一项入账检查(只检查是否写了,不判断写得对不对,与现有「产物存在且格式正确」同类):

- 每个问题都给出了结论,或明确写为「未回答」并说明原因。
- 每个仍在考察中的候选、每个涉及答案的开着的未解释项,都出现在该问题的「尚未确定的事项」中,并写明**若它成立,答案会如何改变**。
- 不满足时返回缺项清单,不允许以 `achieved` 结案;可以改为 `partial`。

这一条把「探索到决策不再改变为止」落到可检查的形式上,也直接覆盖了复盘中「看见了漂移但配方仍按设定温度交付」的情形。

### F. 结论四部分

- Conclude 新增按问题填写的 `answers`:结论 / 依据(每个已排除、已采纳的候选一行,注明对应的实验或来源)/ 尚未确定的事项 / 待您决策。
- 本体货架的「结论」按问题显示四部分卡片;对话中的最后答复与卡片同形。中间判断、评估记录、步骤列表不进入结论,只在探索货架中查看。
- 调研型的四部分:概要与各板块一句话 / 各板块核实了几条、依据哪些来源 / 未厘清的板块与暂缓的问题 / 值得另立课题深入的问题。

### G. 独立裁决的范围

- 独立裁决只在两处进行:**事实升格**与**结案**;核对范围限于答案所依赖的判断与 E 中列出的项目。逐步裁决改为模型可选(L3 步骤仍可请求)。
- 目标:裁决 token 降到当前的一半以下,且不减少「错而自信」的拦截。

### H. 界面

按定稿样稿实现([画布](https://claude.ai/artifact/87EQpHTsP2WpRqLDGK6oBc)):

- 新增「探索」货架(`conversation.view`,紧挨「本体」):当前进度一行(课题、阶段、当前问题、预算)、待您处理、问题与候选假设(或调研板块与新发现的问题)、下一步(含各候选的预测)、过程记录(步骤、判断、评估、未解释现象,默认折叠)。
- 右栏「世界树」撤销,内容并入探索货架;计划 chip 改为打开探索货架,显示「问题 1/2 · 待检验假设 2 个」或「板块 3/6 · 1 个问题待您决定」。
- 「本体」货架瘦身:本体图、实体图、已确立的事实、经验、各问题的结论卡;判断列表与进度条移到探索货架。
- 「立为问题 / 暂缓」两个按钮向模型发送一句话,由模型用一次 Frame 修订落账;界面本身不写状态。其余板块与问题只由模型写,用户通过对话补充。
- 全部界面文字按 [ui-wording.md](ui-wording.zh-CN.md) 替换;模型侧卡片、工具说明与校验报错按同一原则改写。

### I. 删除或收缩

- 卡片上的本体重复提醒(由 B 取代)。
- 逐步强制的独立裁决(由 G 取代)。
- 右栏世界树页签与相关的「点一下开右栏」文案。

## 五、测试计划

所有长测的模型、独立评估者与裸模型对照均使用 **Sonnet 5.5,思考强度中等**。

### 1. 开发集(决定是否继续)

| 任务 | 类型 | 主要检验 | 每组次数 |
|---|---|---|---|
| 反应器配方(`lh-reactor`) | 定向求解 · 优化 | 漂移纠正、是否找到温度与催化剂耦合的斜脊 | 4 + 4 |
| 电解液寿命(`lh-cell`) | 定向求解 · 优化 | 快测外推的陷阱、配比耦合 | 4 + 4 |
| 良率归因三连(`lh-factory-1/2/3`) | 定向求解 · 定位 | 归因是否正确、「定义已变」是否触发 | 2 + 2 序列 |
| 固态电池调研(`lh-battery`) | 广度调研 | 板块覆盖、宣称核实、新发现问题的处理 | 2 + 2 |

对照组为裸模型(同任务书、同预算)。系统问人时由剧本应答(中试默认「批准」,另跑一组「不批准」),两组一致。

**评分口径先修两处,再开跑:**

- 漂移项:纠正 = 1;发现但未纠正 = 0.5;未发现且结论不受影响 = 0.5;被误导 = 0。
- 温度一律按实际温度代入真值函数,写入答案键。

**机制指标(从账本机算,不采信模型自述):**

- 本体非空,且答案涉及的每个量都有「测量」关系:≥ 90% 的 ClearAI 运行。
- 预测注明了本体来源(非「直觉」)的步骤比例。
- 涉及答案的开着的未解释项被「静默结案」:0 次。
- 指向已升格事实的未解释项使该事实回到「待核验」:每次都发生。
- 各候选预测相同的步骤所占比例(越低越好)。

**止损线(任一不满足就停下重新设计,不进入正式验证):**

- 机制指标中前三项全部达到。
- 反应器题:漂移纠正 ≥ 3/4,且配方真值均值不低于裸模型。
- 至少一道定向求解题,有 ≥ 2/4 次找到耦合结构(斜脊或配比),而 0.5 在这两题上为 0/8。
- 成本:含独立评估的总 token ≤ 裸模型的 2.5 倍。

### 2. 正式验证(开发集通过后)

沿用 0.5 计划中尚未执行的正式验证,规模按实际可行收缩:

- **预注册**:开跑前把假设、指标、答案键、样本量、统计方法提交到仓库,跑完不改。
- **题目隔离**:由一个不看 ClearAI 代码的代理另出新题,覆盖定位、优化、调研三类各一题,另加两道简单题(检验不劣)。题目与答案开跑前封存。
- **对照组**:裸模型、裸模型加笔记(自己读写 notes.md)、ClearAI;同模型、同预算、同时间上限。
- **样本量**:每组每题 6 次,顺序随机。
- **评分**:能机算的机算;需要判断的部分由两位盲评者独立评分,交付物去掉 ClearAI 术语,报告一致性,分歧由第三位裁定。
- **统计**:按题配对,报告均值差与 95% bootstrap 置信区间;简单题用非劣效检验(界限事先定)。
- **消融**(正式验证通过后再做):去掉 B 的测量要求、去掉 E 的停止检查、去掉独立裁决。去掉后不掉分的机制,按奥卡姆删除。

### 3. 发布

正式验证的预注册假设成立,即发布有效性声明,并把记录写进 `docs/cases/`;不成立,如实记录,不发布有效性声明。
