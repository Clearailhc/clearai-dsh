# 探索货架与整体体验设计

2026-10-08 定稿,随 0.5.1 实现。上接 [exploration-first-principles.md](exploration-first-principles.zh-CN.md)。

界面用语以 [ui-wording.md](ui-wording.zh-CN.md) 为准(本文的「铺开 / 收敛」在界面上叫「广度调研 / 定向求解」,「版块」叫「调研板块」,「追 / 先放着」叫「立为问题 / 暂缓」,结论四部分叫「结论 / 依据 / 尚未确定的事项 / 待您决策」)。

## 结论

- **不推翻现有的东西。** 目标、判断、计划、步骤、独立评估、事实、经验、本体文件,全部照旧;新增的只有两样:**问题**(可以一开始没有,边做边冒出来)和**候选**(一个问题下的几种可能答案或解释)。
- **一个新货架「探索」,放在「本体」旁边,取代右栏的世界树。** 探索货架看「过程」:我们在回答什么、走到哪、下一步做什么、为什么。本体货架只留「结果」:本体图、实体图、已确立的知识、经验、各问题的结论。
- **所有场景用同一棵树:课题 → 问题 → 候选 → 步骤。** 不同场景只是树长得不一样:调研类先长「版图」再冒出问题,定位和优化类一开始就有问题和候选。
- **结论四块**,所有场景同一个形状:结论 / 凭什么 / 还不确定的 / 要你定的。中间判断全部留在探索货架,不进结论。
- 「活着」改成**考察中**。

## 先想清楚:人会拿它来做什么

| 场景 | 例子 | 一开始有没有核心问题 | 想要的结果 | 树长什么样 |
|---|---|---|---|---|
| 扫盲 / 行业调研 | 某个行业的工艺、玩家、痛点 | 没有 | 一张能信的版图 + 值得追的问题 | 先铺版块(工艺、玩家、成本……),每块摸清;痛点作为「冒出来的问题」挂上去 |
| 发展脉络 | LLM 是怎么走到今天的 | 没有,或很宽 | 时间线 + 几个关键转折及其原因 | 版块是阶段;每个转折是一个问题,候选是几种说法(算力、数据、架构……) |
| 找真问题 | 世界模型现在真正卡在哪 | 有一个宽问题 | 少数几个被证据撑住的「真问题」,以及被推翻的伪问题 | 宽问题下先列候选(各家说法),逐个检验;被推翻的保留并写明理由 |
| 定位瓶颈 | 某道工艺的瓶颈在哪 | 有 | 一个被证实的原因 + 怎么修 | 候选原因列全(含「读数在骗人」),每一步把候选劈开 |
| 估优化空间 | 排产还能省多少 | 有 | 一个有范围的数 + 达到它的条件 | 候选是几种结构性的浪费来源;每种给一个估计和可信度 |
| 优化工艺 | 找最好的配方 | 有 | 一个配方 + 可信范围 | 候选是响应面的几种结构(单调、峰、耦合、漂移) |

规律:**前两类以「铺开」为主,后四类以「收敛」为主**;找真问题介于两者之间,先铺候选再收敛。一棵树能装下两种节奏:

- **铺开**:课题下长出版块(或阶段)。每块的状态是 未涉及 / 摸底中 / 已摸清。摸的过程中冒出来的问题挂在版块下,状态是「冒出来的」,人或模型决定要不要追。
- **收敛**:问题下长出候选。每个候选的状态是 考察中 / 已排除 / 已采纳。每一步挂在它要区分的候选下面。

## 两个货架怎么分

| | 探索(新) | 本体(已有,瘦身) |
|---|---|---|
| 回答 | 我们在做什么、走到哪、下一步、为什么 | 我们知道了什么、凭什么信 |
| 主体 | 探索树(课题 → 版块 / 问题 → 候选 → 步骤) | 本体图、实体图 |
| 列表 | 判断及其可信度怎么变的、评估记录、未解释项 | 已确立的知识(事实)、经验、各问题的结论 |
| 从哪搬来 | 右栏世界树(计划步骤、闸门、评估弧线)整体搬进来,挂到它服务的问题下;本体货架里的「待核验 / 验证中 / 不确定 / 已推翻」判断列表和进度条搬过来 | 留下图和「已验证 → 入本体」的那部分 |
| 待处理 | 放在第一屏顶上(要人放行、要人撤回、交给人的未解释项) | 不放 |

本体货架上「结论」一节改成按问题列的结论卡(四块),点「凭什么」里的一行,跳到探索货架对应的候选。

## 探索货架的样子

数字和名字都是示意。

### 收敛型(定位瓶颈、优化、找真问题)

```
┌ 课题:C 线胺化找最优配方 ───────────────── 预算 18 / 30 · 第 2 阶段:收敛 ┐
│ 待处理 1:中试命令等你放行                                              │
├────────────────────────────────────────────────────────────────────┤
│ ▾ 问题 1 · 推荐哪个配方(杂质 < 0.2%)              考察中 2 · 排除 1 · 采纳 1 │
│     ○ 温度与 cat 沿斜脊耦合        考察中 · 交互 −29 还没拆                 │
│     ○ 有内部峰、各因素可加          考察中                                 │
│     ✕ 收率只随温度单调              已排除 · 第 9 次 140 °C 收率反降         │
│     ● 温度计漂移                    已采纳 · T_ref 偏低 8 °C               │
│   ▸ 问题 2 · 可信范围多宽            还没开始                               │
├────────────────────────────────────────────────────────────────────┤
│ 下一步 · 对角点 T−8 / cat+0.3                                           │
│   若耦合 → 收率约 93;若可加 → 约 88。能把问题 1 剩下的两个分开。           │
└────────────────────────────────────────────────────────────────────┘
  过程 ▸ 判断 9 · 评估 3 · 未解释 2 · 计划文档
```

### 铺开型(扫盲、发展脉络)

```
┌ 课题:锂电池正极材料行业摸底 ───────────────────────── 第 1 阶段:铺开 ┐
│ 版图  已摸清 3 · 摸底中 1 · 未涉及 2                                    │
│   ● 技术路线(LFP / 三元 / 锰基)       已摸清 · 来源 14 · 已核 9          │
│   ● 主要玩家与产能                     已摸清                             │
│   ◐ 成本结构                           摸底中 · 原料价格两个来源对不上      │
│       ↳ 冒出来的问题:锰基的成本优势是真的吗?  [追] [先放着]            │
│   ● 工艺流程                           已摸清                             │
│   ○ 回收与环保                         未涉及                             │
│   ○ 政策                               未涉及                             │
├────────────────────────────────────────────────────────────────────┤
│ 下一步 · 补成本结构:找第三个原料价格来源,判断哪边对                       │
└────────────────────────────────────────────────────────────────────┘
```

- 「冒出来的问题」带两个按钮:追(变成一个收敛型的问题,长出候选)或先放着(结案时列进「还不确定的」)。不点也不拦,模型按自己的判断走,但人随时能插手。
- 版块从哪来:模型立题时写;本体里的顶层概念(类别)也可以直接当版块。版块「已摸清」的标准是:这一块里的判断都过了核验,且没有开着的未解释项。

## 结论四块(结案时,对话里的最后答复与本体货架的结论卡同形)

| 块 | 收敛型写什么 | 铺开型写什么 |
|---|---|---|
| 结论 | 答案(配方、原因、优化空间的数) | 一句话概览 + 每个版块一句 |
| 凭什么 | 每个已排除 / 已采纳的候选一行,写清哪次实验或哪个来源 | 每个版块核了几条、靠什么来源 |
| 还不确定的 | 还在考察中、且会改变答案的候选 | 没摸清的版块、冒出来但没追的问题 |
| 要你定的 | 放行、取舍、下一步要不要投预算 | 哪些问题值得开新课题去追 |

不进结论的:中间判断、评估记录、步骤列表。它们都在探索货架里,点「凭什么」的一行就能跳过去看。

## 模型那一侧(卡片与提示词)

- 卡片第一行就是「你在哪」:课题、阶段(铺开 / 收敛)、当前问题、预算。和探索货架顶部那一行同一句话。
- 收敛型:列考察中的候选、本体里还没成为候选的结构、下一步各候选的预期(预期相同就提示这一步区分不了)。
- 铺开型:列版块状态、冒出来但没决定的问题。
- 提示词:立题时说清是铺开还是收敛(或先铺后收);最后答复按四块写。

## 对现有实现的改动

| 层 | 改动 | 是否破坏旧的 |
|---|---|---|
| 状态 | Frame 可带 `areas`(版块)与 `questions`;判断可带 `question`(挂在哪个问题下);问题和版块的状态由判断与证据算出 | 都可选;旧会话没有问题,就把整个目标当一个问题显示 |
| 计划 | 步骤可带 `serves`(为哪个问题或版块);不填就挂在当前问题下 | 可选 |
| 工具 | 不新增;「冒出来的问题」用 Frame 补写(或 RevisePlan) | 无 |
| 界面 | 新货架「探索」(`conversation.view`,紧挨本体);右栏世界树撤掉,计划 chip 点开探索货架;本体货架的判断列表与进度条搬走 | 世界树的内容全部保留,只是换了位置和父节点 |
| 结论 | 本体货架的「结论」按问题出四块卡 | 旧会话按目标出一张 |
