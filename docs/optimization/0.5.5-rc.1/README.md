# 0.5.5-rc.1 原生团队融合

审计误杀修复已单独作为 0.5.4 正式版发布。本候选沿用该修复，不再将其等待团队开发。

## 权威与接口

宿主控制团队开关、成员上限、成员生命周期、执行依赖、任务状态和消息。ClearAI 不注册第二套团队工具或看板，不自动开启团队。独立评估仍由原生一次性子代理执行，保留 fresh context、工具限制、结构化输出和复跑副本。

CreatePlan.steps 与 RevisePlan(action=add).step 接受可选 `team_task_id`。系统检查当前 Team 身份和任务存在性，存入团队 id 与任务快照；同一活动计划不能把同一任务绑定两步。原生 completed 只代表已交付，AdvancePlan 仍为证据验收入口。任务重开或消失产生待复核异常，保留原事实的范围；任务和文件变化触发现有审计材料检查。

投影升至 23，新增 `team/observed` 执行观测，不改写旧账本，不补造绑定。审计指纹 v6 包含当前团队材料，v5 记录仅供查阅。切换团队开关后，既有任务不会被自动迁移或重新派发；新会话使用新的宿主配置。

原生任务看板显示执行；原生 todo 显示验收，“已交付，待核验”不显示为完成。详情可展开证据与独立评估卡。

## 冻结的定向长测方案

使用已提交的 tools/native-headless/team-sequence.mjs 和 factory.mjs。3 个预登记世界种子 team-world-101 / 202 / 303 × 普通子代理 / 原生团队 × 2 题，共 12 场，均为 ClearAI 候选。每题新会话，同一组保留工作区；两组使用同一合成数据。

第一题分析八月一次合格率，识别批次与湿度共同影响并积累带范围知识。第二题读九月新数据，指标改为返工后的最终合格率，检查停用旧批次后仍存在的工位磨损问题。必须保留旧月份与旧指标范围内的知识。每题均有可重跑脚本、报告与明确提交字段；不以图节点数证明质量。

abhome / deepseek-flash / medium；每题累计输入加输出（含缓存输入）5,000,000 token，90 分钟。主、普通子代理、队友、评估者均核对实际请求配置与用量。团队组明确要求创建队友和绑定原生任务；普通组明确要求子代理分工。

候选摘要、代码提交、生成器、种子、评分规则与秘密生成种子承诺在运行前写入 manifest。秘密种子、隐藏真值及控制日志位于工作区之外，以原生 Seatbelt 与工具读权限约束隔离，并实际探测直接读取、shell、符号链接和目录扫描；任何探测失败停止。

记录完成率、实际委派、审计次数、等待期主模型请求、token、墙钟、图回灌和实际引用。机器评分只核对固定的批次/湿度及产线/工位字段；范围与图中语义主张结合原始证据复核。业务失败保留。关键机制错误（重复派发、错误裁决复用、等待空转、取消后自动启动、错误升格或用量不可核对）停止批次。修订须新冻结，旧记录保留并单列。

此批只作为工程验收，不宣称统计产品收益。当前状态：开发验证中，未发布，未开始正式 12 场冻结长测。
