# 已知缺口

以下是这一版**诚实的边界**。每一条要么没做，要么只做到写明的深度。本文没列、别处也没演示过的，一律当作未验证。

**读法**：凡别处描述机制的段落，以本文与[机制真值表](optimization/truth-table.zh-CN.md)为准——真值表逐条标了 `已实现 / 部分实现 / 设计目标`，并标出「文档说 A、代码是 B」的每一处。

## 还没实现

- **验证的八状态机。** [验证本体](verification-loop.zh-CN.md)描述了验证对象的完整状态机。落地的是内核实际执行的那一部分：命题、观测、评估、证据、事实，以及 L0–L4 五个等级。更完整的生命周期是设计目标。
- **普遍的 L4 人放行门。** L4 的**步骤级**人放行已实现：交付那次调用当场问人，人放行才交给评估者，不放行或没人能答就拒收。覆盖每一次评估的全局闸门没有实现。
- **人上传 / 文件投递 / 回调 / 拉取这四种外部来源。** 等级表（L4）列了它们，但**观测对象只有 `self` 一个来源**——类型只声明真有生产者的取值。这四种入口接上时，再把取值加进声明。
- **面板上不能手工改本体。** 本体格只读：要改本体就在对话里说，由模型改 `clear/ontology/` 下的文件（或人直接改文件），走同样的三道检查。
- **领域本体没有跨项目的复用。** 本体文件与事实文件是**工作区级**的：同一工作区里的新会话读得到之前的本体与事实，换一个工作区就要重新写；用户级的词汇库不做。
- **只认文件树里的本体。** 本体与实体只从 `clear/ontology/` 读；会话日志里没有本体事件可读，也不做转写。
- **读时的跨文件问题只标不拦。** 指空的父概念、值域、实体类型或关系宾语，在图下与卡上列出、那一份不进图，但不阻止模型继续写；升格那一刻才会拦住依赖它的断言。
- **实体图里的实例不做实体消解。** 同名即同节点；同一事物的两种叫法不会被合并。
- **机器评估者没有后台重评循环。** 准入判出 `needs_audit` 时内核派一个独立评估者（真的子会话）；此外没有定期重评。

## 只验到写明的深度

- **两场长跑是样本，不是统计。** [JEPA 世界模型](cases/jepa-world-model.zh-CN.md)与 [Navier–Stokes](cases/navier-stokes.zh-CN.md) 两个案例是真模型在模拟宿主（`tools/sim/`）里跑的完整会话：本体、实体、分层、升格都走通了，写入零拒绝。但它们只证明这条路走得通，不证明模型每次都走；实体嵌套（`contains`）两场里只用过一次，技能提醒两场都没被采纳。
- **实体门的拦截分支只有单元与重放覆盖。** `entities_unlanded`（将要升格的判断，主体不在实体图上就拒）在两场真跑里没有拦过——模型都先把实体写进了文件。「为了过门随手建一个空实体」这种风险还没观察到。
- **领域词汇的校验只到「形状」为止。** 值形态、主词域、值域、`is_a` 成环、同一事实自冲突都在升格前判；**不判**量纲换算与数值容差，**不解析**公式语义，**不查** `code` 形态指向的文件在不在。
- **冲突只暴露，不裁决。** 两条未撤回的已确认事实落在同一单值谓词、同一主体、不同客体时，投影给出一对冲突读数：它**不撤回任何一侧**、不判断哪条为真、也不进闸门。只有推翻证据落账的那次交付会当场问人撤回还是维持（`fact/reviewed`）。
- **事实挂本体靠词面。** 升格时，断言用到的词条加上判断与推翻条件里**按名字提到**的词条，一起记进事实的指纹；同义换说、缩写不在别名里的，挂不上。
- **没有断言的事实补不上断言。** 断言只在升格那一刻落地；没写断言的事实永远显示为「未结构化」，不算欠账。
- **界面截图来自回放。** README 与案例里的截图是在真 DSH 里回放两场真跑的会话拍的（模型调用由脚本回放）。真模型 + 真浏览器的整场走查、长会话下的面板交互（出处跳转、命题展开）、触摸手势没有在本版验过。
- **图的渲染用 React Flow（@xyflow/react 12），由 `tools/build-vendor.mjs` 打成插件自己的模块行。** 升级它要走 `npm run vendor`，不能只改 package.json；vendor 是生成物、不入库，缺失时相关测试如实跳过。`npm run check:browser` 用真 Chrome 挂载 `GraphBand`，挡的是装载与形状两类错，不是观感。
- **语言跟着人走,按会话算。** 系统自己写的话(工具结果、运行态卡、问人的话、提示词段、工具说明、`clear/` 下的文件)都用人说话的语言,按人写的消息判:有汉字且不算少就是中文,只有拉丁字母就是英文。中英混用的会话跟着最近一条有明确信号的消息;其他语言退回中文。面板的界面字跟着界面语言,命令行跟着 `--lang` 或系统语言。模型自己写的内容(主张、本体词条)用模型写的那种语言,系统不翻译。

## 子 run 与进程生命周期

- **评估者的结论由内核自己收。** 评估者子 run 走 `subagents.start()` 的一次性句柄：结论以本进程攥着的 `run.result` 为准，正文由收集那一刻的工具返回交给模型。原生结算通知（`subagent/end`）是 best-effort，只作补充。
- **进程重启后的回收只有单元测试的保证。** `sweepEndedAudits` 先从子会话日志取回裁决（`recoverVerdictFromChildSession`），取不回才落 `audit/settled{verdict:'unknown'}`；这条慢路径在部署形态里没有真跑证据。
- **硬杀留下悬空。** SIGKILL／超时强杀时那一拍没有执行者，账上只剩 `audit/dispatched`；长测不变量会把它如实标成悬空。
- **一次性形态没有「下一回合」。** 子 run 若在父会话最后一个收集点之后才落定，就收不到；常驻形态有下一回合，不受此限。

## 结构性限制

- **灵魂映射是人工维护的。** [灵魂映射](soul-map.zh-CN.md)把每条原则映到承载它的机制与测试。文字宪法与实现之间**没有机械等价检查**；这份表会漂移，只靠复查维持诚实。
- **有些原则只是偏好。** 约束只写在提示词、没有机制承载时，映射表会如实注明。
- **中英文档同步靠人。** 两份文档同时维护；改动只落一边时无法自动发现。

## 跑起来之前

- **pnpm 是前置条件，而且它是 DSH 的，不是本插件的。** `dsh plugin …` 转发给 pnpm，所以 `PATH` 上必须有一个可执行的 `pnpm`；没有它，CLI 会停在 `pnpm not found on PATH`。直接装它（`npm install -g pnpm`，或用系统包管理器）。`corepack enable` 不是安装：它放的是一个版本转发器，Node 24 自带的 corepack 0.34 找的是 `bin/pnpm.cjs`，而 pnpm 11 起没有这个文件，于是它可能下载一个自己启动不了的版本，还可能遮住本来可用的 pnpm。
- **装插件靠的是 DSH CLI 本身，它随 npm 包 `@deepseek-ai/dsh` 发行。** 用 `npx` 起 harness **不会**把 `dsh` 放到 `PATH` 上。要么借它来装（`npx @deepseek-ai/dsh plugin --profile web add clearai-dsh@<版本>`），要么 `npm install -g @deepseek-ai/dsh`。
- **pnpm ≥ 11 不会装一天内发布的版本，而且它不说。** `minimumReleaseAge` 默认 1440 分钟，且是**非严格**的：裸包名或 `@latest` **静默解析到一天以前的最新版**。写死版本，或者在 profile 的 `pnpm-workspace.yaml` 里豁免这个包：

  ```yaml
  minimumReleaseAgeExclude:
    - clearai-dsh
  ```

  包自带的安装器（`npx clearai-dsh install`）会解析当前版本并把确切版本传下去，所以不受影响。
- **在版本切换的中途刷新插件列表，可能看到一次 `locale` 元信息错误。** 那是宿主读到了一个换了一半的包；装稳之后就好。
- **装完要重启 `dsh web`。** 宿主半与客户端半都缓存在运行中的进程里；只刷新浏览器不够。
