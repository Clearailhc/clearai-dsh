## 一、第一性原理

**起源。** 用 AI 做研究,最大的风险不是答不出来,而是答得太顺:已知、推测和编造用同一种口气说出来。人分不清哪句能信,下一次又从零开始。

- **认识论**回答「这句话凭什么能信」:一个结论可信,当且仅当它经受住了一次本可以让它失败的检验,并写清在什么情况下不成立。
- **本体论**回答「这些结论加起来是什么」:成立的结论沉淀成概念、关系和找到的具体东西,下一轮从已知出发。

**核心循环。** 这一轮所有取舍只用这一把尺子:

> 问题 → 判断(写明怎样算错)→ 一次可能失败的检验 → 证据 → 已确立的结论(带范围)→ 长进本体

**脚手架原则。** 模型的自我认知和长程能力会越来越强。ClearAI 只提供它自己做不到、也不该自己做的那部分——**事实边界**:什么算完成、谁的裁决有效、什么能写进知识。其余交给模型的判断,或交给宿主。

## 二、分工:宿主做什么,ClearAI 只做什么

### ClearAI 只做三件事

1. **认识论契约**:判断带推翻条件;判据先写后做;交付是唯一的完成动作;准入只判收不收;做的人不判自己(L3 以上派独立评估者);证据只增不删;结案前独立评估;升格为事实并带范围。
2. **本体**:词汇(概念、谓词)、实例、断言、冲突派生、图投影;已确立的结论跨会话留在工作区里,下一轮按概念取用。
3. **呈现**:「本体」格、「世界树」格、运行态卡。

### 其余全部交给宿主

| 能力 | 宿主提供 | 我们删掉的 |
|---|---|---|
| 目标与续跑 | `dsh-goal`、续跑驱动、`/goal` 命令与界面 | 续跑窗口账本、续跑令牌、运行档、两套澄清提示、`SetGoal` 的目标本体 |
| 计划审阅 | `dsh-plan-mode`(`/plan` 进入,`exit_plan_mode` 交人评审) | 审阅卡、`RequestPlanReview`、授权记号 |
| 子代理 | `dsh-subagent` + `subagent` 工具 | `SpawnScout`、`MapScouts`、立约前侦察、世界线执行者 |

| 交付物 | `present` 工具、交付卡片、改动文件卡片、正文文件链接 | 「产物」页签与它的宿主读面 |

## 三、目标层一步到位:怎么挂在原生 goal 上

- **目标本身用原生 goal。** 目标的文字、续跑轮数、暂停 / 阻塞 / 完成,全部由 `dsh-goal` 持有;人用原生界面与 `/goal` 管它。
- **ClearAI 只往当前 goal 上挂两样东西**:判据(怎样算完成)与判断(每条带推翻条件)。由一个工具 `Frame` 登记与修订;修订判据仍要一份独立裁决(防止中途挪球门)。
- **完成要过独立评估。** 结案工具 `Conclude`:派独立评估者逐条核对判据,判达成才把原生 goal 置为完成,并把达门槛的判断升格为事实。原生 `update_goal(complete)` 由 `ctx.tools.guard()` 拦下并指向 `Conclude`——这一条是机制,不是劝告。
- **要人时让原生 goal 停下。** 门开着(计划连续被拦、事实出现反例待复核、结论说法不一致)时,ClearAI 把原生 goal 置为 blocked 并写明原因;人处理完,原生 resume。

## 六、代价与影响

1. **失去「恢复到某一版」**:宿主只能看每轮改了什么,不能恢复,宿主重启后也看不到之前的改动。安全改由宿主的权限预设与审批承担。(已接受)
2. **状态形状变化**:旧会话的续跑窗口、世界线、侦察、账本事件不再被折成状态;旧日志仍可读,只是这些部分不再显示。`STATE_VERSION` 要升一版。
3. **文档大改**:循环哲学、验证闭环、领域本体、权威归属、真值表、已知缺口、README 都要按本方案重写;真值表 71 条机制会删掉一大半。
4. **测试大改**:内核测试 834 项里,世界线、侦察、外脑、账本、续跑相关的会删掉;新增「原生 goal 守卫」「Frame / Conclude」的测试。

## 七、动手前需要先做原型验证的三件事

1. **原生 goal 的完成能否被可靠拦下**:用 `ctx.tools.guard()` 拦 `update_goal(action=complete)`,并确认原生续跑驱动不会绕过它自行完成。
2. **人的决定能否不可伪造地落账**:改用 `ask_user_question` 之后,人对「撤回 / 维持事实」「留哪条结论」的回答必须由内核从会话日志里读到,而不是由模型转述——否则就是把人的决定交给了模型。读不到,就保留现有的最小人门通道。
3. **原生 `present` 与准入的关系**:计划步骤声明的产物仍由准入核对存在与非空;最终交付是否要求 `present`,还是由准入通过后自动声明。
