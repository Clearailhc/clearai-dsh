# 受够了 AI 给你"看起来对"的答案？我们把认识论和本体论写成了代码

> 评测快照：Clearailhc/clearai-dsh @ v0.2.0
> 项目定位：DSH 原生的认识论工作台 + 可信本体构建插件
> 数据指标：15 套件 / 1372 条断言 / 29 个意图工具 / 6694 行内核 / MIT 协议（Apache-2.0）
> 安装：`npx clearai-dsh install`

---

先说一个每个用过 AI Agent 做正经事的人都撞过的墙。

你让模型调研一个技术选型，或者梳理一套业务流程。它给你一份漂亮的分析——有结构、有数据、有结论。你读完觉得挺有道理，准备拿去汇报。

然后领导问了一个问题：**"这个结论怎么验证的？证据在哪？"**

你翻聊天记录。发现证据散落在十几轮对话里，有的在工具输出里，有的在模型自己的推理链里，有的……根本没有。你甚至不确定模型是推理出来的还是编出来的。

这不是模型不够聪明。GPT-4、Claude、DeepSeek 都一样聪明。问题在于 **Agent 的架构里根本没有一个地方存放"这个结论凭什么成立"**。

聊天记录不存这个。向量数据库不存这个。LangGraph 的 state graph 也不存这个。

ClearAI 的回答是：这件事需要一个认识论层（epistemic layer），而且这个层不能靠提示词——得靠 schema。

---

## 一、它到底做了什么

一句话：**AI 在你的项目里长出一个活的领域本体，每条边都要通过验证循环挣得它的位置。**

![](docs/diagrams/ontology-hero.zh-CN.png)

左边那个环是认识论循环——七个阶段（界定、假设、规划、观测、验证、评估、记录），运行时压成四拍。右边长出来的是领域本体：概念是节点、谓词是边、事实是断言。中间那颗绿点是两者的桥——循环落定的事实，就是本体的第一个节点。

拆开看三个核心能力：

**1. 领域语言先于系统。** 开始研究之前，先立词。`RegisterTerm` 登记概念（带依据、可修订、可废止），`RegisterPredicate` 登记谓词（主词域、值域、单值约束）。比如"氧含量"是一个概念，"氧含量检测值"是一个谓词——主词域是"铸锭"，值形态是 `quantity`（单位 ppm），单值。

**2. 假设带类型化断言。** 立假设时可以挂断言——一个三元组：主词、谓词、宾语。值形态有五种（statement / quantity / formula / code / reference），关系谓词的宾语是另一个概念的实例。落账之前严格校验：引用不存在的谓词、值形态不合域、同一事实自相矛盾——全部在 schema 层拒绝，不是事后提醒。

**3. 冲突自动现形。** 两条已确认事实落在同一个单值谓词、同一个主体、不同取值上——数学上不可能同时为真。系统自动报出这对冲突，两侧分毫不动。撤回或维持，由人决定。

这三条合在一起，意味着研究结束时你拿到的是一个**可计算的知识结构**——可以按概念检索、可以审计证据链、可以自动检测矛盾。聊天记录做不到这些。

## 二、认识论这一半：流程图挂在墙上，schema 写在代码里

很多团队画过"科学研究方法论"的流程图。提出假设→设计实验→收集数据→得出结论。画完挂在墙上，然后该怎样怎样。

ClearAI 的七阶段循环不是这样的。**每一条纪律都有 schema 级的强制落点：**

### 判据在结果之前登记

```
SetGoal({
  claim: "催化剂 A 的转化率优于 B",
  refute_when: "复测显示 A 的转化率低于 B",   // ← 必填
  done_criteria: "三次独立实验的均值差 > 5%",  // ← 必填
  promote_at_level: "L3",                      // ← 结论至少要过独立评估
  hypotheses: [...]
})
```

`refute_when` 不填，schema 拒绝。这意味着**你无法在看到结果之后再编一个恰好命中的判据**——在科学方法论里这叫 pre-registration（事前登记），是防止 HARKing（结果出来后再编假设）的金标准。ClearAI 把它做进了工具签名。

### 模型没有"宣告完成"的字段

29 个意图工具里，没有任何一个接受 `status: "done"` 或 `progress: 100` 之类的参数。推进只经 `AdvancePlan`，它需要 `evidenceId`——指向一条已经落盘的证据。系统按证据算出来步骤有没有完成，模型说了不算。

这一条的效果：模型没法"说它做完了"。要么交出证据，要么那步就还开着。

### 高等级不能自判

结论分五级（L0–L4）。L0 自判（推理检查），L1–L2 需要登记判据后的验证，**L3 以上必须有独立评估者**——一个 fresh-context 的子会话，只有只读工具面，看不到做这件事的模型的推理过程。做的人不能判自己。

这在认识论里叫 inter-rater reliability（评分者间信度）。ClearAI 的实现是每个 L3+ 步骤自动派遣一个评估者子代理，它的裁决落在自己的证据链上。

### 被推翻的留作负知识

推翻 ≠ 删除。被推翻的假设留在原位，标"已推翻"，连同推翻它的证据一起展示。什么都没删。

波普尔说一个理论的价值在于它能被证伪。ClearAI 的实现是：证伪了的结论也是知识——知道"哪条路不通"和知道"哪条路通"同样有价值。

## 三、本体论这一半：不是画图工具，是领域契约

先澄清一个容易搞混的点：ClearAI 的"本体图"和市面上那些"知识图谱可视化"工具完全是两回事。

后者通常是：从文本里抽取实体和关系 → 画成一张图 → 看起来很酷 → 但你不知道哪条边是对的。

ClearAI 的本体不是抽取出来的。**它是登记出来的、验证出来的、一条一条挣出来的。**

### 词汇的纪律

```
RegisterTerm({
  id: "ingot",
  label: "铸锭",
  gloss: "立式半连续铸造产出的单根金属锭",
  basis: "工艺手册第 6.1 节"    // ← 必填：这个词的出处是什么
})
```

每条词汇带依据接纳。没有依据？不收。修订要留版本（旧值不删）。废止要写原因（黏性废止，没有删除操作）。语义变化必须换 id——`ingot` 的含义不许在历史上悄悄改变。

这不是官僚主义。这是本体工程的常识：**如果一个词的含义可以随时变，建立在它之上的所有断言都是沙上城堡。**

### 断言的形式

值形态五种，每种有明确的工程语义：

| 形态 | 含义 | 例子 |
|---|---|---|
| `statement` | 一句可验证的陈述 | "催化剂 A 优于 B" |
| `quantity` | 数值 + 单位 | `{ value: 10, unit: "ppm" }` |
| `formula` | 指向一个可重跑的公式文件 | `lab/models/oxygen_pickup.py` |
| `code` | 指向工作区里可执行的代码 | `lab/scripts/analysis.py` |
| `reference` | 指向一个外部来源 | 论文 DOI、标准编号 |

关系谓词的宾语是另一个概念的**实例**（instance），不是字面量——这样实体图里才能画出"哪个具体的东西"和"哪个具体的东西"之间的关系。

### 两张图，两个问题

**本体图**（ontology graph）：概念是节点，`is_a` 和谓词是边。回答"这门领域允许表达什么"。它可以在零事实的状态下存在——先立词，再提假设，语言先于句子。

**实体图**（entity graph）：实例是节点，断言是边，每条边带那条事实的支持等级和复核态。回答"已经验证出了什么"。它只在事实升格后才有内容——挣得多少，画多少。

两张图都是纯函数投影——从账本事件流算出来的，不是存在数据库里的。改不了，也不用同步。

## 四、冲突：认识论里最有意思的部分

说一个具体场景（虚构，但每一行都是真实机制的输出）。

一个材料实验室在研究某个合金的热处理工艺。两个不同的假设分别验证后升格成了事实：

- 事实 `f-001`：`quench_rate(specimen-3) = 45 °C/s`（L2，两条证据支持）
- 事实 `f-002`：`quench_rate(specimen-3) = 62 °C/s`（L3，独立评估者确认）

`quench_rate` 被登记为**单值谓词**——同一试样只有一个淬冷速率。两条事实挂在同一个主体、同一个谓词、不同取值上。

系统自动报出：

```
冲突 1 对
quench_rate · specimen-3:
  f-001 (quantity:45:°C/s)  L2
  f-kuxazz (quantity:62:°C/s)  L3
—— 只暴露，不裁决；撤回或维持由人决定
```

本体货架上的两条事实各自标出内联冲突标记。实体图上的两条断言边变色。

系统**不动任何一侧**。不撤回、不判谁对、不静默取后写的。

为什么？因为系统没有能力裁决真值。也许 f-001 的测量方法有系统误差，也许 f-002 的试样其实不是同一块。**判断需要人来做**——但发现冲突不需要人来做，数学就够了。

这就是"只暴露，不裁决"的含义：把发现交给机器，把判断留给人。

市面上号称"知识图谱"的产品没有一家做这件事。因为做这件事需要知道哪条边是单值的——这要求谓词有 schema，而抽取出来的图没有 schema。

## 五、架构：三条纪律，不多不少

浅看源码结构：

```
ui/lib/domain-language.js    740 行   判据纯函数（词汇/断言/冲突/投影）
ui/lib/fold.js              1971 行   事件折叠（44 个分支，纯函数）
ui/lib/client.js            3537 行   面板（React，只读投影）
preset/plugins/clearai-kernel.js  6694 行  内核（29 个意图工具 + 货架 + 账本写入）
preset/plugins/prompts.js     370 行   提示词段（23 段在场）
```

总量 13,000 行出头。对一个做到这个深度的系统来说不算大——因为三条架构纪律替它挡住了大量复杂度：

### 纪律一：账本是唯一权威，面板只是投影

所有状态变更落成事件（event sourcing）：`ontology/term_added`、`goal/set`、`step/advanced`、`fact/promoted`……写入按工作区隔离的账本（一个 git 管理的事件流）。面板读的是投影——`fold.js` 是一个纯函数，从事件流算出当前状态。

**没有第二份存储。** 你在面板上看到的每一个数字、每一条事实、每一个冲突，都是纯函数从事件流现场算出来的。改面板不会改状态（面板没有写入口径）。改状态必须经过事件。这意味着状态永远可以从零重放出来，审计就是读一遍事件流。

### 纪律二：DSH 引擎一行没改

ClearAI 跑在 DeepSeek Harness（DSH）的组合面上——一个宿主包（注册路由和投影单元）、一个 agent 预设（内核 + 提示词 + 工具 schema）、一个客户端模块（面板）。没有 fork，没有 monkey patch。DSH 升级不影响 ClearAI，反过来也一样。

### 纪律三：判据只有一份

词汇校验、断言校验、值形态检查、冲突推导——全部在 `domain-language.js` 一个纯函数模块里。模型工具（`RegisterTerm`）、人门动词（面板编辑走 `/api/clearai/gate`）、折法（`fold.js`）三个面调同一份判据。

为什么？因为**规则如果写在两处，一定漂移**。漂移的那一刻，模型看到的规则和用户看到的规则不一致，整个可信承诺就塌了。

## 六、和现有方案比，差在哪

| 维度 | 通用 Agent（LangChain/AutoGPT） | 知识图谱工具（Neo4j 等） | ClearAI |
|---|---|---|---|
| 结论可信度 | 靠模型自觉 | N/A（不做验证） | schema 强制：判据先行 + 独立评估 + 无宣告字段 |
| 知识积累 | 聊天记录 | 手动录入或批量抽取 | 类型化断言随事实自动入库 |
| 冲突检测 | 无 | 需手写约束 | 单值谓词违反自动报出 |
| 证据链 | 无结构化存储 | N/A | 每条结论挂 L0–L4 证据，可追溯 |
| 知识的可靠性 | 不可审计 | 依赖录入质量 | 每条边通过循环挣得，可回放到零 |
| 部署侵入性 | 需改框架 | 需建基础设施 | DSH 插件，零改动 |

坦率地说，ClearAI 不替代任何现有工具。LangChain 擅长编排调用链，Neo4j 擅长大规模图查询——ClearAI 擅长的是**让 AI 产出的知识可信**。它们是互补关系。

但如果你的场景是"研究探索"或"业务建模"——结论要拿去用的、错了会出事的——那可信这一层不是可选项。

## 八、五分钟上手

```bash
npx clearai-dsh install
```

装完重启 `dsh web`（插件两半都在运行中的进程里按 URL 缓存，只刷新浏览器没用），新建会话，预设选 ClearAI。

发第一句话之前，可以想好你的领域大概有哪几个概念。不用想全——词汇是增量登记的，漏了随时补。

然后正常对话。该验证的时候 ClearAI 会自己走循环；该你裁决的时候（冲突、计划审阅、临时采纳确认），它在面板上等你。

## 九、如实说几条边界

- **本体不跨项目。** 一个项目一个本体，先做深。跨项目复用是 OWL 层的事，不是这一层的事。
- **没有删除。** 废止是黏性的——留痕、标原因、不再被引用，但它还在。历史不可篡改是审计的前提。
- **不宣称 RSI。** ClearAI 提供的是自我改进系统**需要的认识论底座**（诚实记录改了什么、证据是什么、谁评估了它），不宣称自己是 RSI。
- **浏览器交互的长测还在进行。** 面板的缩放、全景、词条展开在结构级测试里全绿，但真浏览器里的长时间走查还在收尾——已知缺口在 `docs/known-gaps.md` 里如实挂着。

---

## 总结

大多数 AI Agent 在优化"做得更快"。ClearAI 在解决一个更基本的问题：**做完之后，你敢不敢信。**

它给出的答案不花哨：把认识论（判据先行、独立评估、证伪保留）和本体论（概念、谓词、类型化断言）从教科书里搬出来，写进工具 schema、事件账本和纯函数折叠里。

13,000 行代码。29 个工具。44 种事件。15 套测试 1372 条断言。不多——但每一行都在回答同一个问题：**这条边是怎么挣来的。**
