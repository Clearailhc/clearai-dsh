# 认识论 × 本体论：让 AI 的研究长成一个可信的本体

> ClearAI 0.2.0 — 世界第一个能在 DSH 上构建可信本体的插件。

**一句话**：AI 在你的真实项目里长出一个活的领域本体——每条边都经过证据与独立评估的检验，冲突自动现形，结论可追溯，知识可积累。

本文讲清楚三件事：它能做什么、为什么这样设计、怎么实现的。

---

## 一、一个没人回答的问题

语言模型几秒内给出一个看起来合理的答案。然后呢？

科研工作者的追问：**验证做了什么？证据在哪？结论为什么可信？**

业务建模者的追问：**领域知识存在哪？下次还能用吗？换了个人还找得到吗？**

分析师的追问：**两条结论矛盾了怎么办？系统怎么知道它们矛盾？**

现有 agent loop 的回答是沉默。它跟踪一件事：任务做完没有。至于一个结论凭什么被信任——那是模型上下文窗口里的一段话，关掉就没了。

这不是模型能力问题，是**机制缺位**。我们补的就是这块。

![](docs/diagrams/ontology-hero.zh-CN.png)

*左：认识论循环（七阶段）。绿点是它落定的事实，也是右侧领域本体的第一个节点。右：本体图——深墨是概念，浅墨是值形态，emerald 是实例。*

## 二、两个哲学工具，一个工程问题

认识论（epistemology）研究知识的本质：一个信念凭什么算知识，证据怎么支持结论，什么条件下该修正。

本体论（ontology）研究存在的结构：这个世界有哪些类的东西，它们之间有什么关系，用什么语言描述。

听起来抽象，但映射到 AI Agent 里就是两个非常具体的工程问题：

| 哲学问题 | 工程问题 | ClearAI 的回答 |
|---|---|---|
| 一个结论凭什么被信任？ | 怎么防止模型"说完成了就算完成"？ | 认识论循环：七阶段机制强制 |
| 知识该以什么形态存在？ | 研究产出怎么积累？聊天记录关了就没了。 | 领域本体：词汇 + 已确立条目 + 图 |

两者缺一：只有循环没本体，验证完的东西散落一地，下一轮还得重读散文；只有本体没循环，图上的边没有出处，画得再漂亮也只是断言堆积。

**别的知识图谱靠抽取与断言堆边。这里的每一条边都要通过循环挣得。**

---

## 三、认识论这一半：七阶段循环是机制，不是流程图

认识论循环有七个阶段：界定、提出假设、规划、观测、验证、评估、记录并行动。听起来像项目管理？

关键区别：**流程图挂在墙上靠自觉，机制写进 schema 靠强制。**

![](docs/diagrams/epistemic-loop-hero.zh-CN.png)

*环内是这台仪器的读数面：L0–L4 等级轴、事先登记的阈值虚线、五个带误差棒的观测——被支持的填实、无法判定的画虚圈、被推翻的留在原位打一道斜杠。什么都不删。*

每一条纪律的机制落点：

**判据在结果之前登记。** 立目标（`SetGoal`）时必须写 `refute_when`（什么结果会推翻它）和 `done_criteria`（怎样算回答了）。事后补判据？写不进去——schema 拒绝。

**模型没有"宣告完成"的字段。** 意图工具的面里，不存在任何可以设 `status: done` 的参数。推进只经 `AdvancePlan`，它需要交付的证据（`evidenceId`）——系统按证据算出来，模型说了不算。

**高等级不能自判。** L3 以上结论必须有独立评估者（fresh-context 子会话，只读工具面），做的人不能判自己。

**被推翻的命题留作负知识。** 推翻 ≠ 删除。它留在原位、标"已推翻"、连同推翻它的证据一起展示。知道"哪条路不通"和知道"哪条路通"同样有价值——这是波普尔证伪主义的工程化。

**运行时压缩为四拍。** 七阶段在工作节奏上折成计划→执行→观察→反思。每个阶段收尾时系统算出当前状态（阶段、证据计数、冲突数），面板与模型看到的完全一致。

## 四、本体论这一半：领域语言与类型化断言

研究开始之前，先回答一个问题：**这门领域用什么语言说话？**

### 词汇：概念与谓词

概念（concept）是名词：铸锭、炉次、氧含量、拉速、立式半连续铸造。

谓词（predicate）是动词：氧含量检测值（主词域=铸锭，值形态=quantity，单位=ppm，**单值**）、浇铸拉速（值形态=quantity，单位=mm/min，单值）。

每条词汇**带依据接纳**（basis 指向材料出处），版本化修订，黏性废止（废止了也留痕，因为没有删除）。语义变化必须换 id——稳定 id 的含义不许在历史上悄悄改变。

### 断言：类型化的事实

一条断言是三元组：**主词 - 谓词 - 宾语**。

```
{ predicate: 'oxygen_ppm',
  subject:   { id: 'INGOT-3', type: 'ingot' },
  object:    { kind: 'quantity', value: 10, unit: 'ppm' } }
```

值形态有五种：陈述（statement）、量（quantity = 数值+单位）、公式（formula = 指向可重跑的文件）、代码（code = 指向工作区文件）、引用（reference）。关系谓词的宾语是另一个概念的**实例**（instance）。

断言在假设阶段就挂上（提供即严校：引用不存在、形态不合域、同一事实自洽，一律在落账之前拒）。升格时断言随事实定型——事实以本体词汇写成，进架那一刻就是结构化的。

### 两张图，两个问题

**本体图**（你的领域长什么样）：概念是节点，`is_a` 与谓词是边。它在任何事实出现之前就可以存在——先立词，再提假设。

**实体图**（已经验证出了什么）：实例是节点，断言是边，每条边带那条事实的支持等级。它只在事实升格后才有内容——挣得多少，画多少。

![](docs/shots/zh/facts.png)

*本体格：顶部图带（本体图|实体图切换），下面是本体货架（已确立条目，每条带断言芯片），底部是折叠的词汇维护区。*

## 五、冲突：只暴露，不裁决

同一单值谓词、同一主体、不同取值——数学上不可能同时为真。

系统自动报出：

```
冲突 1 对
oxygen_ppm · INGOT-3:
  f-poxoxu (quantity:10:ppm)
  f-kuxazz (quantity:12:ppm)
—— 只暴露，不裁决；撤回或维持由人决定
```

本体货架上的两条事实各自标出内联冲突标记，图带上的两条断言边变色。

系统**不动任何一侧**。不撤回、不判谁对、不静默取后写的。处置走既有的人门：你决定撤回哪条（写缘由，记录保留），或者维持（也许两条口径各有适用范围，你来判断）。

这是认识论的谦逊——系统没有能力裁决真值；也是本体论的诚实——不一致就该被看见，不该被平均掉。

## 六、真跑证据：亨通铜业

这不是玩具例子。真模型，真材料，真工厂。

**材料**：亨通铜铝箔研究院的会议纪要与调研依据清单（无氧铜熔铸工艺）。

**任务**：读材料 → 登记概念与谓词 → 立目标带断言假设 → 建计划 → 交付 → 评估 → 升格。

**结果**（一个回合，21 条变更，e2e 断言 36/0）：

模型从材料里自己立了 **5 个概念**（铸锭、炉次、氧含量、拉速、立式半连续铸造）和 **2 个单值谓词**（氧含量检测值 ppm、浇铸拉速 mm/min），每条 basis 精确指向会议纪要章节或 **ASTM B170 / E2575 标准**。

第一条假设带两条断言（氧含量 10 ppm、拉速 80 mm/min），qualifiers 写清口径（"5ppm 仅为偶发检出"）与来源。计划两步各绑一条假设。

走完交付与评估后，`CloseGoal` 触发独立评估。两条假设各自达标，升格为 **2 条事实**——都带着完整断言。

然后：两条事实挂在同一个主体（INGOT-3）、同一个单值谓词（oxygen_ppm）、两个不同取值（10 vs 12 ppm）上。

**冲突自动现形。** 系统报出 1 对，卡片与货架各说一遍，两侧事实分毫未动。

8 条跨机制不变量全绿（准入先于推进、评估无悬空、升格与证据等级自洽……）。

## 七、它能用在哪

三个场景，同一套机制。

### 科研探索

假设管理、证据分级、负知识保留——认识论循环的主场。

- 每条假设有 `refute_when`（什么结果推翻它），判据在实验之前登记
- 证据分 L0–L4 五级：L0 自判 → L3+ 独立评估者
- 被推翻的假设留作负知识，连同推翻它的证据
- 结论升格后带断言进本体货架，下一轮按概念检索

### 业务建模

领域驱动设计（DDD）的自动落地。

- 概念与谓词就是业务语言：客户、订单、交付物、合规指标……
- 谓词的主词域与值域即业务规则："一个订单只能有一个生效的合规判定"（单值谓词）
- 冲突检测自动找出"同一字段两个矛盾值"——数据治理的刚需
- 本体图即业务概念模型：可视化、可导出（Mermaid）、可版本化

### 分析

- 冲突检测：系统自动找出互相矛盾的结论，不靠人眼扫
- 按概念检索：下一轮研究用 `QueryKnowledge` 按概念查，无需重读全部散文
- 本体图导航：点概念节点过滤下方货架，图就是索引
- 知识审计：每条结论的证据链、等级、判者都可追溯

## 八、实现：三条架构纪律

### 1. 账本是唯一权威，面板只是投影

所有变更落成事件（event sourcing）：`ontology/term_added`、`goal/set`、`step/advanced`、`fact/promoted`……写入按工作区隔离的账本。

面板读的是投影——纯函数折叠（`fold.js`）从事件流算出当前状态。**没有第二份存储**：改面板不会改状态，改状态必然经过事件。状态可重放、可审计、可回滚。

### 2. DSH 引擎一行没改

ClearAI 是组合面上的一个插件：一个宿主包（`clearai-dsh`，路由 + 投影注册）、一个 agent 预设（内核 + 提示词 + 工具 schema）、一个客户端模块（面板）。没有 fork，没有 patch。升级 DSH 不影响 ClearAI，反过来也一样。

### 3. 判据只有一份

词汇校验、断言校验、值形态检查——全部在一个纯函数模块（`domain-language.js`）。模型工具、人门动词（面板编辑）、折法三个面调同一份判据。两处长出来的规则必然漂移，所以只许有一处。

## 九、我们不做什么

每条"不做"和每条"做了"一样经过论证：

- **不自动裁决冲突。** 系统没有能力判真值；裁决权在人。
- **不删除。** 废止是黏性的（留痕、标因、不消失）。历史不可篡改是审计的前提。
- **不做跨项目本体库。** 一个项目一个本体，先做深。跨项目复用是 OWL 层的事，不是当前这一层。
- **不宣称递归自我改进（RSI）。** 我们提供的是自我改进系统**需要的认识论底座**（诚实记录改了什么、证据是什么、谁评估了它），不是 RSI 本身。
- **不做量纲换算与数值容差。** 10 ppm 和 0.001% 是不是同一个值，由登记词汇的人决定，系统不猜。

## 十、开始使用

```bash
npx clearai-dsh install
```

装完**重启 `dsh web`**（插件两半都在运行中的进程里按模块 URL 缓存，只刷新浏览器不够），新建会话，在预设选择器里选 **ClearAI**。

然后给你的项目发第一句话。你的本体从第一条概念开始长。
