# 领域预研交付检查单（发布闸门）

交付预研报告前逐条核对；任一条不满足即不发布，或明确标 `[信息缺失]` 并说明原因。

## 内容完整性
- [ ] 领域全貌一段讲清：问题域边界、主要流派/路线、当前热点与争议
- [ ] 关键玩家/团队/数据源已列出，并注明各自立场或利益相关
- [ ] 时间线覆盖近 3-5 年关键进展，标明拐点事件
- [ ] 关键未知与待验证问题单独成节，未与已确认事实混排

## 证据与溯源
- [ ] 每条事实句尾有 [编号] 或 [推断] 标注；无裸断言
- [ ] 编号与文末来源清单一一对应，链接可回查
- [ ] 相互矛盾的来源已显式列出并给出取舍理由
- [ ] 二手转述已尽量回溯到一手来源

## 图表
- [ ] 图表落盘 `lab/diagrams/`，报告内引用路径正确（`../../lab/diagrams/`）
- [ ] 含中文文字的图已用 `read_image` 验收，无乱码
- [ ] 每张图有编号、标题与一句话结论

## 文件纪律
- [ ] 报告直接位于 `products/reports/`，未创建多余子目录
- [ ] 文件名 slug 与正文引用全文一致
