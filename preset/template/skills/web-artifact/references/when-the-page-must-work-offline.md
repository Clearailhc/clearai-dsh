# 页面必须能离线打开

制品的读者常常不在 Workbench 里，也未必有网。会议室、客户现场、飞机上、内网隔离的工位——
一份打开是白屏的评审件等于没交付。

## 约束的本意

**运行时零网络请求。** 构建期随便联网（本技能自己就在构建期跑 ELK 布局、算摘要）。

把本意记住比记住禁令有用。「不许引 CDN」只覆盖了一种情况，而实际会漏网的有好几处：

- Google Fonts 也是外部请求。所以字体只用系统栈，`system-ui` 打头，中文补
  `PingFang SC` 与 `Microsoft YaHei`。想要更强的字体个性，代价是把字体文件内联成
  data URI——通常不值得，除非是对外交付档。
- 图片走 data URI，或者干脆用 SVG 画出来。
- `<link rel="preconnect">`、`<link rel="dns-prefetch">` 这类提示也删掉，它们没用且误导。
- 动态 `import()` 一个裸模块名同样会失败，因为没有 import map，也不该有。

`scripts/check_artifact.py` 会把这几类都扫一遍。

## 体积预算

原生渲染器的产物大致这样构成：

| 部分 | 量级 |
|---|---|
| 渲染器 JS | ~13 KB |
| 样式 | ~6 KB |
| 页面骨架 | ~2 KB |
| 数据 | 随规模，7 节点约 5 KB |
| **合计** | **20–40 KB** |

作为对照，内联 React + ReactDOM + 一个图库轻松到 450 KB 以上，换来的能力在检查类制品上
基本用不到。详见 [SKILL.md](../SKILL.md) 的「为什么不用框架」。

真需要一个重型库时（比如某种专门的图表），先问它是否只在构建期需要——布局、统计、聚合都
可以在生成时算完，把结果写进数据，浏览器端只负责画。本技能的 ELK 就是这么用的：1.6 MB 的
布局引擎跑在 node 端，一个字节都没进产物。

## 与 App 侧 freeze 的区别

两者都产出一个能双击打开的自包含文件，来路完全不同：

| | 本技能的制品 | App 侧的 freeze |
|---|---|---|
| 来源 | 数据文件 | 运行中的 App 实例 |
| 重新生成 | 改数据再跑一次生成器 | 需要实例还活着 |
| 版本标识 | 源数据摘要 | source revision |
| 场景 | 还没建 App，或根本不需要 | 已有 App，要给圈外人看当前状态 |

判断见「你可能还不需要 App」
一节。

## 自查

```bash
grep -oE 'https?://[^"'"'"' )]+' out/artifact.html | grep -v w3.org
python3 scripts/check_artifact.py out/artifact.html --source data.json
```

真要确认，断网后双击打开一次。这一步只花十秒，而它挡住的是「专家打开是白屏」这种当场
丢脸的事故。
