# 项目章程

本文件回答三件事：**这个项目在探索什么问题；目前已经知道什么、还不知道什么；一个结论要满足什么条件才算可信。**
它只保存跨任务稳定的项目事实与验收门槛。单次任务的委托属于 Goal，执行步骤与证据属于 Plan，此处不重复。
未填写的条目请保留占位文字——占位就是「尚未确定」，不能被当成默认答案或完成证据。

<!-- clearai:section=project-goal -->
## 1. 项目目标

- **要回答的核心问题**：[用一句话写清本项目最终要回答什么问题、或验证什么命题]
- **使用者与用途**：[谁会使用这里的结论，用来做什么]
- **成功的样子**：[项目完成时应存在哪些交付物（报告 / 数据集 / 模型 / 应用），各自达到什么程度]
- **当前阶段**：[资料理解 / 假设形成 / 数据验证 / 实验验证 / 结论沉淀 —— 随进展更新此行]

<!-- clearai:section=background -->
## 2. 背景与已知事实

> 只写已被证据支撑的事实，并注明来源；猜测与假设写到第 3 节或工作区的假设清单里。

- **问题背景**：[这个问题为什么值得探索，此前已有哪些工作]
- **已确认的事实**：[逐条列出，每条附来源（文献 / 数据文件 / 实验记录路径）]
- **关键未知**：[目前明确不知道、需要本项目回答的点]

<!-- clearai:section=constraints -->
## 3. 关键约束与假设

- **资源约束**：[可用数据、算力、实验条件、时间预算]
- **方法约束**：[必须使用 / 不得使用的方法、数据许可与伦理边界]
- **工作假设**：[当前依赖但尚未验证的假设，逐条列出并标注验证计划]

<!-- clearai:section=evidence -->
## 4. 证据与验收标准

> 一个结论只有满足下面的门槛才能写进「已确认的事实」或最终交付物。

- **证据分级**：[本项目认可哪些证据形态及其强弱次序，如：可复现实验 > 数据统计检验 > 文献佐证 > 推理论证]
- **验收标准**：[每类交付物的通过条件；写成可检验的判据，而不是形容词]
- **可复现要求**：[结论对应的数据、脚本、参数应存放在何处，他人如何复跑]
- **升格门槛**：[达到哪一级（L0–L4）的支持证据且无推翻，假设即成为事实；默认 L3。各等级在本项目里具体指什么，见仓库 docs/verification-loop.md 第 3 节]
