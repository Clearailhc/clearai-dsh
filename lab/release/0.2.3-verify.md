## 根因(已另案诊断)

`@deepseek-ai/dsh` 的 `latest` 在 2026-09-23T13:44Z 从旧机制的 `0.1.5-rc.3` 前进到 `0.1.7-rc.1`,而 **0.1.7-alpha.1 起宿主把 agent 预设的注册从「root 目录扫描」换成了「组合里的声明行」**:

- 旧:`- id: agent-presets`(`@deepseek-ai/dsh-agent-presets`),config 含 `default / includeShippedRoot / includeUserRoot / roots:[{path, trust}]`
- 新:`- id: agent-preset-registry`(`@deepseek-ai/dsh-agent-preset-registry`),config 只剩 `default / selectedDefault`;每个预设是一条 `- id: preset-<id>` 声明行,`plugins:` 里放整份插件列表

我们 `pack/cordis.patch.yml` 里那段按 id 覆盖 `agent-presets` 的补丁因此**没有落点**——profile 照样起(所以 ③/③′ 仍绿),但名册不再指向包内 `presets/`,预设不进模式选择器。

完整证据链:`lab/release/0.2.3-release-blocker.md`。

## 对本次发布的判定

0.2.3 的源码侧没有问题:**同一 commit、同一份包**,在 09-23 的 CI run 35857872272 上是绿的,suites、构建自检、版本一致性三道门本次也全绿。红的只有「在最新宿主上干净安装」这一道——它红得对:在 ≥0.1.7 宿主上,这个包装出来的预设确实不会出现。

因此本次发布的中断**不是事故,是门禁起了作用**:如果第 11 步不存在,0.2.3 会带着一个在新宿主上不可用的预设被推到 npm,而「发布成功」的所有后续核对都不会发现它(内容比对只验「registry 上那一份 == 本 commit 构建的那一份」,不验「装上之后能不能用」)。
