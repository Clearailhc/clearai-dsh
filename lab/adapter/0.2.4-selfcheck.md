## 二、那两个崩溃:环境问题,不是本次改动

```
--- 宿主 ---
✗ 部署的 host.js 与源不一致——先跑 bash install.sh 再测(这份测试测的是要跑的那一份)。
--- 客户端 ---
✗ 部署的 client.js 与源不一致——先跑 bash install.sh(这份测试测的是要跑的那一份)。
```

判为**本机环境**,三条依据:

1. **测试自己的设计**:`test/client.test.mjs:67-71`(host 同形)在**找不到部署件时跳过并 `exit 0`**,注释写着「装上再测:bash install.sh,或 node tools/install-native.mjs --profile web」。CI 里没有部署件 → 走跳过分支;本机 profile 里装着一份**旧的**开发形态部署(`~/.dsh/profiles/web/package.json` 里是 `file:/tmp/clearai-release/dist/clearai-dsh`),于是走到比对并红。
2. **它们测的文件本次一行没碰**:两条套件比对的是 `lib/host.js` 与 `lib/client.js`,其源是 `ui/lib/index.js` 与 `ui/lib/client.js` —— 本次改动清单里没有它们(改动集中在 `pack/`、`preset/agent.cordis.yml`、`tools/`、`test/preset-composition.test.mjs`、清单与 CHANGELOG)。
3. **不是新出现的**:这一对失败在本次改动**之前**就存在(第一次跑自检时就在),修完 `verify-package` 与组合套件后仍只有它们。

**不去跑 `bash install.sh` 修它**:那会把本机的开发形态部署重装一遍,影响用户正在使用的环境;这条留给用户在合适的时机自行处理(它不影响 CI,也不影响发布)。

## 三、自检抓到的两处真问题(已修)

### 1. `verify-package` 的 patch 形态断言写死了字符串

```
✗ 清单声明了宿主 bundle(patch)
```

该断言要求 `manifest.dsh.bundle.patch` 是**字符串**,而本版按宿主新形态改成了**数组**。改成两种形态都接受,并**加了一条更有价值的断言**:声明的每个补丁文件都必须真的在包里(声明一个不存在的文件,宿主加载时会直接失败)。修后:

```
✓ 清单声明了宿主 bundle(patch)
✓ 声明的每个补丁文件都真的在包里
```

### 2. 组合套件里有一条**假通过**,另一条真的失效

`test/preset-composition.test.mjs`:

- `✗ clearai-commands 插件挂载` —— 断言写的是 `/\.\/plugins\/commands\.js/`,而本版把包内插件改成了包内子路径。**真失效**,已改成按行匹配新的 name。
- `✓ workflow worker 与 delegation realm 在` —— 它匹配 `/workflow-worker-thread/`,而那一行**本版已经删掉**(新宿主没有这个包)。它之所以显示 ✓,是因为我删行时留下的**注释里写着那个旧包名**。**这是假通过**:断言被自己的注释骗过了。已改成按行锚定 `^ {4}- id: workflow-ptc$`。

第二条比第一条更值得记:全文正则匹配在「同一个词既出现在配置里、也出现在注释里」时无法区分二者。修完之后:
